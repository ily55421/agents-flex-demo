# 项目全貌分析总结

- 日期：2026-09-11
- 类型：只读分析（无代码修改）

## 一、项目定位

Agents-Flex Agent Runtime Showcase——基于 Agents-Flex 框架（`agents-flex-agent` 2.2.9）的全链路 Agent 运行时演示项目。通过"AI 市场研究"场景，把框架的原生能力（SSE 事件流、动态表单、人工审批、上下文压缩、挂起/恢复、预算、重试、OpenTelemetry 可观测性）串联并可视化，主对话调用真实 OpenAI-compatible 模型（默认 DeepSeek）。

## 二、技术栈与规模

| 侧 | 技术 | 规模 |
| --- | --- | --- |
| 后端 | Java 8 + Spring Boot 2.7.18 + Agents-Flex 2.2.9 + OpenTelemetry | 28 个 Java 文件，约 5188 行 |
| 前端 | Vue 3.5 + TypeScript 5.8 + Vite 6 + Pinia 3 + Tailwind 4 | 21 个 Vue/TS 文件，约 2537 行 |
| 构建 | Maven 单模块 + pnpm | 测试：`mvn test` / `pnpm build`（vue-tsc） |

## 三、架构分层

```text
Vue 3 控制台（Pinia useAgentRun 编排 SSE + REST）
        |  create Agent + 命令（REST） / 原生 AgentEvent（SSE）
        v
Spring Boot API（api 包：仅校验与路由，14 个 Run 端点）
        v
ShowcaseRuntime（runtime 包：控制面，命令提交 + 异步推进 + SSE/OTel 协调）
        v
Agents-Flex AgentRunner + AgentTurnSnapshot（状态唯一事实来源，框架持有）
  |-- ChatMemory + 压缩策略（demo 包 ResearchAgentFactory 配置）
  |-- 4 个工具 + ToolApprovalPolicy（表单/研究/必失败重试/高风险发布）
  |-- AgentBudget + AgentRetryPolicy + AgentWorker lease 重试
        v
每 Run 独立 TelemetryRoute + InMemory Span/Metric Exporter（observability 包）
```

关键设计约束：Demo 不复制框架状态机；`DemoRun` 为每次运行提供隔离的 Runner、TurnStore、ChatMemory 与 OTel Route，多任务互不串扰。

## 四、核心模块

- 后端
  - `api/AgentRunController`：create/start/messages/form/approval/suspend/resume/cancel/events(SSE)/trace 等 14 端点。
  - `runtime/ShowcaseRuntime`：CAS 单飞推进（`processing`）、协作式安全检查点暂停、`AgentWorker.pollAndRun` 走真实持久化重试路径、终态时结束 rootSpan。
  - `demo/ResearchAgentFactory`：把 UI 声明式配置映射为框架原生 Builder（执行策略、预算、重试退避、压缩 Decider/Compressor、审批策略）；`verify_sources` 工具按 Turn+工具名计次，前两次必失败以演示重试。
  - `config/ModelProperties` + `ModelConfiguration`：application.yml/环境变量默认值，UI 可覆盖并重建 ChatModel；API Key 只留后端内存。
  - `observability`：InMemory Span/Metric Exporter，每 Run 独立；trace 查询前强制 forceFlush。
- 前端
  - `composables/useAgentRun.ts`（Pinia store）：SSE 连接与重连状态、eventId 去重、40ms + requestAnimationFrame 的 Token 批量刷新、90ms 防抖快照刷新、飞行中事件合并、`?run=` URL 恢复。
  - 组件：ChatWorkspace、EventStream（虚拟滚动）、TraceViewer、ApprovalPanel、BudgetPanel、CompressionPanel、RetryPanel、DynamicForm（按框架 JSON Schema 渲染）等 16 个。

## 五、状态流（框架原生）

READY -> WAITING_FOR_USER（表单）-> RETRY_SCHEDULED（Worker lease）-> WAITING_FOR_APPROVAL（发布审批）-> COMPLETED；READY/SUSPENDED 支持手动挂起与恢复；终态含 FAILED / CANCELLED / BUDGET_EXCEEDED 等。

## 六、测试

`ShowcaseRuntimeIntegrationTest` 用确定性 ChatModel（`ShowcaseChatModel`/`SummaryChatModel`）走完整框架链路：表单→两次重试→审批→Trace 断言；另有 Token 预算超限、拒绝审批、手动挂起恢复用例，以及 3 个请求校验/配置测试。生产代码始终创建真实模型。

## 七、亮点

1. 框架边界干净：Controller/Runtime 只做编排，状态机完全由 Agents-Flex 持有。
2. Run 级完全隔离（内存、快照、遥测），适合多浏览器并行演示。
3. 手动暂停是协作式的：不抢占原子 Step，用原生 USER_INPUT Suspension 持久化。
4. SSE 性能工程到位：Delta 批量提交、事件去重、防抖刷新、虚拟滚动。
5. 可观测性真实：rootSpan 覆盖含人工等待的完整墙钟；生命周期事件不冒充 Span。
6. 安全细节：Key 不回显、未配置 Key 时拒绝创建 Agent 而非走模拟流程。

## 八、局限与注意点

- 全内存存储（Run/事件/Trace/压缩状态），服务重启即失，无持久化。
- 金额成本仅为 `DEMO_PROJECTION` Token 估算；Token 估算器非真实 tokenizer。
- README 指出依赖本地 agents-flex 源码安装（与 Maven Central 同版本号构件存在漂移），pom 当前指向 2.2.9。
- Java 8 / javax.validation 语法约束；Spring Boot 2.7 已停止 OSS 维护。
- README 中启动路径为 macOS 风格（`/Users/michael/...`），Windows 环境需自行调整。
