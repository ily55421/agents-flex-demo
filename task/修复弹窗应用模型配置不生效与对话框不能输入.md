# 修复弹窗应用模型配置不生效与对话框不能输入

- 日期：2026-09-12
- 类型：缺陷修复（可用性）
- 触发：用户反馈"这里配置了模型不生效，对话框不能输入"（配置 ollama/qwen2.5:7b 与内网 bge-m3 后仍被禁用）

## 一、根因（三个问题叠加）

1. **后端强制 API Key**：`ModelProperties.isConfigured()` 要求非空密钥；Ollama（localhost:11434）与内网网关（192.168.31.214:8080）是免鉴权服务，用户留空 Key 即被判"未配置"→ 输入框永久禁用。
2. **弹窗"应用配置"只改浏览器**：不创建 Agent 时配置根本没到后端，模型状态（`/runs/model`）仍为 configured=false。
3. **引导文案过时**：空状态仍提示"请在左侧'模型连接'填写 API Key"（该表单组已移入弹窗）。

## 二、修复

### 后端
- `ModelProperties` 新增 `isLocalEndpoint()`：localhost/127./[::1]/0.0.0.0/host.docker.internal 及 192.168.、10.、172.16~31. 内网段视为免鉴权部署 → `isConfigured()` 对这类端点直接返回 true
- `ModelConfiguration.buildChatModel()`：免鉴权端点留空 Key 时填 `local-model` 占位
- **新增 `POST /api/agent/runs/model`**（`UpdateModelRequest` + `ResearchAgentFactory.applyModelConnection` + `ShowcaseRuntime.updateModel`）：仅应用模型连接到内存并失效 modelStatus 缓存，不必创建 Agent

### 前端
- `agentApi.updateModel()` + store `applyModelConfiguration()`：弹窗"应用配置"时把聊天模型同步到后端并刷新模型状态（头部芯片、输入框可用性立即变化）
- TaskComposer 弹窗应用后同时触发 `applyModel` 与 `configureEmbedding`（后者带空值保护）
- 应用向量配置后主动刷新 KnowledgePanel；失败也刷新（展示 lastError）
- ChatWorkspace 文案更新：占位符"请先点击左侧「⚙ 配置模型」应用模型配置"→"模型已就绪，点击左侧「创建 Agent」…"，空状态引导同步更新

### 附带修复（验证中发现的 500）
- 配置**不支持 /embeddings 的服务**（如 18888 网关）时 RogueMemory 构建抛含 HTML 的原始异常 → 500
- `KnowledgeService.configure()` 现在先探测连接：失败转 409 + 单行中文提示（含 404 时建议改用 Ollama），并回退 KEYWORD_ONLY 模式保证知识库可用；`lastError` 展示在知识库面板

## 三、验证（全部通过）

- `mvn test` 81 全绿；`pnpm build` 通过
- API 实测：`POST /runs/model`（ollama 无 Key）→ `configured:true`，GET 确认缓存已失效
- E2E `e2e_model_apply.py`：初始禁用（新提示）→ 弹窗选 Ollama 预设应用 → 头部芯片 `OLLAMA qwen2.5:7b` + data-configured=true → 提示推进到"创建 Agent"→ 创建成功 → **输入框可用、文本可输入**
- E2E 回归：纯对话页 13 项、知识库 7 项全过
- 坏向量服务：409 + 中文提示，知识库回退关键词模式不崩

## 四、用户操作指引

本地/内网免鉴权模型：弹窗选预设（或自定义填地址+模型名，Key 留空）→ 应用配置 → 创建 Agent → 对话框解锁。
云服务商（DeepSeek/OpenAI 等）：同上，但需填 API Key。
