## 第1讲：数据库技术引言

### 1.1 数据管理的发展阶段
*   **人工管理阶段**：数据不保存，无共享，应用程序管理数据。
*   **文件系统阶段**：数据可长期保存，但冗余度高，数据独立性差，存在数据孤立和一致性维护困难。
*   **数据库系统阶段**：数据结构化，共享性高，独立性高，由 DBMS 统一管理和控制。

### 1.2 数据库系统基本概念
*   **DB (Database)**：相互有关联的数据集合。
*   **DBMS (Database Management System)**：位于用户与操作系统之间的一层数据管理软件，负责数据的定义、操纵、控制和维护。
*   **DBS (Database System)**：DB + DBMS + 应用系统 + DBA + 用户。

### 1.3 数据视图与抽象
DBMS 通过三层抽象屏蔽复杂性：
1.  **物理层 (Physical Level)**：描述数据在存储介质上的具体存储方式（如磁盘块、字节）。
2.  **逻辑层 (Logical Level)**：描述数据库中存储什么数据及其关系（如表、记录、字段）。DBA 和开发人员主要在此层工作。
3.  **视图层 (View Level)**：描述用户看到的部分数据，提供安全性和简化接口。

**数据独立性**：
*   **物理数据独立性**：修改物理模式不影响逻辑模式。
*   **逻辑数据独立性**：修改逻辑模式不影响外部视图/应用程序。

### 1.4 DBMS 总体结构
*   **查询处理器**：
    *   DDL 解释器：处理模式定义。
    *   DML 编译器：将查询转换为低级指令，进行查询优化。
    *   查询执行引擎：执行低级指令。
*   **存储管理器**：
    *   权限及完整性管理器。
    *   事务管理器：保证 ACID 特性。
    *   文件管理器：管理磁盘空间分配。
    *   缓冲区管理器：管理内存与磁盘间的数据交换 a.k.a. Buffer Pool。

## 第2讲：实体-联系模型 (E-R Model)

### 2.1 基本概念
*   **实体 (Entity)**：现实世界中可区别的对象。
*   **属性 (Attribute)**：实体的特征。
    *   简单/复合属性
    *   单值/多值属性
    *   NULL 属性
    *   派生属性
*   **联系 (Relationship)**：实体间的关联。
    *   **映射基数 (Cardinality)**：一对一 (1:1)、一对多 (1:N)、多对多 (M:N)。
    *   **参与约束**：全部参与 vs 部分参与。

### 2.2 E-R 图设计要素
*   **矩形**：实体集。
*   **椭圆**：属性。
*   **菱形**：联系集。
*   **双线矩形/菱形**：弱实体集/标识性联系。

### 2.3 扩展 E-R特性
*   **特殊化 (Specialization)**：自顶向下，强调差异（如：学生 -> 本科生/研究生）。
*   **概括 (Generalization)**：自底向上，强调共性。
*   **聚集 (Aggregation)**：将联系视为高层实体，用于表达联系与其他实体间的关系。

### 2.4 E-R 图到关系表的转换规则
1.  **强实体集**：直接转换为表，主码即为表的主码。
2.  **弱实体集**：转换为表，包含自身属性 + 依赖的强实体主码。主码 = 强实体主码 + 弱实体分辨符。
3.  **联系集**：
    *   **M:N**：单独建表，主码为两端实体主码的组合。
    *   **1:N**：可将“1”方主码加入“N”方表中作为外键，或单独建表（主码为 N 方主码）。
    *   **1:1**：可将任一方主码加入另一方，或单独建表。
4.  **多值属性**：单独建表，包含原实体主码 + 该属性值。

## 第3讲：关系模型与关系代数

### 3.1 关系模型基础
*   **关系 (Relation)**：数学上定义为域笛卡尔积的子集，表现为二维表。
*   **模式 (Schema)**：关系的结构定义（属性名、类型）。
*   **实例 (Instance)**：特定时刻表中数据的集合。
*   **码 (Key)**：
    *   **超码**：能唯一标识元组的属性集。
    *   **候选码**：最小超码。
    *   **主码**：选定的候选码。
    *   **外码**：引用其他关系主码的属性。

### 3.2 关系代数 (Relational Algebra)
一种过程化查询语言，运算对象和结果均为关系。

**基本运算**：
1.  **选择 ($\sigma$)**：筛选满足条件的行。
2.  **投影 ($\Pi$)**：筛选指定的列（去重）。
3.  **并 ($\cup$)**：两个相容关系的元组合并。
4.  **集合差 ($-$)**：在 R 中但不在 S 中的元组。
5.  **笛卡尔积 ($\times$)**：R 中每个元组与 S 中每个元组拼接。
6.  **更名 ($\rho$)**：重命名关系或属性。

**附加运算**（可由基本运算推导）：
*   **交 ($\cap$)**：$R \cap S = R - (R - S)$。
*   **自然连接 ($\bowtie$)**：基于公共属性相等进行的连接，并去除重复列。
*   **Theta 连接 ($\bowtie_\theta$)**：基于任意条件 $\theta$的连接。
*   **除 ($\div$)**：用于“对所有...”类型的查询。
*   **赋值 ($\leftarrow$)**：用于简化复杂表达式。

**扩展运算**：
*   **广义投影**：允许算术表达式。
*   **外连接**：左外、右外、全外连接，保留未匹配元组并用 NULL 填充。
*   **聚集函数**：avg, min, max, sum, count。支持分组聚集 ($G$).

## 第4讲：结构化查询语言 SQL

### 4.1 SQL 概述
*   集 DDL (定义), DML (操纵), DCL (控制) 于一体。
*   非过程化，面向集合操作。

### 4.2 基本查询结构
```sql
SELECT [DISTINCT] <列名>
FROM <表名>
WHERE <条件>
GROUP BY <分组列>
HAVING <分组过滤条件>
ORDER BY <排序列> [ASC|DESC];
```
*   **执行顺序**：FROM -> WHERE -> GROUP BY -> HAVING -> SELECT -> ORDER BY。
*   **字符串匹配**：`LIKE '%pattern_'` (% 匹配任意串, _ 匹配单个字符)。
*   **空值处理**：使用 `IS NULL` / `IS NOT NULL`，不能用 `= NULL`。

### 4.3 集合操作
*   `UNION` (并), `INTERSECT` (交), `EXCEPT` (差)。
*   默认去重，使用 `ALL` 保留重复项。

### 4.4 嵌套子查询
*   **IN / NOT IN**：测试集合成员资格。
*   **比较运算符 + SOME/ALL**：如 `> SOME`, `>= ALL`。
*   **EXISTS / NOT EXISTS**：测试子查询结果是否为空（相关子查询常用）。
*   **FROM 子句中的子query**：生成派生关系（临时表），必须指定别名。

### 4.5 视图 (View)
*   **定义**：`CREATE VIEW view_name AS <查询语句>`。
*   **特点**：虚表，不存储数据，只存储定义。提高安全性、逻辑独立性。
*   **更新限制**：一般只读，若涉及多表、聚集函数等则不可更新。

### 4.6 数据修改
*   **插入**：`INSERT INTO ... VALUES ...` 或 `INSERT INTO ... SELECT ...`。
*   **删除**：`DELETE FROM ... WHERE ...`。
*   **更新**：`UPDATE ... SET ... WHERE ...`。

### 4.7 连接 (Join)
*   `INNER JOIN`: 仅返回匹配行。
*   `LEFT/RIGHT/FULL OUTER JOIN`: 保留未匹配行。
*   `NATURAL JOIN`: 自动基于同名同值属性连接。
*   `JOIN ... ON <condition>`: 指定连接条件。

### 4.8 DDL (数据定义)
*   `CREATE TABLE`: 定义表结构、主键、外键、Check 约束。
*   `ALTER TABLE`: 添加/删除列。
*   `DROP TABLE`: 删除表。
*   **数据类型**：char, varchar, int, numeric, date, time 等。

## 第5讲：完整性约束与模式分解

### 5.1 完整性约束类型
1.  **域约束 (Domain Constraints)**：属性取值范围（数据类型、Check）。
2.  **参照完整性 (Referential Integrity)**：外码必须引用存在的主码值。
    *   违反时的策略：拒绝 (No Action)、级联 (Cascade)、置空 (Set Null)。
3.  **断言 (Assertions)**：全局约束 `CREATE ASSERTION ... CHECK (...)`，开销大，少用。
4.  **触发器 (Triggers)**：事件驱动的代码块，用于复杂业务逻辑和完整性维护。

### 5.2 函数依赖 (Functional Dependency, FD)
*   **定义**：若 $X \rightarrow Y$，则对于关系中任意两个元组，若 X 值相同，则 Y 值必相同。
*   **Armstrong 公理**：自反律、增补律、传递律。
*   **闭包 ($F^+$)**：由 F 逻辑蕴涵的所有函数依赖集合。

### 5.3 范式 (Normal Forms)
*   **1NF**：属性原子性，不可再分。
*   **2NF**：在 1NF 基础上，非主属性完全依赖于主码（消除部分依赖）。
*   **3NF**：在 2NF 基础上，非主属性不传递依赖于主码（消除传递依赖）。
*   **BCNF**：在 3NF 基础上，所有决定因素都包含候选码。

### 5.4 模式分解
*   **目标**：消除冗余，避免插入/删除/更新异常。
*   **无损连接分解**：分解后的关系自然连接能恢复原关系，无信息丢失。
    *   判定条件：$R_1 \cap R_2 \rightarrow R_1$ 或 $R_1 \cap R_2 \rightarrow R_2$。
*   **保持函数依赖**：分解后能在局部关系上验证原有的 FD。

## 第6讲：存储结构和文件结构

### 6.1 物理存储基础
*   **磁盘结构**：盘片、磁道、扇区、柱面。
*   **块 (Block/Page)**：I/O 传输的基本单位。
*   **RAID**：独立磁盘冗余阵列。
    *   RAID 0 (条带化，高性能，无冗余)
    *   RAID 1 (镜像，高可靠，成本高)
    *   RAID 5 (分布式奇偶校验，平衡性能与可靠性，常用)

### 6.2 文件组织
*   **堆文件 (Heap File)**：记录无序存放，插入快，检索慢。
*   **顺序文件 (Sequential File)**：按搜索码排序存放，适合范围查询，插入维护成本高。
*   **散列文件 (Hashed File)**：通过哈希函数定位桶，适合等值查询，不支持范围查询。
*   **簇集文件 (Clustered File)**：将不同关系中相关联的记录物理上靠近存储，优化连接操作。

### 6.3 记录存储
*   **定长记录**：易于管理，可能浪费空间。
*   **变长记录**：
    *   字节流表示法。
    *   **滑槽页结构 (Slotted Page Structure)**：页头包含槽指针数组，指向记录实际位置。支持记录移动而不改变外部指针指向的逻辑地址。

### 6.4 数据字典
*   存储元数据（关于数据的数据），如表结构、用户权限、统计信息等。通常以系统表形式存在。

## 第7讲：索引、散列和查询处理

### 7.1 索引基础
*   **目的**：加速数据检索。
*   **评价标准**：访问类型支持、访问时间、插入/删除/更新开销、空间开销。
*   **分类**：
    *   **主索引 (Primary/Clustered)**：决定数据物理顺序，一个表只有一个。
    *   **辅助索引 (Secondary/Non-clustered)**：不决定物理顺序，可有多个。
    *   **稠密索引**：每个搜索码值都有索引项。
    *   **稀疏索引**：只为部分值建立索引项（通常每个块一个）。

### 7.2 B+ 树索引
*   **结构**：平衡多路查找树。
    *   **叶节点**：包含所有数据指针（或数据本身），并通过指针链表连接，支持范围查询。
    *   **非叶节点**：作为多级稀疏索引，引导搜索路径。
*   **优点**：高度低（减少 I/O），支持随机和顺序访问，动态平衡。

### 7.3 散列索引
*   **原理**：$H(Key) \rightarrow Bucket Address$。
*   **适用**：仅适用于等值查询 (`=`)，不支持范围查询 (`>`, `<`, `BETWEEN`)。
*   **问题**：冲突处理（溢出链），动态散列（可扩展散列）解决桶分裂问题。

### 7.4 查询处理
1.  **解析与翻译**：SQL -> 关系代数表达式树。
2.  **优化**：
    *   **启发式优化**：尽早执行选择和投影，减少中间结果大小；将选择下推到连接之前。
    *   **基于代价的优化**：利用统计信息（元组数、块数、 distinct 值数）估算不同执行计划的 I/O 代价，选择代价最小的计划。
3.  **执行**：执行引擎根据计划执行算法（如嵌套循环连接、归并连接、哈希连接）。

## 第8讲：事务和并发控制

### 8.1 事务特性 (ACID)
*   **原子性 (Atomicity)**：要么全做，要么全不做。
*   **一致性 (Consistency)**：事务执行前后数据库保持一致状态。
*   **隔离性 (Isolation)**：并发事务互不干扰。
*   **持久性 (Durability)**：提交后修改永久保存。

### 8.2 并发控制问题
*   **丢失修改**：两个事务同时写，后写的覆盖先写的。
*   **脏读 (Dirty Read)**：读到未提交的数据。
*   **不可重复读 (Non-repeatable Read)**：同一事务内两次读取结果不同（因其他事务修改或删除）。
*   **幻读 (Phantom Read)**：同一事务内两次查询结果行数不同（因其他事务插入）。

### 8.3 锁协议 (Locking Protocols)
*   **锁类型**：共享锁 (S, 读), 排他锁 (X, 写)。
*   **两阶段封锁协议 (2PL)**：
    *   **增长阶段**：只加锁，不解锁。
    *   **缩减阶段**：只解锁，不加锁。
    *   **保证**：冲突可串行化。
*   **严格 2PL**：排他锁直到事务提交才释放。防止级联回滚。
*   **死锁处理**：
    *   **预防**：等待-死亡 (Wait-Die), 受伤-等待 (Wound-Wait)。
    *   **检测与恢复**：构建等待图，检测环路，回滚牺牲者事务。

### 8.4 时间戳排序协议 (Timestamp Ordering)
*   每个事务赋予唯一时间戳 TS(T)。
*   读写操作检查时间戳冲突，若违反顺序则回滚重启。
*   **优点**：无死锁。
*   **缺点**：可能导致频繁回滚（活锁风险），调度可能不可恢复。

### 8.5 恢复机制
*   **日志 (Log)**：记录事务开始、提交、以及所有更新操作的前像 (Before Image) 和后像 (After Image)。
*   **Undo**：回滚未提交事务的影响。
*   **Redo**：重做已提交但未写入磁盘的事务影响。
*   **检查点 (Checkpoint)**：定期将内存脏页刷盘，并在日志中标记，缩短恢复时间。

### 8.6 隔离级别 (SQL Standard)
1.  **Read Uncommitted**：允许脏读。
2.  **Read Committed**：不允许脏读，允许不可重复读和幻读（多数 DBMS 默认）。
3.  **Repeatable Read**：不允许脏读和不可重复读，允许幻读。
4.  **Serializable**：最高隔离级别，等效于串行执行，杜绝所有并发异常。
