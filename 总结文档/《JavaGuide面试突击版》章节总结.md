## 前言/导读：如何使用本书与简历指导

### 核心论点
-   **解决问题**：解决 Java 求职者在准备面试时知识体系零散、重点不突出以及简历撰写不规范的问题。
-   **核心观点**：面试准备应聚焦高频考点与底层原理，简历是面试的“敲门砖”，必须通过量化成果与技术深度来体现个人价值，而非简单罗列技能。

### 关键概念/事件
-   **STAR/FAB 法则**：简历与面试回答的黄金结构。STAR 指情境(Situation)、任务(Task)、行动(Action)、结果(Result)；FAB 指属性(Feature)、优势(Advantage)、利益(Benefit)。
-   **技术栈分级**：将技能分为“精通”、“熟悉”、“了解”三级，强调不要盲目写“精通”，除非能经受住底层源码级追问。
-   **项目亮点挖掘**：从业务难点、性能优化、架构设计三个维度提炼项目经验，避免写成流水账。

### 逻辑推演/叙事脉络
作者首先分析了当前 Java 就业市场的竞争态势，指出“八股文”虽是基础但需理解而非死记。随后转入简历指导，通过对比“差简历”与“好简历”的案例，论证了量化数据和技术细节的重要性。最后给出了面试全流程的心态建设与复习路线图，强调“基础+项目+算法”三位一体的准备策略。

### 经典金句/数据
> “简历不是你的自传，而是你向企业推销自己的广告。每一个技术名词背后，都应该有一个你能讲清楚的故事。”

## 第1章：Java 基础

### 核心论点
-   **解决问题**：澄清 Java 语言基础中易混淆的概念，夯实面向对象与核心 API 的理解。
-   **核心观点**：Java 基础不仅是语法，更是对 JVM 内存模型、对象生命周期及 API 设计哲学的理解，这是区分初级与中级开发者的分水岭。

### 关键概念/事件
-   **String 不可变性**：String 被声明为 final 且内部数组不可变，保证了安全性、线程安全及哈希缓存，但也带来了拼接性能问题（引出 StringBuilder/Buffer）。
-   **== vs equals()**：`==` 比较引用地址（基本类型比值），`equals()` 默认比较地址但常被重写为值比较；重写 equals 必须重写 hashCode。
-   **反射与动态代理**：Java 动态性的基石，Spring AOP、MyBatis 等框架的核心实现机制，涉及 ClassLoader 与 Proxy 类。
-   **异常体系**：Throwable 分为 Error（系统级崩溃）和 Exception（可恢复），Checked Exception 强制处理，Unchecked (Runtime) 依赖开发者规范。

### 逻辑推演/叙事脉络
本章从数据类型切入，深入 String 的内存布局与常量池机制。接着探讨面向对象三大特性在 Java 中的具体体现（如多态的实现原理）。随后分析集合框架前的基础 API（Object, Comparable, Cloneable）。最后通过 IO/NIO/AIO 的演进，引出 Java 对高并发与高性能 IO 的支持历程。整体遵循“语法 -> 内存 -> 设计哲学”的递进逻辑。

### 经典金句/数据
> “String 的不可变性是 Java 安全模型的基石之一，它使得字符串可以安全地在多线程间共享而无需同步。”

## 第2章：Java 集合框架

### 核心论点
-   **解决问题**：解析常用集合容器的底层数据结构、扩容机制及线程安全问题。
-   **核心观点**：没有万能的集合，只有适合场景的选择；理解 HashMap 的红黑树转换与 ConcurrentHashMap 的锁优化是掌握集合框架的关键。

### 关键概念/事件
-   **ArrayList vs LinkedList**：数组 vs 双向链表。ArrayList 随机访问 O(1) 但插入删除慢；LinkedList 反之。实际开发中 ArrayList 因 CPU 缓存友好性通常优于 LinkedList。
-   **HashMap 进化史**：JDK1.7 数组+链表（头插法，并发死循环风险） -> JDK1.8 数组+链表+红黑树（尾插法，链表长度>8 且容量>=64 转树）。
-   **ConcurrentHashMap**：JDK1.7 Segment 分段锁 -> JDK1.8 Node + CAS + synchronized + volatile，锁粒度细化到桶头节点，并发度大幅提升。
-   **Fail-Fast vs Fail-Safe**：快速失败（modCount 检测）保障单线程安全；安全失败（CopyOnWrite）牺牲实时性保障并发读取。

### 逻辑推演/叙事脉络
先总览 Collection 与 Map 接口体系。重点剖析 List 的存储差异与性能权衡。随后花费大量篇幅详解 HashMap：从 hash 扰动函数、put/get 流程、扩容 rehash 到红黑树转换阈值。接着对比 Hashtable 与 ConcurrentHashMap，阐述并发容器如何平衡“线程安全”与“性能”。最后简述 Set 作为 Map Key 视图的本质。

### 经典金句/数据
> “HashMap 在 JDK1.8 中引入红黑树并非为了替代链表，而是为了防止极端哈希冲突下查询效率退化为 O(n)，是一种兜底的安全机制。”

## 第3章：Java 多线程与并发

### 核心论点
-   **解决问题**：建立正确的并发编程思维，掌握 JUC 工具包原理与线程安全方案。
-   **核心观点**：并发的本质是对共享资源的管理；理解 JMM（Java 内存模型）是理解 volatile、synchronized 及原子类的理论基础。

### 关键概念/事件
-   **线程生命周期**：NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED 六种状态及其转换条件。
-   **synchronized 锁升级**：无锁 -> 偏向锁 -> 轻量级锁（CAS）-> 重量级锁（Monitor）。JDK1.6 后的优化使其性能接近 ReentrantLock。
-   **AQS (AbstractQueuedSynchronizer)**：JUC 的基石，通过 state + CLH 队列实现独占/共享锁，ReentrantLock、CountDownLatch 等均基于此构建。
-   **线程池参数**：corePoolSize, maxPoolSize, workQueue, handler 的协作流程；拒绝策略的选择与生产环境配置规范（禁止使用 Executors 创建）。

### 逻辑推演/叙事脉络
从进程/线程区别入手，讲解线程创建方式与状态流转。深入 JMM 的可见性、有序性、原子性问题，引出 volatile 与 happens-before 原则。接着分析 synchronized 的底层 Monitor 机制与锁升级过程。随后介绍 AQS 框架及其衍生工具。最后落脚于线程池的工程实践与 ThreadLocal 的内存泄漏风险。

### 经典金句/数据
> “线程池的真正意义不在于‘减少线程创建开销’，而在于‘控制并发资源上限’，防止系统因过载而崩溃。”

## 第4章：JVM 虚拟机

### 核心论点
-   **解决问题**：理解 Java 代码的运行载体，掌握内存管理、GC 算法与调优手段。
-   **核心观点**：JVM 是 Java 跨平台与自动内存管理的核心；GC 调优的本质是在吞吐量、延迟与内存占用之间寻找平衡点。

### 关键概念/事件
-   **运行时数据区**：堆（对象）、方法区（元数据）、栈（局部变量/调用）、程序计数器、本地方法栈。OOM 常发于堆与方法区。
-   **垃圾回收算法**：标记-清除（碎片）、复制（新生代）、标记-整理（老年代）。分代收集理论是 GC 设计的基石。
-   **垃圾收集器**：Serial/ParNew/CMS/G1/ZGC。G1 将堆划分为 Region，兼顾吞吐与停顿时间；ZGC 追求亚毫秒级停顿。
-   **类加载机制**：加载、验证、准备、解析、初始化五阶段；双亲委派模型保证核心类安全，SPI/OSGi 打破双亲委派的场景。

### 逻辑推演/叙事脉络
首先描绘 JVM 内存全景图，明确各区域职责与异常类型。接着探讨对象存活判定（可达性分析）与 GC 算法优劣。然后按时间线梳理收集器演进，重点对比 CMS 与 G1 的设计差异。之后讲解类加载全过程与双亲委派模型。最后给出常见 OOM 排查思路与 JVM 参数调优实战案例。

### 经典金句/数据
> “所有的 GC 调优都应始于监控数据，终于业务目标。脱离业务场景谈 GC 参数都是耍流氓。”

## 第5章：计算机网络

### 核心论点
-   **解决问题**：补齐后端工程师的网络短板，理解 HTTP/TCP 协议栈与网络安全。
-   **核心观点**：网络协议是分层的抽象，每一层都在解决特定问题；理解 TCP 可靠传输与 HTTP 语义是排查分布式系统问题的关键。

### 关键概念/事件
-   **TCP 三次握手/四次挥手**：SYN/ACK 标志位作用，为什么握手3次挥手4次（全双工关闭），TIME_WAIT 状态的意义。
-   **HTTP 1.x vs 2.0 vs 3.0**：1.1 持久连接/管线化；2.0 二进制帧/多路复用/头部压缩；3.0 QUIC/UDP 解决队头阻塞。
-   **HTTPS 加密**：对称加密（AES）传数据，非对称加密（RSA/ECDHE）交换密钥，CA 证书防篡改。TLS 握手流程详解。
-   **Cookie/Session/JWT**：状态管理三件套。Session 服务端有状态，JWT 客户端无状态，各自适用场景与安全陷阱。

### 逻辑推演/叙事脉络
从 OSI/TCP-IP 模型宏观切入。深入传输层，图解 TCP 连接管理与流量/拥塞控制。上升至应用层，对比 HTTP 版本演进与 HTTPS 安全原理。接着讨论 Web 认证机制与跨域/CSRF 防护。最后简述 DNS、CDN 等基础设施原理。

### 经典金句/数据
> “TCP 的可靠性是以牺牲实时性为代价的；在弱网环境下，QUIC (HTTP/3) 通过 UDP 重建传输层，实现了真正的低延迟。”

## 第6章：数据库 (MySQL)

### 核心论点
-   **解决问题**：掌握关系型数据库索引原理、事务隔离与 SQL 优化方法论。
-   **核心观点**：索引是空间换时间的艺术，B+树结构决定了查询性能的边界；SQL 优化应从执行计划出发，而非凭感觉改写。

### 关键概念/事件
-   **B+ Tree 索引**：聚簇索引（数据即索引）vs 二级索引（回表）；覆盖索引避免回表；最左前缀匹配原则。
-   **事务 ACID 与隔离级别**：Undo Log 保原子性，Redo Log 保持久性，MVCC 保隔离性。RR 级别下 Next-Key Lock 解决幻读。
-   **SQL 执行流程**：连接器->查询缓存->分析器->优化器->执行器。Explain 关键字段：type, key, rows, Extra。
-   **分库分表**：垂直拆分（业务解耦）vs 水平拆分（数据量级）。ShardingSphere/MyCat 中间件方案与分布式 ID 生成。

### 逻辑推演/叙事脉络
先回顾 MySQL 架构与存储引擎（InnoDB vs MyISAM）。深入索引数据结构，解释为何选 B+树而非 Hash/B树。接着剖析事务实现原理，重点讲 MVCC 版本链与 ReadView。然后进入实战环节，演示如何通过 Explain 定位慢查询。最后扩展至高可用（主从/MGR）与分片架构。

### 经典金句/数据
> “索引不是越多越好，每个索引都有维护成本。联合索引的设计应遵循‘等值查询优先、区分度高优先、排序字段靠后’的原则。”

## 第7章：Redis

### 核心论点
-   **解决问题**：理解 Redis 高性能原因、持久化机制及典型应用场景。
-   **核心观点**：Redis 快不仅因为内存操作，更得益于 IO 多路复用与高效数据结构；缓存一致性是分布式系统中的永恒难题。

### 关键概念/事件
-   **核心数据结构**：SDS, ZipList, QuickList, Skiplist, IntSet。不同数据量级下的编码转换策略。
-   **持久化 RDB vs AOF**：RDB 快照恢复快但可能丢数据；AOF 日志数据安全但文件大。混合持久化（4.0+）兼顾两者优点。
-   **缓存三兄弟**：穿透（布隆过滤器）、击穿（互斥锁/逻辑过期）、雪崩（随机TTL/多级缓存）。
-   **分布式锁**：SETNX + EXPIRE 原子性。Redisson WatchDog 续期机制。Redlock 算法争议与工程取舍。

### 逻辑推演/叙事脉络
从 Redis 单线程模型与 IO 多路复用解释“为什么快”。逐一拆解五大基本类型的底层编码。对比 RDB/AOF 优缺点与适用场景。深入缓存异常场景与解决方案。接着讲解集群模式（Sentinel/Cluster）与数据分片。最后探讨 Lua 脚本、Pipeline 等高级特性。

### 经典金句/数据
> “Redis 的单线程指的是‘网络请求处理与命令执行’单线程，6.0 后 IO 读写已多线程化。不要用旧认知限制新技术的应用。”

## 第8章：Spring 全家桶

### 核心论点
-   **解决问题**：透视 Spring 核心设计思想，掌握 IOC/AOP/事务/Boot 启动原理。
-   **核心观点**：Spring 的本质是容器与胶水；IOC 解耦组件，AOP 分离关注点，Boot 约定优于配置，三者共同构成了现代 Java 开发的基石。

### 关键概念/事件
-   **IOC 容器**：BeanDefinition -> BeanFactory -> ApplicationContext。三级缓存解决循环依赖。Bean 生命周期与扩展点（BeanPostProcessor）。
-   **AOP 代理**：JDK Dynamic Proxy（接口）vs CGLIB（类）。AspectJ 织入时机。事务失效的八大场景（自调用、异常类型、传播行为等）。
-   **Spring Boot 启动**：@SpringBootApplication 组合注解。AutoConfiguration 条件装配（@Conditional）。Starter 机制与 SPI 加载。
-   **Spring MVC 流程**：DispatcherServlet -> HandlerMapping -> HandlerAdapter -> ViewResolver。RESTful 设计与统一异常处理。

### 逻辑推演/叙事脉络
先宏观介绍 Spring 生态与设计理念。深入 IOC 容器启动与 Bean 创建全流程，图解循环依赖解决。接着剖析 AOP 动态代理实现与事务管理器。然后转向 Spring Boot，揭秘自动配置原理与启动事件。最后简述 MVC 请求处理链路。全程贯穿“源码级理解”与“工程化应用”两条线。

### 经典金句/数据
> “Spring 事务失效最常见的原因不是配置错误，而是‘同类方法自调用’绕过了代理对象。理解代理模式是避坑的前提。”

## 第9章：MyBatis

### 核心论点
-   **解决问题**：理解 ORM 框架工作原理，掌握 MyBatis 插件开发与性能优化。
-   **核心观点**：MyBatis 是半自动 ORM，保留了 SQL 控制权；其核心在于 SqlSession、Executor 与 MapperProxy 的动态代理机制。

### 关键概念/事件
-   **核心组件**：SqlSessionFactory -> SqlSession -> Executor -> StatementHandler -> ResultSetHandler。一级/二级缓存机制与坑。
-   **#{} vs ${}**：预编译（防注入）vs 字符串替换（动态表名/排序）。
-   **插件机制**：Interceptor 拦截四大对象方法。分页插件 PageHelper 原理与 ThreadLocal 风险。
-   **延迟加载**：CGLIB 代理 + 触发方法重写。N+1 问题与关联查询优化。

### 逻辑推演/叙事脉络
从 JDBC 痛点引出 MyBatis 价值。梳理配置加载与 SQL 执行全流程。对比 #{} 与 ${} 的安全差异。深入缓存机制与失效场景。讲解插件开发原理与常见应用。最后讨论 MyBatis-Plus 等增强工具的取舍。

### 经典金句/数据
> “MyBatis 的一级缓存默认开启但在分布式环境下极易导致脏读，建议在微服务架构中显式关闭或仅用于只读场景。”

## 第10章：系统设计与分布式

### 核心论点
-   **解决问题**：培养架构思维，应对高并发、高可用、海量数据场景的设计挑战。
-   **核心观点**：系统设计没有银弹，只有权衡（Trade-off）；所有架构决策都应围绕 CAP/BASE 理论与业务 SLA 展开。

### 关键概念/事件
-   **分布式理论**：CAP 定理（CP/AP 选择），BASE 理论（最终一致性）。Raft/Paxos 共识算法。
-   **消息队列**：解耦、削峰、异步。Kafka/RocketMQ/RabbitMQ 选型。消息丢失/重复/积压解决方案。顺序消息与事务消息。
-   **微服务治理**：注册发现（Nacos/Eureka）、负载均衡、熔断限流（Sentinel/Hystrix）、链路追踪（SkyWalking）。网关鉴权与灰度发布。
-   **海量数据处理**：读写分离、分库分表、ES 搜索、冷热分离。分布式事务（Seata AT/TCC/Saga）。

### 逻辑推演/叙事脉络
先从单体到分布式的演进讲起，引入 CAP 理论作为决策标尺。接着分模块讲解 MQ、缓存、数据库、RPC 的设计要点与常见问题。然后整合为完整的高并发/高可用架构案例（如秒杀、订单）。最后探讨分布式事务与数据一致性方案。强调“场景驱动设计”而非“技术驱动设计”。

### 经典金句/数据
> “架构设计的终极目标不是追求技术的先进性，而是在满足业务需求的前提下，让系统的复杂度可控、成本可接受。”

## 附录：真实大厂面经与复盘

### 核心论点
-   **解决问题**：提供一线实战反馈，帮助读者校准复习方向与面试节奏。
-   **核心观点**：面经的价值不在于背题，而在于洞察考察重点的变化趋势与自身知识盲区。

### 关键概念/事件
-   **面试轮次侧重**：一面基础（八股+算法），二面项目/架构（深度+广度），三面综合素质（潜力+文化），HR面（稳定性+薪资）。
-   **高频考点变迁**：从纯背诵向“场景化提问”转变（如“如果...怎么办”）。手撕代码难度稳定在 LeetCode Medium。
-   **反问环节技巧**：问团队技术栈、业务挑战、成长路径，避免问“加班吗”“工资多少”等敏感问题。

### 逻辑推演/叙事脉络
收录多家互联网大厂（阿里、美团、字节等）的真实面试记录。按公司/岗位分类展示问答实录。每篇面经后附点评与知识点延伸。最后总结共性规律与备考建议。
