## 第一部分：前端工程化管理工具 (01-05)
> **核心目标**：透过工具表象看本质，理解包管理和构建工具的底层机制。

### 01 安装机制及企业级部署私服原理
*   **npm 内部机制**：解析 `npm install` 流程（检查 config -> lock 文件 -> 构建依赖树 -> 下载/缓存 -> 解压）。
*   **扁平化安装**：npm v3+ 采用扁平化目录结构解决“依赖地狱”，但需注意版本冲突时的嵌套安装。
*   **缓存机制**：`cacache` 文件夹存储二进制内容和索引，加速二次安装。
*   **企业级私服**：Nexus/Verdaccio 原理（代理转发、私有仓库托管、Group Repository 合并），解决内网速度和私有模块安全问题。

### 02 Yarn 安装理念及依赖管理困境破解
*   **Yarn 优势**：确定性（lock 文件）、并行安装、离线模式、扁平化。
*   **安装五步曲**：检测包 -> 解析包（确定版本）-> 获取包（下载/缓存）-> 链接包（扁平化复制到 node_modules）-> 构建包（编译二进制）。
*   **依赖冲突解决**：理解 npm/yarn 如何处理同一依赖的不同版本（顶层提升 vs 嵌套安装）。

### 03 CI 环境下的 npm 优化及工程化问题解析
*   **CI 优化**：使用 `npm ci` 代替 `npm install`（严格依据 lock 文件，速度快，纯净安装）。
*   **Lock 文件提交**：应用项目必须提交 lock 文件以保证环境一致；公共库通常不提交（避免锁定子依赖版本）。
*   **依赖类型详解**：`dependencies`, `devDependencies`, `peerDependencies` (插件场景), `bundledDependencies`, `optionalDependencies`。
*   **版本锁定**：SemVer 规范，以及 create-react-app 等工具如何强制校验核心依赖版本。

### 04 主流构建工具的设计考量
*   **横向对比**：Webpack, Rollup, Parcel, Browserify。
*   **六大维度**：Code Splitting（代码分割）, Hashing（缓存策略）, Importing Modules（模块化兼容）, Non-JS Resources, Output Module Formats, Transformations（编译转换）。
*   **Hash 策略**：`hash` (项目级), `chunkhash` (入口级), `contenthash` (文件内容级，推荐用于长期缓存)。

### 05 Vite 实现：源码分析与工程构建
*   **Vite 哲学**：利用浏览器原生 ESM，开发环境无打包（Bundleless），按需编译；生产环境使用 Rollup 打包。
*   **核心流程**：
    *   Koa 服务器拦截请求。
    *   中间件重写 import 路径（如 `vue` -> `/@modules/vue`）。
    *   即时编译 `.vue`, `.ts`, `.css` 等文件。
    *   HMR 基于 WebSocket 和 ESM 动态导入，速度不随模块增加而变慢。

## 第二部分：现代化前端开发和架构生态 (06-16)
> **核心目标**：掌握 Babel、Polyfill、Tree Shaking 等生态核心概念，理解跨端技术演进。

### 06 谈谈 core-js 及 polyfill 理念
*   **Core-js 架构**：Monorepo 结构，分为 `core-js` (全局污染), `core-js-pure` (无污染), `core-js-compat` (兼容性数据)。
*   **Polyfill 方案演进**：
    *   手动补丁 -> es5-shim -> babel-polyfill (全量引入，体积大) -> `@babel/preset-env` + `useBuiltIns: 'entry'/'usage'` (按需引入)。
    *   **最佳实践**：按环境 targets 和代码使用情况按需打补丁，结合 `core-js-compat`。

### 07 梳理混乱的 Babel，拒绝编译报错
*   **Babel 本质**：JavaScript 编译器（Parser -> Transformer -> Generator）。
*   **Monorepo 家族**：
    *   `@babel/core`: 核心转换。
    *   `@babel/parser/traverse/types/generator`: AST 操作底层能力。
    *   `@babel/preset-env`: 智能降级，结合 browserslist。
    *   `@babel/plugin-transform-runtime` + `@babel/runtime`: 提取 helper 函数，避免重复注入和全局污染。
*   **分层架构**：辅助层 -> 基础层 -> 胶水层 (Presets/Plugins) -> 应用层 (CLI/Loader)。

### 08 前端工具链：统一标准化的 babel-preset
*   **公共库 vs 应用项目**：
    *   公共库：需考虑多环境兼容，通常发布 ES Module 格式以支持 Tree Shaking，不内置 Polyfill。
    *   应用项目：统一编译标准，处理 `node_modules` 中的第三方库（`sourceType: 'unambiguous'`）。
*   **标准化 Preset 设计**：区分 `app`, `dependencies`, `library` 预设，统一管理 runtime 路径和编译目标。

### 09 从 0 到 1 构建一个符合标准的公共库
*   **多环境适配**：
    *   浏览器 `<script>` 标签：UMD 格式，挂载全局变量。
    *   Node.js/CommonJS：`main` 字段。
    *   ESM/Bundler：`module` 字段。
*   **构建工具选择**：Webpack (功能强大) 或 Rollup (适合库，Tree Shaking 友好)。
*   **Package.json 关键字段**：`main`, `module`, `browser`, `sideEffects`, `files`。

### 10 代码拆分与按需加载
*   **按需加载 vs 按需打包**：
    *   按需加载：运行时动态导入 (`import()`)。
    *   按需打包：构建时移除未引用代码 (Tree Shaking, `babel-plugin-import`)。
*   **Dynamic Import**：ESM Stage 4 特性，返回 Promise。Webpack 将其转换为 JSONP 异步加载脚本。
*   **SplitChunks**：自动提取公共代码，优化缓存命中率。

### 11 Tree Shaking：移除 JavaScript 上下文中的未引用代码
*   **前提条件**：必须使用 ESM (静态分析)，CommonJS 不支持。
*   **副作用 (Side Effects)**：
    *   Webpack 无法判断模块是否有副作用，默认保留。
    *   通过 `package.json` 中 `"sideEffects": false` 或数组标记告知 Webpack 可安全删除未引用模块。
*   **最佳实践**：原子化导出（避免 export default 一个大对象），使用纯函数。

### 12 理解 AST 实现和编译原理
*   **AST 基础**：抽象语法树，源码的结构化表示。
*   **Acorn 解析器**：词法分析 (Token) -> 语法分析 (AST)。
*   **实战：简易 Tree Shaking**：
    *   解析 AST。
    *   遍历收集声明 (`decls`) 和调用 (`calledDecls`)。
    *   过滤未调用的声明，重新生成代码。

### 13 工程化思维：主题切换架构
*   **PostCSS 插件化**：类似 Babel，基于 AST 处理 CSS。
*   **主题切换方案**：
    *   定义色组配置 (Light/Dark)。
    *   编写 PostCSS 插件识别自定义函数 `cc(color-group)`。
    *   编译时生成两套 CSS：一套默认 Light，一套通过属性选择器 `html[data-theme='dark']` 覆盖。
    *   结合 JS 切换 HTML 根节点属性。

### 14 解析 Webpack 源码，实现工具构建
*   **Webpack 本质**：静态模块打包器。
*   **核心原理**：
    *   **Dependency Graph**：递归解析入口依赖。
    *   **Module Map**：将所有模块包裹在函数中，存入对象。
    *   **Runtime**：实现简易 `require` 函数，从 Map 中加载执行模块。
*   **Rollup 对比**：Rollup 拍平代码，无包裹函数，更适合库打包。
*   **手写 Bundler**：利用 `@babel/parser` 解析依赖，`@babel/core` 编译，最终拼接 IIFE 代码。

### 15 跨端解析小程序多端方案
*   **三类方案**：编译时、运行时、编译+运行结合。
*   **类 Vue 方案 (如 mpvue/uni-app)**：
    *   编译时：Template 转 WXML (AST 转换)。
    *   运行时：内置 Vue Runtime，拦截数据变化，调用小程序 `setData`。
*   **类 React 方案 (如 Taro Next/Remax)**：
    *   难点：JSX 动态性难以静态编译。
    *   解法：利用 `react-reconciler`。自定义 `HostConfig`，将 React 的 Diff 结果映射为小程序的数据结构，通过 `setData` 更新视图。

### 16 从移动端跨平台到 Flutter 的技术变革
*   **Hybrid (WebView)**：JSBridge 通信，性能瓶颈在于频繁通信和 WebView 渲染。
*   **React Native (OEM Hybrid)**：JS 逻辑层 + Native 渲染层，通过 Bridge 异步通信。新版架构 (Fabric/TurboModules) 引入 JSI (C++) 实现同步调用，消除 Bridge 瓶颈。
*   **Flutter (自渲染)**：
    *   Dart 语言，Skia 引擎直接绘制 UI。
    *   三层架构：Framework (Dart), Engine (C++), Embedder (平台接入)。
    *   优势：高性能、高一致性；劣势：生态较小，包体积大。

## 第三部分：核心框架原理与代码设计模式 (17-22)
> **核心目标**：深入源码级别理解 Axios、Koa、Redux 等经典库的设计模式，掌握数据结构在前端的应用。

### 17 axios：封装一个结构清晰的 Fetch 库
*   **设计亮点**：
    *   **适配器模式 (Adapter)**：区分浏览器 (XHR) 和 Node.js (http) 环境。
    *   **拦截器 (Interceptor)**：洋葱模型，任务注册 -> 编排 (Chain) -> 调度 (Promise.then 链式调用)。
    *   **安全**：默认 XSRF 防御 (双重 Cookie 验证)。

### 18 对比 Koa 和 Redux：解析前端中间件
*   **Koa 中间件**：洋葱模型 (Async/Await + compose)。`next()` 控制流向下，执行完后向上回溯。
*   **Express 中间件**：线性模型，基于回调，难以处理响应后的逻辑。
*   **Redux 中间件**：函数柯里化 `store => next => action => ...`。通过 `compose` 增强 `dispatch`。
*   **实战**：实现一个中间件化的 `fetch-wrap`，解耦业务逻辑与请求核心。

### 19 软件开发的灵活性和定制性
*   **设计模式**：
    *   **代理模式 (Proxy)**：缓存计算结果、节流、Vue3 响应式原理。
    *   **装饰者模式**：React HOC (`connect`, `Form.create`)，AOP (Before/After)。
*   **函数式思想**：
    *   **纯函数**：无副作用，输入确定输出确定。
    *   **Curry (柯里化)**：参数复用，延迟执行。
    *   **UnCurry (反柯里化)**：借用方法，扩大适用范围 (如 `Array.prototype.push` 用于类数组对象)。

### 20 理解前端中的面向对象思想
*   **New 的实现**：创建空对象 -> 链接原型 -> 绑定 this 执行构造函数 -> 返回对象。
*   **继承**：
    *   ES5 组合继承 (原型链 + 构造函数窃取)。
    *   ES6 `class extends`。
    *   **特殊案例**：继承内置对象 (如 Date) 需要特殊处理原型链或使用 ES6 class。
*   **jQuery 面向对象**：工厂函数返回实例，原型方法挂载在 `$.fn`，静态方法挂载在 `$`。
*   **原型继承 vs 类继承**：原型继承更灵活，避免“大猩猩-香蕉”问题 (继承了一堆不需要的东西)。

### 21 利用 JavaScript 实现经典数据结构
*   **线性结构**：Stack (LIFO), Queue (FIFO), Linked List (单向/双向，指针操作)。
*   **树 (Tree)**：Binary Search Tree (BST)，插入、删除、查找、遍历 (前/中/后序)。
*   **图 (Graph)**：邻接表存储，BFS (队列), DFS (递归/栈)。
*   **哈希表**：键值对映射。

### 22 剖析前端数据结构的应用场景
*   **Stack**：浏览器历史记录、Undo/Redo、函数调用栈、React Context 状态入栈出栈。
*   **Queue**：事件循环 (宏/微任务)、HTTP/1.1 队头阻塞。
*   **Linked List**：**React Fiber**。将递归渲染拆解为链表遍历，支持时间切片 (Time Slicing) 和中断恢复，解决主线程阻塞问题。
*   **Tree**：DOM 树、Virtual DOM、React Element 树。DFS 用于 Reconciliation。
*   **Trie (字典树)**：自动补全 (Auto Complete)、搜索建议，空间换时间。

## 第四部分：前端架构设计实战 (23-26)
> **核心目标**：从 0 到 1 落地工程化方案，包括 Scripts、Lint、离线包、脚手架。

### 23 npm scripts：打造一体化构建和部署流程
*   **原理**：npm run 创建 Shell 环境，自动将 `node_modules/.bin` 加入 PATH。
*   **技巧**：钩子 (pre/post), 环境变量, 串行 (`&&`) / 并行 (`&`)。
*   **实战 lucas-scripts**：封装统一的 Babel/Webpack 配置，类似 `create-react-app` 但允许 eject/覆盖配置，实现 "Tools without config"。

### 24 自动化代码检查：剖析 Lint 工具
*   **Prettier vs ESLint**：Prettier 负责格式化 (风格)，ESLint 负责代码质量 (逻辑/规范)。
*   **集成**：Husky (Git Hooks) + lint-staged (只检查暂存文件) + Prettier/ESLint。
*   **ESLint 原理**：Espree 解析 AST -> 遍历 AST -> 匹配规则 (Selector) -> 报告错误。支持 Code Path Analysis 处理复杂控制流。

### 25 前端 + 移动端离线包方案设计
*   **Hybrid 痛点**：WebView 启动慢、网络请求耗时。
*   **离线包 (NSR)**：客户端预下载 HTML/JS/CSS 模板。
*   **流程**：
    1.  客户端路由拦截。
    2.  检查离线包版本 (本地 vs 服务端)。
    3.  若可用：加载本地模板 + 客户端发起数据请求 + 渲染 HTML -> WebView 展示。
    4.  若不可用：走在线流程。
*   **平台化**：离线包管理平台 (上传、版本查询、增量下发、完整性校验)。
*   **优化**：增量更新 (bsdiff), 灰度发布, Fallback 机制。

### 26 设计一个“万能”的项目脚手架
*   **CLI 开发**：Node.js + Commander/Yargs (参数解析) + Inquirer (交互) + Chalk (颜色)。
*   **核心逻辑**：
    1.  解析参数。
    2.  交互式询问 (模板类型、Git 初始化等)。
    3.  下载/拷贝模板文件。
    4.  执行 Git init, npm install。
*   **万能扩展**：模板市场、版本管理、动态模板渲染 (EJS/Handlebars 填充 package.json 等配置文件)。

## 第五部分：前端全链路——Node.js 全栈开发 (27-30)
> **核心目标**：拓展前端边界，利用 Node.js 解决 SSR、性能监控、网关、自动化等后端/运维领域问题。

### 27 同构渲染架构：实现 SSR 应用
*   **SSR 流程**：
    *   Server: `renderToString` 生成 HTML 字符串 + 脱水 (Dehydrate) 初始状态。
    *   Client: `hydrate` 接管 DOM + 注水 (Hydrate) 恢复状态。
*   **关键细节**：
    *   **路由**：Server 用 `StaticRouter`，Client 用 `BrowserRouter`。
    *   **数据获取**：Server 端预取数据 (matchRoutes 或 static loadData)，序列化注入 HTML。
    *   **样式**：`isomorphic-style-loader` 收集组件样式，内联到 `<style>` 标签。
    *   **安全**：XSS 防护 (序列化状态时转义)。
    *   **鉴权**：Server 端透传 Cookie/Header 请求后端接口。

### 28 性能守卫系统设计：完善 CI/CD 流程
*   **性能指标**：LCP, FID, CLS (Core Web Vitals)。
*   **监控类型**：RUM (真实用户) vs Synthetic (合成监控/实验室数据)。
*   **Perf-patronus 系统**：
    *   基于 **Lighthouse** + **Puppeteer**。
    *   CI/CD 触发 -> Puppeteer 启动 Headless Chrome -> Lighthouse 跑分 -> 结果存入 Redis/数据库。
    *   **可变因素控制**：固定 CPU/网络 throttling，多次运行取平均。
    *   **自定义 Audit**：编写 Lighthouse 插件检查特定业务指标 (如大图检测)。

### 29 打造网关：改造企业级 BFF 方案
*   **BFF (Backend for Frontend)**：服务于前端的后端，负责数据聚合、裁剪、协议转换。
*   **Node.js 网关设计 (lucas-gateway)**：
    *   **反向代理**：基于 `fast-proxy` 或 `http-proxy`。
    *   **中间件**：限流 (rate-limit), IP 记录, 缓存 (Redis/Memory)。
    *   **Hooks**：`onRequest`/`onResponse` 拦截，实现鉴权、日志、熔断。
    *   **负载均衡**：自定义 proxyHandler 实现轮询/P2C 算法。
*   **价值**：解耦前后端，适配多端 (Web/App/MiniProgram) 数据需求。

### 30 实现高可用：Puppeteer 实战
*   **Puppeteer 原理**：通过 CDP (Chrome DevTools Protocol) 控制 Chromium。
*   **应用场景**：
    1.  **SSR 预渲染**：针对纯 CSR 页面，Puppeteer 访问后截图/获取 HTML，作为 SSR 替代方案 (成本高，通用性强)。
    2.  **UI 测试**：结合 Jest，模拟用户操作，断言页面状态。
    3.  **海报生成服务 (posterMan)**：
        *   接收 HTML/URL。
        *   **连接池**：使用 `generic-pool` 管理 Puppeteer 实例，避免频繁启动浏览器的开销。
        *   截图并返回图片流。
    4.  **性能监控**：与 Lighthouse 结合，自动化采集性能数据。

## 💡 总结与启示

1.  **工程化是核心竞争力**：不仅仅是配置 Webpack，而是理解依赖管理、编译原理、构建优化，打造自动化的研发流水线。
2.  **底层原理决定上限**：理解 AST、V8 机制、浏览器渲染原理、数据结构，才能解决复杂性能问题和设计高质量框架。
3.  **架构思维**：从单体到微服务，从 CSR 到 SSR/NSR，从单一端到多端跨平台，架构选型需权衡性能、开发效率和维护成本。
4.  **Node.js 是全栈利器**：不仅做 BFF 和 SSR，还能深入运维 (CI/CD 性能守卫)、自动化测试、图形处理等领域，拓宽前端职业边界。
5.  **持续演进**：技术栈在变 (jQuery -> React/Vue -> Vite/Solid)，但设计模式 (中间件、观察者、代理)、工程化思想 (模块化、按需加载、Tree Shaking) 是恒定的。
