## 3. 搜索增强（优先级：高）

### 3.1 搜索建议（Autocomplete）

**问题**：当前搜索需输入完整关键词后回车或等待 300ms，无实时建议。

**方案**：
- 前端：输入时调用 `/api/search-suggest?q=xxx&limit=8`
- 后端：从 `docs_fts` 提取高频匹配标题，返回 `[{id, title, category}]`
- UI：下拉面板展示，支持键盘上下选择 + Enter 直达

**实现要点**：
```python
# server.py 新增接口
def do_suggest(self, q):
    conn = get_db()
    rows = conn.execute("""
        SELECT d.id, d.title, c.name as category_name
        FROM docs_fts fts
        JOIN documents d ON d.id = fts.rowid
        JOIN categories c ON c.id = d.category_id
        WHERE docs_fts MATCH ?
        ORDER BY rank
        LIMIT 8
    """, (q,)).fetchall()
    return {"suggestions": [dict(r) for r in rows]}
```

### 3.2 分类过滤搜索

**问题**：搜索结果跨所有分类，无法限定在特定分类内检索。

**方案**：
- 搜索框旁增加分类下拉选择器
- API 增加 `category` 参数：`/api/search?q=xxx&category=java`
- FTS5 已索引 `category_name`，直接利用

### 3.3 搜索历史

**问题**：用户无法快速复用之前的搜索词。

**方案**：
- 使用 `localStorage` 存储最近 10 条搜索记录
- 搜索框聚焦时展示历史下拉
- 支持单个删除和一键清空

### 3.4 相似文档推荐

**问题**：阅读完一篇文章后，没有相关推荐。

**方案**：
- 文章页底部增加「相关文档」区域
- 后端：基于相同分类 + 标题关键词重叠度排序
- API：`/api/related?id=xxx&limit=5`

## 4. 阅读体验（优先级：高）

### 4.1 代码语法高亮

**问题**：代码块目前为纯文本，无语法着色。

**方案**：
- 引入轻量级高亮库（如 [Prism.js](https://prismjs.com/) 或 [highlight.js](https://highlightjs.org/)）
- 在 `md_to_html()` 中识别代码块语言标记
```python
# 提取语言标识
if stripped.startswith('```'):
    lang = stripped[3:].strip()  # ```python -> python
    # 渲染时添加 class
    html_lines.append(f'<pre><code class="language-{lang}">...')
```
- 前端加载对应 CSS 主题文件

### 4.2 阅读进度记忆

**问题**：刷新页面或重新进入文章后，滚动位置丢失。

**方案**：
- 滚动时节流保存 `scrollY` 到 `localStorage`（key: `scroll:articleId`）
- 进入文章页时读取并恢复位置
- 增加「继续阅读」按钮（如果上次有进度）

### 4.3 字体大小调节

**问题**：不同用户对字体大小需求不同。

**方案**：
- 文章页增加 A-/A+ 字体调节按钮
- 使用 CSS 变量 `--article-font-size`，通过 JS 调节
- 偏好保存到 `localStorage`

### 4.4 图片灯箱（Lightbox）

**问题**：文章中的图片点击后无法放大查看。

**方案**：
- 为 `.article-content img` 绑定点击事件
- 弹出全屏遮罩层展示原图
- 支持 ESC 关闭、左右切换（如果有多张图）

### 4.5 阅读时间估算

**问题**：用户无法预估阅读一篇文章需要多久。

**方案**：
- 后端：根据 `word_count` 计算阅读时间（按 300 字/分钟）
- 前端：在文章 meta 区显示「预计阅读 X 分钟」

## 5. 管理效率（优先级：中）

### 5.1 文档收藏

**问题**：用户无法标记常用文档。

**方案**：
- 增加收藏按钮（文章页右上角 ⭐）
- `localStorage` 存储收藏 ID 列表
- 侧边栏增加「我的收藏」入口
- 收藏数据可导出/导入（JSON 文件）

### 5.2 标签系统

**问题**：分类粒度较粗，同一分类下文档过多。

**方案**：
- 数据库新增 `tags` 表和 `document_tags` 关联表
- 从文档内容中提取标签（如 `#标签` 语法）或手动维护
- 支持按标签筛选和标签云展示

### 5.3 批量操作

**问题**：无法对多篇文档进行批量分类调整。

**方案**：
- 管理后台模式（通过 URL 参数 `?admin=1` 进入）
- 文档列表增加复选框
- 支持批量修改分类、批量重新索引

### 5.4 回收站机制

**问题**：误删文档后无法恢复。

**方案**：
- 数据库增加 `deleted_at` 字段（软删除）
- 删除时标记时间戳，不物理删除
- 提供「回收站」页面，支持恢复或彻底删除

## 6. 系统架构（优先级：中）

### 6.1 配置外置化

**问题**：所有配置硬编码在 `server.py` 中，修改需改代码。

**方案**：
- 新增 `config.json` 配置文件
```json
{
  "port": 8080,
  "db_path": "data/docs.db",
  "docs_src": "../",
  "page_limit": 20,
  "theme_default": "dark",
  "enable_suggest": true,
  "enable_highlight": true
}
```
- `server.py` 启动时读取，提供默认值

### 6.2 日志系统

**问题**：仅依赖 `print`，无日志级别和持久化。

**方案**：
- 使用 Python `logging` 模块替代 `print`
- 输出到 `data/server.log`，按天轮转
- 分级：DEBUG / INFO / WARNING / ERROR

### 6.3 性能监控

**问题**：不了解系统运行时的性能瓶颈。

**方案**：
- 记录 API 响应时间（中间件模式）
- 统计热点接口 QPS
- 提供 `/api/health` 健康检查接口

### 6.4 热重载开发模式

**问题**：修改 `server.py` 后需手动重启。

**方案**：
- 开发模式监听文件变更（`watchdog` 库或轮询）
- 文件修改后自动重启服务
- 生产环境关闭此功能

## 7. 前端工程化（优先级：低）

### 7.1 构建工具引入

**问题**：当前无构建流程，JS/CSS 直接手写。

**方案**：
- 引入 Vite 作为构建工具（轻量、快速）
- 模块化拆分：`router.js`, `search.js`, `theme.js`, `toc.js`
- 开发时 HMR，生产时打包压缩

### 7.2 TypeScript 迁移

**问题**：纯 JS 无类型检查，重构风险高。

**方案**：
- 逐步迁移到 TypeScript
- 定义接口类型：`Document`, `Category`, `SearchResult`
- 提升可维护性和 IDE 提示

### 7.3 UI 组件库

**问题**：所有组件从零手写，样式一致性维护成本高。

**方案**：
- 引入轻量级无依赖组件库（如 [Shoelace](https://shoelace.style/)）
- 或基于 Web Components 自建组件体系
- 优先替换：Button, Modal, Dropdown, Toast

## 10. 总结

当前文档博客系统已具备良好的基础架构（增量导入、FTS5 搜索、主题切换、章节导航）。建议按以下优先级推进优化：

1. **搜索增强**：建议优先实现，直接提升核心使用体验
2. **阅读体验**：代码高亮和阅读进度是高频需求
3. **管理效率**：收藏和标签系统提升长期价值
4. **系统架构**：配置化和日志是工程化基础
5. **前端工程化**：当前阶段优先级最低，可待系统稳定后考虑

保持「核心轻量、扩展可选」的原则，确保系统始终易于部署和维护。
