# 《管理信息系统》课程核心知识点总结

## 第一章：管理信息系统概述

### 1. 核心定义
*   **管理 (Management)**: 计划、组织、指挥、协调和控制资源，以有效达到组织目标。
*   **信息 (Information)**: 经过组织和处理、具有意义的数据。
    *   **数据 -> 信息 -> 知识**: 数据是客观事实；信息是有结构的数据；知识是能预测规律、指导行动的经验或理论。
*   **系统 (System)**: 相互作用的多元素复合体。具备集合性、相关性、整体性、层次性、涌现性。
*   **管理信息系统 (MIS)**:
    *   **Gordon B. Davis**: 利用计算机软硬件、手工作业、分析/计划/控制/决策模型及数据库的人-机系统。
    *   **薛华成**: 以人为主导，利用计算机软硬件、网络通信设备等，进行信息的收集、传输、加工、存储、更新和维护，支持企业战略竞优、提高效益和效率，支持高层决策、中层控制、基层运作的集成化人-机系统。

### 2. MIS 的功能与结构
*   **基本功能**: 信息的收集、存储、处理、传递和使用。
*   **组成元素**: 信息源、信息处理器、信息用户、信息系统管理者。
*   **功能结构层次**:
    1.  **业务层 (TPS - Transaction Processing System)**: 支持日常操作，输入原始单据，输出汇总报表。特点是标准化、简单运算、基层使用。是其他系统的基础。
    2.  **知识层**:
        *   **KWS (Knowledge Work System)**: 辅助创造新信息（如工程师、医生）。
        *   **OAS (Office Automation System)**: 帮助处理数据、整理和传递信息（如文字处理、邮件、日历）。
    3.  **管理层**:
        *   **MIS (狭义)**: 支持中层管理，提供结构化报告（周/月/年报），数据主要来自 TPS，侧重内部信息。
        *   **DSS (Decision Support System)**: 支持半结构化决策，利用模型分析数据，人机对话，可使用外部信息。
    4.  **战略层 (ESS - Executive Support System)**: 支持高层战略，监控执行、跟踪竞争、预测趋势。强调非结构化决策，界面友好，整合内外数据。

### 3. MIS 的发展：诺兰模型 (Nolan Model)
信息系统发展分为6个阶段：
1.  **初装**: 购置第一台计算机，单机处理。
2.  **扩展**: 应用扩散到多数部门，效率提高但出现重复。
3.  **控制**: 统筹规划，解决重复和低效问题。
4.  **集成**: 分散系统变为一体化系统，联机处理。
5.  **数据管理**: 统一数据管理体系，真正统一规划应用。
6.  **信息管理 (成熟)**: 内外数据资源充分利用，满足各层次需求。

## 第二章：管理信息系统的开发方法

### 1. 信息系统生命周期
五个阶段：
1.  **可行性研究**: 必要性、可行性（技术/经济/营运）、候选方案。
2.  **系统分析**: 解决“做什么”，提出逻辑模型。
3.  **系统设计**: 解决“怎么做”，建立物理模型。
4.  **系统实施**: 编程、测试、转换、培训。
5.  **系统维护**: 运行中的完善、适应、更正和预防。

### 2. 主要开发方法对比

| 方法                | 核心思想                                                     | 优点                                             | 缺点                                                 | 适用范围                                |
| :------------------ | :----------------------------------------------------------- | :----------------------------------------------- | :--------------------------------------------------- | :-------------------------------------- |
| **结构化开发法**    | 自顶向下、模块化、用户至上、先逻辑后物理。严格区分阶段。     | 整体性强、全局优化、规范标准、易于纠正错误。     | 周期长、重功能轻数据结构、可维护性较差。             | 大型、复杂、需求明确且稳定的系统。      |
| **原型法**          | 快速构建初始原型，用户试用反馈，反复修改完善。               | 沟通直观、贴近实际、周期短、用户满意度高。       | 缺乏全面认识、分析粗略、对工具要求高。               | 小型系统、需求模糊系统、DSS、局部模块。 |
| **面向对象法 (OO)** | 以对象为基础，封装、继承、多态。直接映射客观世界。           | 重用性高、易维护、缩短周期、直接转换现实到软件。 | 需软件环境支持、难从科学管理角度优化、初学者难上手。 | 各类系统，特别是复杂交互系统。          |
| **CASE**            | 计算机辅助软件工程，自动化/半自动化工具支持除调查外的所有步骤。 | 高度自动化、规范性好、效率高、自动生成文档。     | 缺乏全面完善的工具集。                               | 配合上述三种方法使用。                  |

### 3. 开发方式
自行开发、委托开发、合作开发、购买现成软件包。

## 第三章：管理信息系统战略规划

### 1. 战略规划概述
*   **定义**: 在企业远景和业务规划基础上，形成信息系统远景和构架。
*   **作用**: 合理分配资源、找出问题、指导开发、获取竞争优势。
*   **内容**: 目标/约束/结构、组织状况、业务流程现状、技术预测。

### 2. 常用规划方法

#### A. 企业系统规划法 (BSP - Business System Planning)
*   **核心**: 从企业目标入手，自上而下识别目标、业务过程、数据；自下而上设计系统。
*   **关键步骤**:
    1.  **定义业务过程**: 逻辑相关的决策或活动集合。
    2.  **确定数据类**: 支持业务过程的数据集合。
    3.  **U/C 矩阵分析**:
        *   行：功能；列：数据类。
        *   C (Create): 产生数据；U (Use): 使用数据。
        *   **检验**: 完备性（每个数据有C和U）、一致性（每个数据只有一个C）、无冗余（无空行空列）。
        *   **求解**: 调整列使C靠近对角线，划分子系统。
*   **优点**: 明确总体结构、统一数据规划、保证信息一致性。

#### B. 关键成功因素法 (CSF - Critical Success Factors)
*   **核心**: 找出决定企业成功的关键因素，围绕其确定系统需求。
*   **步骤**: 了解战略目标 -> 识别成功因素 -> 确定关键因素 -> 明确性能指标。
*   **优点**: 针对性强、见效快。

#### C. 战略目标集转化法 (SST - Strategy Set Transformation)
*   **核心**: 将组织的战略目标（使命、目标、战略变量）转化为 MIS 的战略目标。

#### D. CSB 综合法
结合 CSF 确定目标，SST 补充完善，BSP 校核并确定结构。

## 第四章：系统分析

### 1. 基本概念
*   **任务**: 解决“做什么”，提出**逻辑模型**。
*   **成果**: 系统说明书。
*   **步骤**: 初步调查 -> 可行性研究 -> 详细调查 -> 新系统逻辑方案。

### 2. 详细调查与分析工具
*   **业务流程图 (TFD)**: 描述具体业务处理过程，符号少，易理解。
*   **数据流图 (DFD)**: 信息运动的抽象，逻辑模型的主要形式。
    *   **要素**: 外部实体、数据流、处理加工、数据存储。
    *   **绘制**: 顶层图（环境图）-> 中层图（分解加工）-> 底层图（基本加工）。
*   **数据词典 (DD)**: 对 DFD 中所有成分（数据流、数据元素、存储、加工、外部项）的定义和说明。
    *   **数据元素**: 最小单位。
    *   **加工描述工具**:
        *   **结构化语言**: IF-THEN-ELSE 规范化描述。
        *   **决策树**: 图形化，适合多策略、多条件。
        *   **决策表**: 表格化，适合条件组合复杂的情况。

### 3. 新系统逻辑方案
*   包括：项目概述、需求说明、现行系统状况、新系统目标/功能/逻辑模型（组织结构图、业务流程图、DFD、DD等）、实施计划。

## 第五章：系统设计

### 1. 基本概念
*   **任务**: 解决“怎么做”，将逻辑模型转换为**物理模型**。
*   **原则**: 自顶向下、模块化、高内聚低耦合。

### 2. 结构化设计 (SD)
*   **模块独立性**:
    *   **耦合 (Coupling)**: 模块间联系。理想：**数据耦合**；避免：控制耦合；坚决避免：内容耦合。
    *   **内聚 (Cohesion)**: 模块内联系。最强：**功能内聚**；最弱：偶然内聚。
*   **从 DFD 导出模块结构图**:
    *   **变换型**: 输入-变换-输出。设计主模块、输入模块、变换模块、输出模块。
    *   **事务型**: 事务中心分流。设计接收模块、分析模块、调度模块、动作模块。

### 3. 详细设计内容
*   **代码设计**:
    *   作用：标识、分类、排序。
    *   类型：顺序码、层次码、特征组合码、助记码。
    *   **校验码**:加权取余法生成，用于检错。
*   **数据库设计**:
    1.  需求分析
    2.  **概念设计**: E-R 图（实体、属性、联系）。
    3.  **逻辑设计**: E-R 图转关系模式（二维表）。
    4.  物理设计: 存储结构、存取路径。
*   **输入/输出设计**:
    *   输出：用户判断系统价值的依据。注重格式、介质、设备。
    *   输入：保证正确性、及时性。原则：简单、早检验、少转换。

### 4. 成果
*   **系统设计说明书**: 包含模块结构图、代码表、输入输出设计、数据库设计、网络/安全设计、实施计划。

## 第六章：系统实施

### 1. 主要工作
*   物理系统实施（硬件/网络安装）。
*   软件开发（编码）。
*   数据准备。
*   系统测试。
*   人员培训。
*   系统转换。
*   文档管理。

### 2. 系统测试
*   **目的**: 发现错误。
*   **方法**:
    *   **黑盒法 (功能测试)**: 不考虑内部结构，测试输入输出是否符合功能需求。
    *   **白盒法 (结构测试)**: 考虑内部逻辑，覆盖所有路径、判断真假、循环边界。

### 3. 系统转换方式
1.  **直接转换**: 新替旧。简单省钱，风险大。
2.  **试运行 (平行运行变种)**: 老系统照常，新系统部分运行，满意后全面切换。
3.  **逐步转换**: 新系统一部分一部分替代老系统。避免风险，但接口复杂。

### 4. 文档管理
*   系统分析报告、设计报告、实施说明、程序资料（源码、流程图）、操作说明。

---

## 第七章：系统的运行维护与升级

### 1. 系统维护
*   **目的**: 保证系统正常可靠运行，适应环境变化。
*   **类型**:
    1.  **完善性维护**: 提高效率、易用性、安全性（占比最大）。
    2.  **适应性维护**: 适应硬件、OS、环境变化。
    3.  **更正性维护**: 修复错误。
    4.  **预防性维护**: 为未来变化做准备。
*   **内容**: 程序维护、数据文件维护、代码维护、机器设备维护。

### 2. 系统升级 vs 维护
*   **升级**: 计划性强、目标明确、里程碑式、质的飞跃（如版本迭代）。
*   **维护**: 应急性、日常性、量的积累。

### 3. 系统审计
*   **内容**:
    *   内部控制制度审计。
    *   应用程序审计（合规性、逻辑正确性）。
    *   数据文件审计（真实性、完整性、安全性）。
    *   处理系统综合审计。
    *   系统开发审计（过程规范性）。

### 4. 系统评价
*   **指标**:
    *   **质量**: 用户满意度、规范性、先进性、安全性。
    *   **运行**: 目标完成情况、实用性、稳定性。
    *   **性能**: 响应时间、处理速度、可扩充性、可维护性。
    *   **效益**:
        *   直接经济效益（投资、运行费、节约额）。
        *   间接经济效益（管理变革、企业形象、员工素质、协作精神）。

## 第八章：面向对象的开发方法

### 1. 基本思想
*   按人类思维方式分析问题。
*   **核心元素**: 对象 (Object)。
*   **特征**:
    *   **封装**: 数据和操作打包，隐藏内部细节。
    *   **继承**: 子类共享父类属性和方法，支持重用。
    *   **多态**: 同一消息在不同对象上产生不同行为。

### 2. 基本概念
*   **对象**: 客观事物的抽象，包含状态（属性）和行为（方法）。
*   **类**: 相似对象的集合，模板。
*   **消息**: 对象间交互的手段（请求服务）。
*   **方法**: 对象执行的操作算法。

### 3. 开发过程
1.  **面向对象分析 (OOA)**:
    *   建立功能模型 (DFD)。
    *   建立对象模型 (类、对象、关联、属性)。
    *   建立动态模型 (状态、交互、时序)。
    *   定义服务。
2.  **面向对象设计 (OOD)**:
    *   问题域子系统设计。
    *   人机交互子系统设计。
    *   任务管理子系统设计。
    *   数据管理子系统设计。
3.  **面向对象实现 (OOP)**: 编码、测试、调试。

### 4. 统一建模语言 (UML)
*   **作用**: 标准化可视化建模语言，促进沟通。
*   **基本块**: 事物、联系、图形。
*   **联系类型**: 依赖、关联、泛化 (继承)、实现。
*   **主要视图/图**:
    *   **类图**: 静态结构，核心。
    *   **对象图**: 类的实例。
    *   **用例图**: 用户视角的功能需求。
    *   **状态图**: 对象生命周期内的状态变化。
    *   **顺序图 (时序图)**: 对象间基于时间的消息交互。
    *   **活动图**: 操作流程。
    *   **构件图/配置图**: 物理架构和部署。
