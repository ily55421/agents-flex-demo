## 第 1 章：了解 SQL

### 核心论点
- 本章试图回答：什么是数据库？什么是 SQL？为什么需要学习它们？
- 核心观点：数据库是以有组织方式存储数据的容器，SQL 是专门用来与数据库通信的简单而强大的语言。

### 关键概念/事件
- **数据库（database）**：保存有组织数据的容器，通常是一个文件或一组文件
- **表（table）**：某种特定类型数据的结构化清单，是数据库中存储数据的基本单位
- **列与数据类型**：列是表中的字段，数据类型定义列可存储的数据种类，限制数据格式
- **主键（primary key）**：唯一标识表中每一行的列或列组合，确保数据可被准确定位
- **SQL**：结构化查询语言，由少量描述性英语单词构成，用于读写数据库数据

### 逻辑推演/叙事脉络
本章从日常使用数据库的场景切入，澄清"数据库"与"数据库管理系统（DBMS）"的常见混淆。随后依次定义表、列、行、主键等基础术语，强调主键的唯一性与非空约束。最后介绍 SQL 的语言特性：跨平台、易学、功能强大，并指出不同 DBMS 的 SQL 实现存在差异，本书聚焦 MySQL。

### 经典金句/数据
> "数据库（database）保存有组织的数据的容器（通常是一个文件或一组文件）。"

> "SQL 不是某个特定数据库供应商专有的语言。几乎所有重要的 DBMS 都支持 SQL，所以，学习此语言使你几乎能与所有数据库打交道。"

## 第 2 章：MySQL 简介

### 核心论点
- 本章试图回答：MySQL 是什么？它有哪些优势？如何使用它？
- 核心观点：MySQL 是开源、高性能、可信赖且易用的客户机—服务器型数据库管理系统。

### 关键概念/事件
- **客户机—服务器架构**：服务器处理数据请求，客户机提交命令并接收结果，二者可部署于同一或不同机器
- **MySQL 版本演进**：版本 4 引入 InnoDB 引擎与事务支持；4.1 增加子查询；5 新增存储过程、触发器、游标、视图
- **mysql 命令行实用程序**：核心工具，无图形界面，用于快速执行脚本与测试语句
- **MySQL Administrator**：图形化管理工具，用于服务器配置、用户权限管理等
- **MySQL Query Browser**：图形化查询工具，支持语句编写、执行与结果查看

### 逻辑推演/叙事脉络
本章首先阐述 MySQL 的四大优势（成本、性能、可信赖、简单），然后解释客户机—服务器工作模型，说明用户如何通过客户机与服务器交互。接着介绍三个核心工具的功能与获取方式，强调即使使用图形工具也应熟悉命令行实用程序，因其始终可用且便于脚本执行。

### 经典金句/数据
> "熟悉 mysql 命令行实用程序 即使你选择使用后面描述的某个图形工具，也应该保证熟悉 mysql 命令行实用程序，因为它是你可以安全地依靠的一个总是会被给出的客户机。"

## 第 3 章：使用 MySQL

### 核心论点
- 本章试图回答：如何连接、登录 MySQL？如何选择数据库？如何查看数据库结构？
- 核心观点：使用 MySQL 前需正确连接并选择目标数据库，通过 SHOW 命令可获取元数据信息。

### 关键概念/事件
- **连接参数**：主机名、端口、用户名、口令是建立连接的必要信息
- **USE 语句**：选择当前操作的数据库，执行数据库操作前必须先执行
- **SHOW DATABASES**：列出服务器上所有可用数据库
- **SHOW TABLES**：列出当前数据库中所有表
- **SHOW COLUMNS / DESCRIBE**：显示表结构，包括字段名、类型、是否允许 NULL、键信息等

### 逻辑推演/叙事脉络
本章按操作流程展开：首先说明连接 MySQL 所需的四项参数；接着介绍使用 USE 语句选择数据库的必要性；然后通过一系列 SHOW 命令演示如何探索数据库和表的结构；最后指出这些命令也是图形工具底层调用的基础，强调元数据查询的重要性。

### 经典金句/数据
> "记住，必须先使用 USE 打开数据库，才能读取其中的数据。"

## 第 4 章：检索数据

### 核心论点
- 本章试图回答：如何使用 SELECT 语句从表中检索数据？
- 核心观点：SELECT 语句通过指定列名和表名，可灵活检索单列、多列或全部列数据。

### 关键概念/事件
- **SELECT 基本语法**：`SELECT 列名 FROM 表名;` 是数据检索的核心结构
- **检索单列/多列**：列名用逗号分隔，最后一个列名后不加逗号
- **通配符 \***：检索所有列，但不推荐滥用，可能降低性能
- **DISTINCT 关键字**：去除重复值，返回唯一结果集
- **LIMIT 子句**：限制返回行数，支持分页（`LIMIT 起始行，行数`）

### 逻辑推演/叙事脉络
本章从最简单的单列检索开始，逐步扩展到多列、全部列的检索方式。随后引入 DISTINCT 解决重复值问题，再介绍 LIMIT 实现结果集截断与分页。最后说明完全限定表名的使用场景，为后续多表操作铺垫。

### 经典金句/数据
> "使用通配符 一般，除非你确实需要表中的每个列，否则最好别使用*通配符。虽然使用通配符可能会使你自己省事，不用明确列出所需列，但检索不需要的列通常会降低检索和应用程序的性能。"

## 第 5 章：排序检索数据

### 核心论点
- 本章试图回答：如何对检索结果进行排序？
- 核心观点：使用 ORDER BY 子句可按单列或多列、升序或降序对结果集排序。

### 关键概念/事件
- **ORDER BY 子句**：指定排序依据的列，必须位于 FROM 之后、LIMIT 之前
- **多列排序**：按指定列顺序依次排序，仅当前列值相同时才比较下一列
- **ASC/DESC 关键字**：控制排序方向，DESC 表示降序，ASC 为默认升序
- **排序与限制结合**：`ORDER BY + LIMIT` 可快速获取最大/最小值

### 逻辑推演/叙事脉络
本章首先指出未排序数据的顺序不可依赖，引出排序的必要性。然后演示 ORDER BY 的基本用法，扩展到多列排序的逻辑规则，再介绍 DESC/ASC 控制方向。最后结合 LIMIT 展示如何高效获取极值，强调子句顺序的语法约束。

### 经典金句/数据
> "关系数据库设计理论认为，如果不明确规定排序顺序，则不应该假定检索出的数据的顺序有意义。"

## 第 6 章：过滤数据

### 核心论点
- 本章试图回答：如何筛选满足特定条件的数据行？
- 核心观点：WHERE 子句配合操作符可实现精确、范围、空值等多种条件过滤。

### 关键概念/事件
- **WHERE 子句**：位于 FROM 之后，用于指定行级过滤条件
- **比较操作符**：`=, <>, !=, <, <=, >, >=` 用于值匹配与比较
- **BETWEEN 操作符**：检查值是否在指定范围内（含边界）
- **IS NULL**：专门用于检查空值，NULL 表示"无值"而非空字符串
- **字符串引号规则**：字符串值需用单引号限定，数值无需引号

### 逻辑推演/叙事脉络
本章从单一条件过滤入手，系统介绍各类比较操作符的用法。随后讲解 BETWEEN 实现范围查询，再强调 NULL 的特殊性及 IS NULL 的使用。最后提醒字符串与数值的引号差异，以及过滤应在数据库层完成以提升性能。

### 经典金句/数据
> "NULL 无值（no value），它与字段包含 0、空字符串或仅仅包含空格不同。"

## 第 7 章：数据过滤

### 核心论点
- 本章试图回答：如何组合多个过滤条件？如何使用高级操作符？
- 核心观点：AND/OR 逻辑组合、IN 列表匹配、NOT 取反可构建复杂过滤逻辑。

### 关键概念/事件
- **AND 操作符**：所有条件必须同时满足
- **OR 操作符**：任一条件满足即可
- **计算次序与括号**：AND 优先级高于 OR，需用括号明确逻辑分组
- **IN 操作符**：匹配指定值列表，语法更清晰且执行效率通常优于多个 OR
- **NOT 操作符**：否定其后条件，常与 IN、BETWEEN 等联合使用

### 逻辑推演/叙事脉络
本章先分别讲解 AND 与 OR 的基本用法，再通过实例揭示操作符优先级问题，强调括号的重要性。随后介绍 IN 操作符的语法优势与性能特点，最后说明 NOT 的取反功能及其在复杂条件中的价值。

### 经典金句/数据
> "在 WHERE 子句中使用圆括号 任何时候使用具有 AND 和 OR 操作符的 WHERE 子句，都应该使用圆括号明确地分组操作符。不要过分依赖默认计算次序，即使它确实是你想要的东西也是如此。"

## 第 8 章：用通配符进行过滤

### 核心论点
- 本章试图回答：如何匹配未知或部分已知的文本内容？
- 核心观点：LIKE 操作符配合通配符%和_可实现灵活的模糊匹配。

### 关键概念/事件
- **通配符（wildcard）**：特殊字符，用于匹配值的一部分
- **% 通配符**：匹配任意字符出现任意次数（包括 0 次）
- **_ 通配符**：仅匹配单个字符
- **LIKE 操作符**：指示使用通配符模式而非精确匹配
- **使用技巧**：避免过度使用、慎用开头通配符、注意尾空格影响

### 逻辑推演/叙事脉络
本章首先说明精确匹配的局限性，引出通配符搜索的必要性。然后分别详解%和_的匹配规则与示例，强调%可匹配 0 字符而_必须匹配 1 字符。最后给出三条实用技巧，提醒通配符搜索的性能成本与注意事项。

### 经典金句/数据
> "注意尾空格 尾空格可能会干扰通配符匹配。例如，在保存词 anvil 时，如果它后面有一个或多个空格，则子句 WHERE prod_name LIKE'%anvil'将不会匹配它们。"

## 第 9 章：用正则表达式进行搜索

### 核心论点
- 本章试图回答：如何实现更复杂、更智能的文本匹配？
- 核心观点：MySQL 支持正则表达式子集，通过 REGEXP 可实现高级模式匹配。

### 关键概念/事件
- **REGEXP 操作符**：替代 LIKE，启用正则表达式匹配
- **基本字符匹配**：`.`匹配任意单字符
- **字符集合 []**：匹配括号内任意一个字符，`[^]`表示否定
- **范围匹配**：`[0-9]`、`[a-z]`等简化字符集合定义
- **重复元字符**：`*`（0+ 次）、`+`（1+ 次）、`?`（0 或 1 次）、`{n}`（精确 n 次）
- **定位符 ^/$**：匹配字符串开始/结束位置

### 逻辑推演/叙事脉络
本章先对比 LIKE 与 REGEXP 的核心差异（子串匹配 vs 全串匹配），然后系统介绍正则表达式基础语法：基本匹配、字符集合、范围、转义、重复、定位符。通过实例展示各语法的应用场景，最后提醒正则表达式在 MySQL 中为子集实现。

### 经典金句/数据
> "LIKE 与 REGEXP 在 LIKE 和 REGEXP 之间有一个重要的差别。...LIKE 匹配整个列。如果被匹配的文本在列值中出现，LIKE 将不会找到它...而 REGEXP 在列值内进行匹配，如果被匹配的文本在列值中出现，REGEXP 将会找到它。"

## 第 10 章：创建计算字段

### 核心论点
- 本章试图回答：如何在检索时动态生成新字段？
- 核心观点：计算字段在 SELECT 语句中运行时创建，可用于拼接、算术等操作。

### 关键概念/事件
- **计算字段**：非物理存储，由查询时表达式动态生成
- **拼接字段**：使用 Concat() 函数合并多个列或字符串
- **别名（AS）**：为计算字段命名，便于应用程序引用
- **算术计算**：支持`+ - * /`操作符，可组合列值进行运算
- **空格处理函数**：LTrim()/RTrim()/Trim() 用于清理字符串

### 逻辑推演/叙事脉络
本章首先列举应用程序中常见的数据格式化需求，引出计算字段的必要性。然后以供应商报表为例，演示 Concat() 拼接列值，并强调使用别名的重要性。最后介绍算术计算的基本操作符，指出计算应在数据库层完成以提升效率。

### 经典金句/数据
> "客户机与服务器的格式 可在 SQL 语句内完成的许多转换和格式化工作都可以直接在客户机应用程序内完成。但一般来说，在数据库服务器上完成这些操作比在客户机中完成要快得多，因为 DBMS 是设计来快速有效地完成这种处理的。"

## 第 11 章：使用数据处理函数

### 核心论点
- 本章试图回答：如何利用内置函数处理文本、日期、数值数据？
- 核心观点：函数提供强大的数据转换能力，但需注意可移植性与使用场景。

- **函数可移植性**：不同 DBMS 函数支持差异大，需谨慎使用

### 逻辑推演/叙事脉络

## 第 12 章：汇总数据

### 核心论点
- 本章试图回答：如何对数据进行统计汇总而不检索全部明细？
- 核心观点：聚集函数可在数据库层高效完成计数、求和、平均、极值等统计操作。

### 关键概念/事件
- **聚集函数**：运行在行组上，返回单个汇总值的函数
- **AVG()**：计算数值列平均值，忽略 NULL 值
- **COUNT()**：`COUNT(*)`统计所有行，`COUNT(列)`统计非空值
- **MAX()/MIN()**：返回列中最大/最小值，支持文本与日期类型
- **SUM()**：计算数值列总和，可结合表达式使用
- **DISTINCT 参数**：仅对唯一值进行聚集计算

### 逻辑推演/叙事脉络
本章首先说明汇总数据的应用场景与性能优势，然后逐一介绍五个核心聚集函数的用法与注意事项。特别强调 NULL 值的处理规则、DISTINCT 参数的适用场景，以及多函数组合使用的灵活性。最后提醒别名命名应避免与表列冲突。

### 经典金句/数据
> "聚集函数（aggregate function）运行在行组上，计算和返回单个值的函数。"

## 第 13 章：分组数据

### 核心论点
- 本章试图回答：如何对数据分组后进行聚合计算？
- 核心观点：GROUP BY 实现数据分组，HAVING 实现组级过滤，二者配合完成复杂汇总。

### 关键概念/事件
- **GROUP BY 子句**：按指定列分组，每组独立执行聚集计算
- **分组规则**：非聚集列必须出现在 GROUP BY 中；支持多列嵌套分组
- **HAVING 子句**：过滤分组结果，与 WHERE 区别在于作用于组而非行
- **GROUP BY 与 ORDER BY**：分组不保证输出顺序，需显式指定 ORDER BY
- **WITH ROLLUP**：为每个分组添加汇总行

### 逻辑推演/叙事脉络
本章从"统计每个供应商产品数"的需求引出分组概念，详解 GROUP BY 的语法与六条重要规则。随后通过对比 WHERE 与 HAVING，阐明行级过滤与组级过滤的本质区别。最后强调分组与排序的独立性，并介绍 SELECT 子句的标准执行顺序。

### 经典金句/数据
> "HAVING 和 WHERE 的差别 WHERE 在数据分组前进行过滤，HAVING 在数据分组后进行过滤。这是一个重要的区别，WHERE 排除的行不包括在分组中。"

## 第 14 章：使用子查询

### 核心论点
- 本章试图回答：如何将一个查询的结果作为另一个查询的条件或数据源？
- 核心观点：子查询支持嵌套过滤与计算字段，但需注意性能与列匹配规则。

### 关键概念/事件
- **子查询（subquery）**：嵌套在其他查询中的 SELECT 语句
- **过滤型子查询**：用于 WHERE 子句，常与 IN 操作符配合
- **计算字段型子查询**：在 SELECT 列表中返回标量值
- **相关子查询**：子查询引用外部查询的列，需使用完全限定名避免歧义
- **执行顺序**：子查询从内向外处理，结果传递给外层查询

### 逻辑推演/叙事脉络
本章以"查找订购某产品的客户"为例，分步演示如何用三个独立查询解决问题，再将其合并为嵌套子查询。随后介绍子查询作为计算字段的用法，强调相关子查询中列名限定的重要性。最后提醒子查询虽灵活但可能影响性能，建议逐步构建与测试。

### 经典金句/数据
> "在 SELECT 语句中，子查询总是从内向外处理。"

## 第 15 章：联结表

### 核心论点
- 本章试图回答：如何从多个关联表中检索整合数据？
- 核心观点：通过指定联结条件，可将分散在多个表中的数据逻辑关联并一次性检索。

### 关键概念/事件
- **关系表设计**：数据分解到多个表，通过主键 - 外键关联，避免冗余
- **外键（foreign key）**：引用其他表主键的列，定义表间关系
- **内部联结（INNER JOIN）**：基于相等条件匹配两表行，返回匹配结果

## 附录 D：MySQL 数据类型

### 核心论点
- 本章试图回答：MySQL 支持哪些数据类型？如何选择合适类型？
- 核心观点：数据类型决定存储格式、取值范围与操作行为，选型影响功能与性能。

### 关键概念/事件
- **串类型**：CHAR（定长）/VARCHAR（变长）/TEXT 系列，注意引号与数值陷阱
- **数值类型**：INT/BIGINT/DECIMAL 等，区分有符号/无符号，货币推荐 DECIMAL(8,2)
- **日期时间**：DATE / TIME / DATETIME / TIMESTAMP / YEAR，统一使用 yyyy-mm-dd 格式
- **二进制类型**：BLOB 系列存储任意二进制数据
- **选型原则**：数值计算用数值类型，标识/编码用串类型

### 逻辑推演/叙事脉络
本章首先说明数据类型的三大作用（约束、存储效率、排序行为），然后分类详解串、数值、日期、二进制四类常用类型。每类均列出具体类型、取值范围、使用注意。最后通过"邮政编码存数值会丢前导 0"等实例强调选型对业务逻辑的影响。

### 经典金句/数据
