# 《MyBatis 官方参考文档》章节总结

## 目录说明
本总结基于提供的《MyBatis 3.5.4 官方文档》与《MyBatis 3.5.2 参考文档》融合整理。两份文档核心架构与内容高度一致，代表了 MyBatis 3.x 时代的官方标准规范。章节划分严格遵循官方文档的逻辑目录，分为：简介、入门、配置、XML 映射文件、Java API 五个核心部分。

---

## 第1章：简介
### 核心论点
本章主要试图回答“什么是 MyBatis 以及它的核心价值是什么”。作者最核心的观点是：MyBatis 是一款优秀的持久层框架，它通过消除繁琐的 JDBC 模板代码，让开发者能够专注于 SQL 本身与业务逻辑。

### 关键概念/事件
- **持久层框架**：MyBatis 的定位，用于替代原生 JDBC、Hibernate 等方案，提供对 SQL 的绝对控制权。
- **定制化 SQL 与高级映射**：支持存储过程以及将原生类型、接口和 Java POJO 映射为数据库记录。
- **双轨配置机制**：支持使用简单的 XML 或 Java 注解来进行框架配置和 SQL 映射。

### 逻辑推演/叙事脉络
本章作为全书导论，开门见山地给出了 MyBatis 的官方定义，直接击中传统 JDBC 开发中“代码冗余、手动设置参数、手动解析结果集”的痛点。随后，作者简述了 MyBatis 的两种配置驱动方式（XML 与注解），并提供了多语言文档的获取途径与开源社区的贡献指引，为后续深入技术细节奠定认知基础。

### 经典金句/数据
> “MyBatis 避免了几乎所有的 JDBC 代码和手动设置参数以及获取结果集。” (p.5)

## 第2章：入门
### 核心论点
本章试图解决“如何从零启动 MyBatis 并理解其核心组件的生命周期”的问题。核心观点是：MyBatis 的应用以 `SqlSessionFactory` 为核心，而正确管理 `SqlSession` 和 Mapper 的作用域是避免并发灾难的前提。

### 关键概念/事件
- **SqlSessionFactory**：应用的核心工厂，负责创建 SqlSession，最佳实践是应用作用域（单例）。
- **SqlSession**：执行 SQL 命令的会话接口，非线程安全，必须限制在请求或方法作用域内并及时关闭。
- **Mapper 接口**：替代传统字符串硬编码调用 SQL 的方式，提供类型安全、IDE 友好的方法调用。
- **作用域（Scope）**：明确界定 Builder（方法级）、Factory（应用级）、Session（请求/方法级）的生命周期。

### 逻辑推演/叙事脉络
本章按照开发者接触框架的自然顺序展开：首先通过 Maven 引入依赖；接着演示如何通过 XML 或纯 Java 代码构建 `SqlSessionFactory`；随后对比了旧版“字符串字面值调用”与新版“Mapper 接口绑定”的优劣，强烈推荐后者。最后，作者严肃地探讨了各核心组件的生命周期与作用域，给出了 `try-with-resources` 的标准资源关闭模式，防止数据库连接泄漏。

### 经典金句/数据
> “每个基于 MyBatis 的应用都是以一个 SqlSessionFactory 的实例为核心的。” (p.7)
> “每个线程都应该有它自己的 SqlSession 实例。SqlSession 的实例不是线程安全的，因此是不能被共享的。” (p.12)

## 第3章：配置
### 核心论点
本章旨在解答“如何通过全局配置深度定制 MyBatis 的运行时行为以适应复杂的企业级环境”。核心观点是：MyBatis 提供了从属性替换、类型转换到多环境隔离、插件拦截的全方位配置体系，使得框架能无缝融入各类架构。

### 关键概念/事件
- **settings（全局设置）**：控制缓存、延迟加载、驼峰命名自动映射（`mapUnderscoreToCamelCase`）等核心运行时行为。
- **typeHandlers（类型处理器）**：架起 JDBC 类型与 Java 类型之间的桥梁，支持自定义转换（如 JSR-310 时间 API）。
- **environments（环境配置）**：支持配置多套数据源与事务管理器（JDBC/MANAGED），但每个 Factory 只能选定一种环境。
- **plugins（插件拦截器）**：允许在 Executor、StatementHandler 等核心接口的方法执行前后进行 AOP 拦截。

### 逻辑推演/叙事脉络
本章以 `mybatis-config.xml` 的顶层 XML 结构为骨架，逐一拆解配置标签。从最基础的 `properties` 外部化配置讲起，深入到影响性能的 `settings` 和解决类型映射的 `typeHandlers`。随后，作者探讨了对象工厂、插件机制以及多环境数据源配置，最后以如何加载 `mappers` 映射文件收尾。整个推演过程由浅入深，从静态属性过渡到动态的运行时干预机制。

### 经典金句/数据
> “SqlSessionFactory 一旦被创建就应该在应用的运行期间一直存在，没有任何理由丢弃它或重新创建另一个实例...多次重建 SqlSessionFactory 被视为一种代码‘坏味道’。” (p.12)

## 第4章：XML 映射文件
### 核心论点
本章试图解决“如何利用 XML 优雅地处理复杂 SQL 拼接与多表关联结果集映射”的问题。核心观点是：MyBatis 的真正魔力在于其强大的动态 SQL 语言与 ResultMap 机制，它们能将数千行的 JDBC 结果集提取代码简化为几行声明式配置。

### 关键概念/事件
- **ResultMap（结果映射）**：MyBatis 最强大的特性，支持一对一（`association`）、一对多（`collection`）及鉴别器（`discriminator`）映射，彻底解决多表 JOIN 后的对象组装问题。
- **动态 SQL**：基于 OGNL 表达式的标签库（`if`, `choose`, `where`, `set`, `foreach`），智能处理 SQL 拼接中的空格、逗号及 AND/OR 逻辑。
- **缓存机制**：分为基于 Session 的一级本地缓存和基于 Namespace 的二级全局缓存，支持 LRU/FIFO 等淘汰策略。
- **selectKey**：用于处理不支持自动生成主键的数据库的主键回填问题。

### 逻辑推演/叙事脉络
本章是全书的重中之重。作者首先介绍基础的 CRUD 标签及参数占位符（`#{}` 与 `${}` 的安全区别）。接着，花费大量篇幅剖析 `ResultMap`，通过“博客-作者-文章-评论”的复杂嵌套案例，演示如何化解 N+1 查询问题与多表结果集映射。随后，引入动态 SQL 标签，对比传统 JDBC 拼接字符串的痛苦，展示 MyBatis 的智能拼接能力。最后补充了缓存配置与多数据库厂商（`databaseId`）的兼容方案。

### 经典金句/数据
> “ResultMap 的设计思想是，对简单的语句做到零配置，对于复杂一点的语句，只需要描述语句之间的关系就行了。” (p.47)
> “利用动态 SQL，可以彻底摆脱这种痛苦（指 JDBC 拼接 SQL 时的空格与逗号问题）。” (p.67)

## 第5章：Java API
### 核心论点
本章旨在解答“在掌握 XML 映射后，如何通过 Java 代码和注解高效、安全地驱动 MyBatis”。核心观点是：虽然 XML 适合复杂映射，但结合 Mapper 接口、Java 注解以及 `SQL` 构建器类，可以在代码层面实现极具表现力且类型安全的持久层操作。

### 关键概念/事件
- **SqlSession API**：提供 `selectOne`、`selectList`、`Cursor`（流式查询）、`ResultHandler` 及批量更新（`ExecutorType.BATCH`）等底层执行方法。
- **Mapper 接口绑定**：无需实现类，MyBatis 通过动态代理将接口方法与 XML/注解中的 SQL ID 自动绑定。
- **注解映射**：提供 `@Select`、`@Results` 等注解替代简单 XML，但受限于 Java 注解表达能力，复杂嵌套仍需依赖 XML。
- **SQL 语句构建器（SQL 类）**：通过匿名内部类和链式调用，在 Java 代码中优雅地构建动态 SQL，避免字符串拼接噩梦。
- **日志工厂**：内置委派机制，自动适配 SLF4J、Log4j、JDK Logging 等主流日志框架。

### 逻辑推演/叙事脉络
本章从底层的 `SqlSession` 方法签名切入，解释事务控制与游标遍历的高级用法。随后，为了消除字符串调用的不安全性，引出 Mapper 接口绑定机制。针对“纯注解派”与“XML 派”的争议，作者客观分析了 Java 注解的局限性，并给出了 `@SelectProvider` 结合 `SQL` 工具类的折中方案，完美解决了在 Java 代码中编写动态 SQL 的痛点。最后，简要说明了如何配置 MyBatis 的底层日志输出以辅助调试。

### 经典金句/数据
> “映射器接口不需要去实现任何接口或继承自任何类。只要方法签名可以被用来唯一识别对应的映射语句就可以了。” (p.88)
> “Java程序员面对的最痛苦的事情之一就是在 Java 代码中嵌入 SQL 语句... MyBatis 3 提供了方便的工具类（SQL类）来帮助解决此问题。” (p.94)
