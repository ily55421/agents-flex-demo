## 第2章：JVM
### 核心论点
- JVM 是 Java 跨平台的核心，理解其内存模型、垃圾回收机制及类加载机制是性能调优和解决线上问题的基础。
- 核心观点：JVM 通过分代收集算法和不同的垃圾收集器平衡吞吐量与停顿时间，通过双亲委派模型保证类加载的安全性。

### 关键概念/事件
- **运行时数据区**：分为线程私有（程序计数器、虚拟机栈、本地方法栈）和线程共享（堆、方法区/元空间）。
- **垃圾回收算法**：包括标记-清除、复制算法、标记-整理及分代收集算法。
- **垃圾收集器**：Serial、ParNew、Parallel Scavenge、CMS、G1 等收集器的特点及适用场景。
- **类加载机制**：加载、验证、准备、解析、初始化五个阶段，以及双亲委派模型。

### 逻辑推演/叙事脉络
- 首先介绍 JVM 的基本概念与运行过程（字节码到机器码）。
- 接着深入内存区域划分，详细解释堆的新生代与老年代结构。
- 随后阐述如何确定垃圾对象（引用计数 vs 可达性分析）及各类回收算法的优缺点。
- 最后介绍具体的垃圾收集器演进及类加载机制，形成完整的 JVM 运行时视图。

## 第3章：JAVA集合
### 核心论点
- Java 集合框架提供了多种数据结构实现，选择合适的集合类对程序性能至关重要。
- 核心观点：HashMap 在 JDK 8 引入红黑树优化了哈希冲突性能；ConcurrentHashMap 通过分段锁（JDK 7）或 CAS+synchronized（JDK 8）实现高并发安全。

### 关键概念/事件
- **List 实现**：ArrayList（数组，随机访问快）、LinkedList（链表，插入删除快）、Vector（线程安全但效率低）。
- **Map 实现**：HashMap（非线程安全，数组+链表+红黑树）、ConcurrentHashMap（线程安全）、TreeMap（排序）、LinkedHashMap（有序）。
- **Set 实现**：HashSet（基于 HashMap）、TreeSet（基于 TreeMap）、LinkedHashSet。

### 逻辑推演/叙事脉络
- 先介绍 Collection 接口继承关系。
- 分别详述 List、Set、Map 三大接口的常用实现类及其底层数据结构。
- 重点对比 HashMap 在 JDK 7 与 JDK 8 的实现差异，以及 ConcurrentHashMap 的线程安全演进。

### 经典金句/数据
> “Java8 对 HashMap 进行了一些修改，最大的不同就是利用了红黑树... 当链表中的元素超过了 8 个以后，会将链表转换为红黑树。” (p.51)

## 第4章：JAVA多线程并发
### 核心论点
- 并发编程的核心在于正确处理共享资源的竞争与线程间的协作。
- 核心观点：通过锁机制（synchronized, ReentrantLock, CAS）、线程池及并发工具类（AQS, CountDownLatch 等）实现高效、安全的并发控制。

### 关键概念/事件
- **线程状态与创建**：NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED；Thread, Runnable, Callable。
- **锁机制**：乐观锁（CAS）、悲观锁（synchronized）、重入锁、读写锁、自旋锁、偏向锁/轻量级锁/重量级锁升级过程。
- **线程池**：核心参数（corePoolSize, maximumPoolSize 等），四种拒绝策略，工作流程。
- **并发工具**：volatile 关键字，ThreadLocal，CountDownLatch，CyclicBarrier，Semaphore，AQS 原理。

### 逻辑推演/叙事脉络
- 从线程的基本创建方式和生命周期入手。
- 深入探讨锁的原理，从 synchronized 到 JUC 包下的 Lock 实现，再到 CAS 原子操作。
- 介绍线程池的原理与最佳实践。
- 最后讲解高级并发工具类及 AQS 抽象队列同步器框架，构建完整的并发知识体系。

### 经典金句/数据
> “volatile 变量具备两种特性... 变量可见性... 禁止重排序。” (p.87)
> “AQS 定义了一套多线程访问共享资源的同步器框架... 维护了一个 volatile int state 和一个 FIFO 线程等待队列。” (p.98)

## 第5章：JAVA基础
### 核心论点
- 扎实的基础知识是构建复杂系统的基石，包括异常处理、反射、注解、泛型及序列化等机制。
- 核心观点：反射机制赋予了 Java 动态能力，但需注意性能开销；序列化用于对象持久化与传输，需注意版本兼容性。

### 关键概念/事件
- **异常处理**：Error vs Exception，Checked vs Unchecked，try-catch-finally 机制。
- **反射**：Class 对象获取，动态创建对象，调用方法，破坏封装性。
- **注解**：元注解（Target, Retention 等），自定义注解及处理器。
- **泛型**：类型擦除，通配符（? extends/super）。
- **序列化**：Serializable 接口，transient 关键字，serialVersionUID 作用。

### 逻辑推演/叙事脉络
- 依次介绍异常分类与处理原则。
- 详解反射机制的原理与应用场景。
- 阐述注解的定义与处理流程。
- 解释泛型的编译期特性及类型擦除。
- 最后讨论对象序列化的实现细节与注意事项。

### 经典金句/数据
> “Java 中的泛型基本上都是在编译器这个层次来实现的... 这个过程就称为类型擦除。” (p.113)

## 第6章：SPRING原理
### 核心论点
- Spring 通过 IOC 和 AOP 两大核心特性实现了企业的解耦与模块化开发。
- 核心观点：IOC 容器管理 Bean 的生命周期与依赖关系，AOP 通过动态代理实现横切关注点的分离。

### 关键概念/事件
- **IOC/DI**：BeanFactory 与 ApplicationContext，Bean 生命周期，依赖注入方式（构造器、Setter、自动装配）。
- **AOP**：切面、连接点、切入点、通知、织入；JDK 动态代理 vs CGLIB。
- **Spring MVC**：DispatcherServlet 流程，HandlerMapping，ViewResolver。
- **Spring Boot**：自动配置原理，起步依赖，嵌入式容器。
- **事务管理**：声明式事务，传播行为，隔离级别。

### 逻辑推演/叙事脉络
- 首先概述 Spring 的特点与核心组件。
- 深入剖析 IOC 容器的启动过程与 Bean 的生命周期。
- 详解 AOP 的实现原理及两种代理方式的区别。
- 介绍 Spring MVC 的请求处理流程。
- 最后简述 Spring Boot 的自动化配置理念及事务管理机制。

## 第7章：微服务
### 核心论点
- 微服务架构通过将单体应用拆分为小型独立服务，提高了系统的可维护性与扩展性，但也带来了分布式复杂性。
- 核心观点：服务注册发现、API 网关、配置中心、熔断器等组件是构建稳定微服务系统的关键。

### 关键概念/事件
- **服务治理**：注册与发现（Eureka, Zookeeper, Consul），客户端负载均衡。
- **API 网关**：请求转发、路由、鉴权、限流（Zuul, Gateway）。
- **配置中心**：集中化管理配置，动态刷新。
- **容错机制**：Hystrix 熔断器原理（开路、半开、闭路状态）。
- **链路追踪**：Sleuth + Zipkin，Trace ID 与 Span ID。

- 重点讲解服务熔断与降级以应对雪崩效应。
- 最后提及链路追踪对于分布式系统调试的意义。

## 第8章：NETTY与RPC
### 核心论点
- Netty 是高性能异步事件驱动的网络应用框架，是构建 RPC 框架的理想底层通信组件。
- 核心观点：Netty 通过 Reactor 线程模型、零拷贝、内存池等技术实现了高吞吐与低延迟；RPC 核心在于动态代理、序列化与网络通信的封装。

### 关键概念/事件
- **Netty 核心**：Channel, Buffer, Selector, EventLoop, Pipeline。
- **高性能设计**：Reactor 模型（单线程/多线程/主从），零拷贝（Direct Buffer, FileRegion），内存池。
- **RPC 实现**：服务暴露与引用，动态代理（JDK/CGLIB），序列化（Protobuf, Hessian），通信协议设计。
- **其他 RPC 框架**：RMI, Thrift, Protocol Buffers。

### 逻辑推演/叙事脉络
- 首先介绍 Netty 的基本原理与高性能特性。
- 详细拆解 Netty 的线程模型与零拷贝机制。
- 进而阐述如何基于 Netty 实现一个简单的 RPC 框架，包括编解码、代理与回调机制。
- 最后简要对比其他 RPC 技术方案。

### 经典金句/数据
> “Netty 是一个高性能、异步事件驱动的 NIO 框架... 它的所有 IO 操作都是异步非阻塞的。” (p.147)

## 第9章：网络
### 核心论点
- 网络协议是分布式系统通信的基础，深入理解 TCP/IP 及 HTTP 协议有助于排查网络连接与性能问题。
- 核心观点：TCP 通过三次握手建立可靠连接，四次挥手断开连接；HTTP 是无状态协议，HTTPS 通过 SSL/TLS 保障安全。

### 关键概念/事件
- **OSI 七层模型**：物理层到应用层的职责划分。
- **TCP/IP**：三次握手（SYN, ACK），四次挥手（FIN, ACK），滑动窗口，拥塞控制。
- **HTTP/HTTPS**：请求/响应模型，状态码（200, 301, 404, 500 等），SSL 证书交换过程。
- **CDN**：内容分发网络原理，负载均衡与缓存策略。

### 逻辑推演/叙事脉络
- 从网络分层模型开始，聚焦传输层 TCP 协议。
- 详细图解 TCP 连接建立与断开过程。
- 转向应用层 HTTP 协议，解析其工作流程与状态码。
- 介绍 HTTPS 的安全机制及 CDN 的加速原理。

### 经典金句/数据
> “TCP 在传输之前会进行三次沟通... 传完数据断开的时候要进行四次沟通。” (p.161)

## 第11章：ZOOKEEPER
### 核心论点
- ZooKeeper 是一个分布式协调服务，为分布式系统提供一致性保障，常用于配置管理、命名服务及分布式锁。
- 核心观点：ZAB 协议保证了 ZooKeeper 集群的数据一致性，通过 Leader 选举与数据同步机制实现高可用。

### 关键概念/事件

- **ZAB 协议**：原子广播，崩溃恢复（Leader 选举），消息广播。
- **角色**：Leader, Follower, Observer。
- **应用场景**：分布式锁，Master 选举，配置中心。

## 第16章：CASSANDRA
### 核心论点
- Cassandra 是一个高度可扩展的分布式 NoSQL 数据库，专为高写入负载和多数据中心部署设计。
- 核心观点：采用去中心化的 P2P 架构与 Gossip 协议，通过一致性哈希与虚拟节点实现数据均匀分布与高可用。

### 关键概念/事件
