## 三、阿里云原生实践

### 3.1 Kubernetes + OAM（李响）

#### 问题诊断
- Kubernetes让DevOps变得更复杂
- 三大痛点：关注点不同、语义抽象程度不同、交互习惯不同

#### OAM（Open Application Model）解决方案
- 与微软联合发布，用于构建云原生应用管理平台的标准规范
- **三大目标**：
  1. 面向用户，应用为中心
  2. 高可扩展（可插拔、模块化）
  3. 统一、标准化

#### 核心概念
- **Component**：应用组成部分（容器、Function、云服务）
- **Trait**：运维能力（扩容、发布、访问控制）
- **ApplicationConfiguration**：应用配置

#### 社区进展
- OAM spec已在GitHub开源
- CNCF Sandbox项目（与Crossplane共建）
- 9月即将开源云原生应用基础平台

---

### 3.2 加速云端深度学习（车漾、范斌）

#### 挑战
- GPU性能提升（P100→V100，4倍算力提升）
- 分布式训练可提速300倍
- 但I/O成为瓶颈：云盘读取时GPU速度降为1/3

#### Alluxio解决方案
- 分布式内存级数据编排系统
- 核心功能：
  1. 分布式数据缓存
  2. 灵活多样的数据访问API（HDFS、POSIX）
  3. 统一文件系统抽象

#### 调优成果
- ResNet50训练性能单机八卡提升**236.1%**
- 四机八卡场景性能损失仅**3.29%**
- 比SSD云盘性能提升**70.1%**

#### 关键调优策略
1. 缓存元数据减少gRPC交互
2. 优化缓存行为控制
3. FUSE性能调优（元数据缓存、线程池配置）

### 3.3 大规模K8s集群SLO保障

#### 核心指标
| 指标                | 说明                  |
| ------------------- | --------------------- |
| 集群健康度          | Healthy/Warning/Fatal |
| 成功率              | Pod创建成功率         |
| Terminating Pod数量 | 残留Pod计数           |
| 服务在线率          | Master组件探针        |
| 故障机数量          | 节点维度指标          |

#### 成功标准
- 普通Pod：1分钟内Ready
- Job Pod：1分钟内Running/Succeeded/Failed
- Terminating Pod：规定时间内从ETCD删除
- 故障机：1分钟内完成Taint标记

#### 基础设施
- **Trace System**：日志采集、数据分析、生命周期展示
- **故障自愈**：NPD检测 + Controller处理
- **隔离机制**：权限、QPS、容量三层隔离

#### SLO提升技巧
- 镜像延迟加载（Image lazyload）
- 智能重试机制（排除失败节点）
- 多租户隔离保障

### 3.5 托管式服务网格ASM（王夕宁）

#### 架构模式变迁
- 代码库模式 → Sidecar代理模式 → 服务网格

#### 四大统一能力
1. **统一流量管理**：基于位置的路由、本地优先负载均衡

### 3.6 KubeNode：节点运维实践（周涛）

#### 挑战
- 规模：数百个ASI集群、数十万个节点
- 复杂性：异构机型（x86/ARM/GPU/FPGA）、多内核版本
- 稳定性：在线业务对延迟敏感

#### 架构组成
- **Machine Operator**：节点及组件管理
- **Remedy Operator**：节点故障自愈
- **Kube Node Agent**：单机agent
- **Kube Defender**：统一风控
- **NPD**：节点故障检测

#### CRD定义
- Machine（节点元信息）
- MachineSet（节点集合）
- MachineComponentSet（节点组件集合）

#### 故障自愈流程
1. NPD检测故障（如内核hung task）
2. Remedy Controller触发修复
3. KubeDefender风控校验
4. KubeNode Agent执行自愈操作

#### 未来计划
- 2020年下半年开源KubeNode

### 3.7 大数据Serverless方案

#### 硬多租架构
- **超级集群（Super Master）**：实际管理物理资源
- **租户集群（Tenant Master）**：虚拟K8s集群，控制面独立

#### 同步策略
- 仅同步12种必要资源到Super集群
- 不修改K8s原生组件
- 租户集群通过99%一致性认证测试（199/204）

#### 隔离机制
- **控制面隔离**：独立apiserver、etcd
- **计算隔离**：阿里云安全沙箱
- **网络隔离**：VPC + ENI直通
- **存储隔离**：弹性云盘

#### 落地产品：Flink全托管
- ABM Controller管理大数据服务
- VC Controller管理虚拟集群
- 无缝对接ARMS监控、SLS日志、OSS存储

### 4.3 Pod创建效率优化（张翼飞）

#### 拉取镜像优化
| 方案             | golang镜像提升 | hadoop镜像提升 |
| ---------------- | -------------- | -------------- |
| unpigz多线程解压 | 35.88%         | 16.41%         |
| 非压缩镜像       | 49.81%         | 27.89%         |

#### 镜像预热（OpenKruise）
```yaml
apiVersion: apps.kruise.io/v1alpha1
kind: ImagePullJob

  name: golang
spec:
  image: registry/golang:1.10
  parallelism: 10
```

#### P2P镜像分发（Dragonfly）
- SuperNode：调度决策 + CDN缓存
- Dfget：下载客户端 + 数据提供者
- Dfdaemon：透明代理

#### 按需加载（Nydus/stargz）

- 新的镜像格式：可索引、支持HTTP Range GET
- 原地升级（OpenKruise CloneSet）

### 4.4 面向SLO的资源调度（余英豪、王双）

#### QoS与优先级设计
- **QoS等级**：资源保障程度（独占CPU核/共享）
- **优先级等级**：调度/抢占/驱逐顺序

#### 资源水位估计
- 基于历史数据预估未来水位
- 增加buffer保障稳定性
- 可回收资源 = 已分配 - 预估需求

#### 冷内存回收
- 内核模块轻量级扫描
- 回收不活跃page cache
- 效果：整机可用内存增加10-20%

#### 成果
- 大规模集群资源利用率提升**10%**

## 五、阿里云开源贡献

### 5.1 Dragonfly：P2P镜像分发

#### 核心特性
- 基于P2P技术的高性能镜像分发基础设施
- 节点增加时分发时间不剧烈增长

#### 工作流程
1. 节点proxy转发拉取请求
2. SuperNode统一调度
3. SuperNode缓存（CDN功能）
4. 返回Peer地址和分片信息
5. 节点间P2P传输
6. 所有分片下载完成

#### 生态集成
- 容器引擎：Docker、Containerd、PouchContainer
- 镜像仓库：Harbor（Preheat预热）
- 可观测性：Prometheus、Grafana
- 部署：Helm一键安装

#### 里程碑
- 2015年诞生于阿里巴巴
- 2017年开源
- 2018年贡献给CNCF（Sandbox）
- 生产规模：阿里巴巴、中国移动、bilibili等

---

### 5.2 Nydus：OCIv2镜像标准探索

#### 当前OCIv1问题
| 问题     | 说明                             |
| -------- | -------------------------------- |
| 按需加载 | 全量下载浪费，仅10%数据被使用    |
| 去重     | 删除文件仍下载，修改导致全量复制 |
| 安全     | 解压后无法校验，缺少签名         |

#### Nydus解决方案
- 用户态文件系统（FUSE/virtiofs）
- 元数据与数据分离
- Merkle树结构（分块、文件、目录级校验）
- 按需加载（chunk粒度）

#### 未来规划
- 作为OCIv2标准参考实现
- 贡献给Dragonfly社区
- 适配不同CRI runtime
- 支持更多压缩算法、动态分块、精细去重
