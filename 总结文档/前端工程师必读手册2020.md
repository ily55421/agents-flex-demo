# 2020前端工程师必读手册 - 内容总结

本手册由阿里巴巴前端委员会推荐，覆盖了**语言框架、前端智能化、微前端、Serverless、工程化**五大热点前端技术方向，汇集了来自阿里、腾讯、百度等公司技术专家的实践分享。

## 一、 语言框架

### 1. JavaScript 语言在引擎级别的执行过程
- **作者**：周爱民（南潮首席架构师）
- **核心内容**：
    - **环境准备**：从传统的作用域（Scope）概念演进到ES5后的环境（Environment）规范，介绍了词法环境、环境记录和标识符引用。
    - **执行上下文**：解释了可执行上下文栈，以及全局、函数、模块等不同执行上下文的创建过程。
    - **过程控制**：深入生成器（Generator）和Promise如何让开发者控制任务队列和执行栈的调度。
    - **结果返回**：区分了执行表达式和语句的不同返回值。
    - **展开语法**：指出展开语法（`...`）是一种特殊的可执行组件，而非表达式或语句。

### 2. 基于 WebAssembly 的 H.265 播放器
- **作者**：陈映平（腾讯高级工程师）
- **背景**：直播行业带宽成本高昂，H.265编码相比H.264能节省30%-50%带宽，但因专利和浏览器支持问题未能普及。
- **方案选型**：对比了MSE和WASM解码方案，选择**HTTP-FLV + WASM + FFmpeg + H.265**的技术方案，利用WebAssembly在浏览器中高性能运行C/C++解码库。
- **架构设计**：设计了包含主线程、IO线程、解码线程的多线程播放器架构。
- **线上实践**：实现了H.265播放器，解决了FLV规范对H.265的CodeID支持、音画同步等典型问题，验证了节省30%流量的效果。

## 二、 前端智能化

### 1. 《前端智能化实践》——逻辑代码生成
- **作者**：甄子（阿里巴巴高级前端技术专家）
- **核心工具**：`imgcook`，通过机器视觉和机器学习将设计稿自动生成为代码。
- **能力升级**：从生成UI代码（UI Code）进阶到生成逻辑代码（Logic Code）。通过自然语言处理理解控件语义、上下文和业务诉求，从而生成数据绑定、交互逻辑等代码。
- **技术生态**：与TensorFlow.js团队合作，开源了前端智能框架`pipcook`，旨在降低前端开发者使用机器学习的门槛。
- **未来展望**：从单页面生成扩展到多页面复杂交互场景，致力于完全替代动效和逻辑开发。

### 2. 数据分析的人工智能画板——马良
- **作者**：言顾
- **产品愿景**：通过手绘稿或设计稿，在秒级内自动生成可编辑的数据可视化大屏。
- **核心技术**：利用深度学习（如Faster R-CNN）进行图表识别和位置提取，并结合可视化界面的概率密度函数优化识别准确率（提升6%-7%）。
- **能力扩展**：支持主题色提取和风格迁移，可将任意图片的配色方案应用到数据大屏中，降低可视化设计门槛。

## 三、 微前端

### 1. 云端新物种 - 微前端体系
- **作者**：克军（阿里云智能安全前端团队负责人）
- **核心概念**：微前端是云时代的前端架构体系，不是单一框架。它将前端应用拆分为按业务域划分的微应用，每个微应用可独立开发、测试、部署，不限技术栈。
- **价值与挑战**：具备独立部署、无限扩展等工程价值，以及产品“原子化”、能力输出的业务价值。但也面临体验折损、维护成本高等挑战。
- **体系构成**：包括微应用容器、配置中心、观察工具、本地开发工作台等基础设施，以及路由管理、沙箱隔离、消息通信等核心机制。

### 2. 标准微前端架构在蚂蚁的落地实践
- **作者**：有知（蚂蚁金服前端技术专家）
- **核心诉求**：解决遗留系统升级困难、技术栈不统一、多系统协作割裂等问题，实现技术栈无关和工程解耦。
- **关键技术决策**：
    - **应用导入**：采用**HTML Entry**方式，保留子应用的完整信息。
    - **样式隔离**：采用**动态加载/卸载样式表**的方案。
    - **JS隔离**：实现了**JS Sandbox**机制，在子应用生命周期内管理全局副作用。
    - **资源共享**：维护语义化版本映射表，实现多版本框架共存和最大程度复用。
    - **应用通信**：基于Props单向数据流和浏览器原生事件。
- **实践成果**：落地为`qiankun`微前端内核，支持了70+线上应用，最复杂场景下同时集成15个不同技术栈的应用。

## 四、 Serverless

### 1. 组件即函数和 Serverless SSR 实践
- **作者**：狼叔（阿里巴巴前端技术专家）
- **核心思想**：提出**组件即函数（Component as a Function, CaaF）** 的概念，将SSR从服务器端渲染升级为**Serverless端侧渲染**。
- **统一写法**：通过静态方法（如`getInitialProps`）和高阶组件，统一了CSR和SSR的组件编写方式。
- **SSR规范**：定义了基于FaaS的页面渲染描述规范（SSR-spec），将组件（Component）、数据获取（fetch）、布局（layout）拆分为独立函数并在配置文件中组合。
- **架构愿景**：实现“组件即函数 -> 页面即函数 -> 页面即服务”的演进，构建“网关 + 页面托管服务”的极简前端开发架构。

### 2. Serverless 函数应用架构升级
- **作者**：张挺（阿里）
- **核心里程**：基于 `midway-faas` 框架解决Serverless应用的四个核心问题：
    - **防厂商锁定**：通过标准化 `serverless.yml` 配置和代码层入参抽象，实现一份代码多云部署。
    - **灵活性**：支持函数的**高密度部署**，即在不改代码的情况下通过配置自由聚合或拆分函数部署，以优化成本和性能。
    - **开发效率**：全面采用TypeScript，引入IoC和装饰器，提升大型项目的可维护性。
    - **运行时扩展**：设计了一套包含Hook的生命周期机制，支持中间件、统一监控、埋点等能力。

### 3. 基于 FaaS 构建 NPM 同步 CDN
- **作者**：张立理（百度资深前端工程师）
- **目标**：构建从NPM到CDN的全自动同步系统，使开发者无需繁琐操作即可使用CDN加速。
- **为何选FaaS**：完美匹配包更新任务的**MapReduce结构**、负载波动大、需弹性伸缩等特点。
- **核心问题及解决**：
    - **事务**：利用锁文件和超时机制，保障异步环境下的最终一致性。
    - **长任务**：大包通过任务切割、流式编程（并行进行下载、校验、解压、上传）解决资源限制。
    - **频控**：优化sleep等待逻辑，减少函数无意义空转，节省费用。
    - **自循环**：使用定时触发器替代函数自调用，实现稳定可靠的永久执行任务。
    - **编排**：使用`Terraform`统一管理函数、存储、CDN等多云资源依赖和部署。

## 五、 工程化

### 1. 前端工程化下一站：IDE
- **作者**：上坡、坑头
- **趋势判断**：一体化研发模式是未来，IDE是承载体。前端工程化将从关注编译构建延伸至整合研发与上线全链路。
- **核心项目**：共建`KAITIAN`（开天）项目，旨在提供一套云端与本地一致、内外统一的IDE通用底层能力。
- **方案策略**：
    - **基础能力**：构建布局、编辑器、文件服务、终端等基础模块。
    - **业务能力**：通过强大的**插件体系**，允许业务定制UI和逻辑，兼容VSCode插件生态，将研发工具和服务集成到IDE中闭环。

### 2. 基于浏览器的实时构建探索之路
- **作者**：玄寂（RichLab花呗借呗前端团队）
- **核心理念**：探索在浏览器端完成整个构建过程，替代传统的服务端/本地Node.js构建，实现即时性、可离线、低成本的开发体验，更适合云时代。
- **技术方案（Gravity）**：
    - **内核**：基于`Tapable`的事件流驱动架构，编排构建流程。
    - **编译链**：通过`Ruleset`描述文件转换规则，利用Tapable`AsyncSeriesWaterfallHook`实现串行编译。
    - **文件系统**：利用`BrowserFS`在浏览器模拟Node.js文件系统。
    - **包管理**：提出服务化NPM思路，将`unpkg/jsdelivr`等CDN桥接为文件系统的后端，按需动态加载文件。
