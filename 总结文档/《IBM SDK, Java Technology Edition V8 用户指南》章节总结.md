## 前言
### 核心论点
- 本章主要介绍本指南的适用范围、基本约定及辅助功能支持。
- 核心观点：本指南适用于 IBM SDK, Java Technology Edition V8 及其后续修订版，旨在提供与 Oracle 实现差异的特定信息，并强调产品的辅助功能承诺。

### 关键概念/事件
- **适用范围**：适用于 IBM SDK V8 及所有后续发行版、修订版，直到新版本另有声明。
- **基础技术**：IBM 的 Java 实现基于 Oracle Corporation 开发的 Java Technology。
- **辅助功能**：产品支持键盘导航及屏幕阅读器（如通过 Oracle Java Access Bridge），致力于满足不同能力用户的需求。

### 逻辑推演/叙事脉络
前言首先明确了文档的版本适用性和更新机制（通过左侧竖线标识修改）。接着介绍了 IBM SDK 与 Oracle Java SE 的关系，指出需结合阅读 Oracle 文档。随后简要说明了术语定义（如 Runtime Environment 与 JVM 互换使用）及安全警告（不用于实时控制系统）。最后阐述了辅助功能的支持情况及键盘导航标准。

## 第1章：产品概述
### 核心论点
- 本章主要回答 IBM SDK V8 包含哪些组件、新增了什么功能以及其基本架构是什么。
- 核心观点：IBM SDK V8 提供了基于 Eclipse OpenJ9 虚拟机的开发工具和运行时环境，完全兼容 Oracle Java SE V8，并引入了针对性能、安全性和硬件加速的新特性。

### 关键概念/事件
- **SDK 组成**：包含 Java 编译器、JVM（Eclipse OpenJ9）、调试工具、GUI 开发工具及集成库。
- **Eclipse OpenJ9 VM**：IBM 贡献给 Eclipse 基金会的虚拟机，替代了旧的 J9 VM 名称，包含 JIT 编译器、诊断组件和内存管理。
- **资源占用量小的 JRE**：专为云环境和 Docker 设计的轻量级运行时，移除了不必要的工具和库以减小体积。
- **新增功能**：包括打包对象技术预览（后移除）、ORB 跟踪改进、GPU 支持（Linux/Windows）、硬件压缩加速等。

### 逻辑推演/叙事脉络
本章首先定义了 IBM SDK 和 Runtime Environment 的基本概念，列举了 SDK 中包含的具体工具（如 javac, java, jar 等）。接着详细介绍了 Eclipse OpenJ9 虚拟机的组件。随后，按时间顺序列出了从首个发行版到服务更新 5 的主要新增内容和变更，重点强调了兼容性、性能优化（如压缩引用、GPU 卸载）以及安全性更新。最后说明了资源占用量小的 JRE 的特性及其与标准 JRE 的区别。

### 经典金句/数据
> “Java平台的 IBM实现是以 Oracle Corporation开发的 Java Technology为基础的。” (p.1)
> “Eclipse OpenJ9 VM包含在针对 AIX、Linux、Windows和 z/OS的 SDK中。此 VM（以前称为 IBM J9 VM）由 IBM于 2017年 9月添加到 Eclipse Foundation中。” (p.12)

## 第2章：迁移
### 核心论点
- 本章主要解决从较低版本的 IBM SDK 或 Oracle JDK 迁移到 V8 时需要注意的兼容性问题和不推荐使用的功能。
- 核心观点：虽然 IBM SDK V8 与 Java SE 8 兼容，但从旧版本迁移时需关注 API 变更、废弃功能（如注释处理工具 apt、Rhino JS 引擎）以及系统属性的变化。

### 关键概念/事件
- **版本兼容性**：通常向后兼容，但不保证向前兼容；需注意 HashMap 迭代顺序变化等底层行为改变。
- **废弃与移除**：移除了注释处理工具 (apt)、Rhino JavaScript 引擎、IBM 辅助功能 JawBridge 等。
- **系统属性变更**：如 `jdk.map.althashing.threshold` 不再需要，`com.ibm.IgnoreMalformedInput` 已移除。
- **ORB 连接管理**：ORB 现在自动管理并发连接数，可能影响现有应用行为。

### 逻辑推演/叙事脉络
本章首先概述了从 V7/V7.1 迁移的主要变化，列出了具体的 API 移除和替换建议（如 JZOS 替代 JRIO）。接着讨论了版本兼容性的一般原则及例外情况（如操作系统依赖、方法名冲突）。最后详细列出了从更早版本迁移时需阅读的额外指南链接，确保用户能平滑过渡。

### 经典金句/数据
> “通常，使用先前版本的 SDK运行的任何 applet或应用程序都应可以使用此发行版正确运行。但不保证使用此发行版编译的类可以在先前的发行版上工作。” (p.41)

## 第3章：安装 SDK
### 核心论点
- 本章主要指导如何在不同操作系统（AIX, Linux, Windows, z/OS）上安装 IBM SDK V8。
- 核心观点：安装方法因平台而异，AIX 和 Linux 支持 InstallAnywhere 和原生包安装，Windows 和 z/OS 有特定的捆绑或 SMP/E 安装要求，且需注意依赖库和权限设置。

### 关键概念/事件
- **受支持环境**：详细列出了各平台支持的 OS 版本、硬件架构（如 POWER, zSystems, x86）及虚拟化软件支持。
- **安装方式**：
    - AIX: installp 包或 InstallAnywhere。
    - Linux: InstallAnywhere (.bin)。
    - Windows: 作为 IBM 产品的一部分提供，不可单独下载。
    - z/OS: SMP/E 或非 SMP/E 包。
- **验证与卸载**：提供了验证安装成功的方法（java -version）及卸载步骤。

### 逻辑推演/叙事脉络
本章首先介绍了不同平台的安装概览。接着详细描述了受支持的硬件和操作系统环境列表。随后分平台详细介绍了安装过程，包括 AIX 的 installp 配置、Linux 的有人照看/无人照看安装、Windows 的特殊说明以及 z/OS 的 SMP/E 流程。最后提供了安装验证、升级、重新定位及卸载的具体操作指南和已知问题。

### 经典金句/数据
> “注：在 Windows、MacOS、Solaris和 HP-UX平台上，SDK只能作为 IBM产品或服务的一部分提供。” (p.1)

## 第4章：配置环境
### 核心论点
- 本章主要解决如何配置环境变量和系统设置以确保 Java 应用程序正常运行。
- 核心观点：正确设置 PATH、CLASSPATH 和库路径（LIBPATH/LD_LIBRARY_PATH）是运行 Java 应用的基础，同时需根据硬件特性配置大页面、GPU 或 RDMA 等高级选项。

### 关键概念/事件
- **路径设置**：PATH 用于查找可执行文件，CLASSPATH 用于查找类库，库路径用于查找共享库。
- **系统资源配置**：包括 ulimits 设置、大页面支持、DLPAR 动态逻辑分区支持。
- **辅助功能配置**：启用 Oracle Java Access Bridge 以支持屏幕阅读器。
- **时区更新**：使用 JTZU 工具更新夏令时（DST）信息。

### 逻辑推演/叙事脉络
本章首先讲解了基本的环境变量设置（PATH, CLASSPATH, 库路径），并给出了具体命令示例。接着讨论了针对特定硬件和 OS 的系统配置，如资源限制、大页面、GPU 和 RDMA 的配置前提。随后介绍了辅助功能的启用方法和 z/OS 代码页转换。最后说明了如何使用 IBM Time Zone Update Utility 处理夏令时更改。

### 经典金句/数据
> “只有出现以下情况时，才需要显式地设置类路径：您需要使用一个不同的库或类文件...您更改了 bin和 lib目录的位置...您计划开发或运行在同一系统上使用不同运行时环境的应用程序。” (p.57)

## 第5章：开发 Java应用程序
### 核心论点
- 本章主要介绍如何使用 SDK 提供的工具进行 Java 应用程序的开发、调试和分发。
- 核心观点：SDK 提供了 JDB 调试器、JPDA 架构支持以及详细的 Swing 键盘绑定规范，开发者需注意不同平台的分发许可证限制。

### 关键概念/事件
- **调试工具**：Java Debugger (JDB) 基于 JPDA，支持本地和远程调试。
- **位模式检测**：通过 `com.ibm.vm.bitmode` 属性判断 JVM 是 32 位还是 64 位。
- **Swing 键盘绑定**：详细列出了各种 Swing 组件（按钮、表格、文本框等）在不同 Look & Feel 下的默认快捷键。
- **分发限制**：明确指出许可证不允许随意重新分发 SDK 文件，需确保目标机器已安装许可版本。

### 逻辑推演/叙事脉络
本章首先介绍了调试 Java 应用的方法，重点讲解了 JDB 的使用和 JPDA 连接方式。接着说明了如何检测 JVM 位模式和本机线程优先级设置。随后花费大量篇幅详细列举了 Swing 组件的默认键盘绑定表，供 GUI 开发参考。最后讨论了应用程序的分发策略及各平台（AIX, Linux, Windows, z/OS）的许可证限制。

### 经典金句/数据

- 本章主要解释如何使用 `java` 和 `javaw` 命令运行应用程序，以及如何配置运行时选项和处理全球化数据。
- 核心观点：通过命令行选项、系统属性和环境变量可以精细控制 JVM 行为，特别是对于双向文本（BiDi）和字符编码的处理需要特定配置。

### 关键概念/事件
- **启动命令**：`java` 和 `javaw` 的语法及参数含义。
- **版本信息**：使用 `-version` 获取构建号和版本详情。
- **双向数据支持**：通过 `JAVABIDI` 系统属性控制阿拉伯语和希伯来语等双向文本的布局转换。
- **全球化参数**：`-Xargencoding` 允许在命令行参数中使用 Unicode 转义序列。

### 逻辑推演/叙事脉络
本章首先定义了 `java` 和 `javaw` 的用途和语法。接着讲解了如何获取版本信息和指定 Java 选项（命令行、环境变量、选项文件）。随后深入探讨了双向数据支持，解释了 BiDi 布局转换的原理、`JAVABIDI` 属性的详细配置语法及局限性。最后介绍了命令行参数的全球化支持和在小尾数法（LE）环境下的运行注意事项。

## 第7章：性能调整
### 核心论点
- 本章主要提供提高 Java 应用程序性能的策略，包括 JVM 调优和硬件加速利用。
- 核心观点：通过选择合适的垃圾回收策略、启用类数据共享、利用硬件压缩、RDMA 和 GPU 加速，可以显著提升应用性能。

### 关键概念/事件
- **JVM 调优**：选择 GC 策略、类数据共享（缩短启动时间）、大页面支持。
- **硬件加速**：
    - 数据压缩：利用 PCIe 卡或 zEDC 加速 zip 操作。
    - RDMA：使用 JSOR 或 jVerbs 实现低延迟网络通信。
    - GPU：将并行计算任务卸载到 GPU（仅限 Linux/Windows）。

### 逻辑推演/叙事脉络
本章首先概述了 OpenJ9 的缺省优化策略，并指出非典型负载需手动调优。接着分节介绍了软件层面的调优手段（GC、类共享、大页面）。随后重点介绍了三种硬件加速技术：数据压缩、RDMA 网络和 GPU 计算，分别说明了其适用场景、配置前提和优势。最后指引读者前往各平台的故障诊断章节以解决性能问题。

### 经典金句/数据
> “OpenJ9配置为使用一组缺省选项启动，这组缺省选项可为具有典型工作负载的 Java应用程序提供最优运行时环境。但是，如果应用程序为非典型应用程序，那么可以通过调整 VM来提高性能。” (p.91)

## 第8章：安全性
### 核心论点
- 本章主要阐述 IBM SDK 中的安全组件、工具及最佳实践，以帮助开发者构建安全的 Java 应用。
- 核心观点：安全性涉及多个层面，包括 Attach API 权限、转储文件敏感信息保护、XML 处理限制、共享类缓存访问控制以及启用 Security Manager。

### 关键概念/事件
- **安全组件**：JAAS, JCE, JSSE, SASL, PKCS#11 等标准安全 API 的 IBM 实现。
- **风险提示**：Attach API 需保护访问权；转储文件可能包含敏感数据；JConsole 非安全选项仅用于开发。
- **XML 安全**：通过 JAXP 限制防止恶意 XML 攻击。
- **共享类安全**：通过 OS 权限和 Java 权限控制对共享类缓存的访问。

### 逻辑推演/叙事脉络
本章首先列出了关键的安全性注意事项，如 Attach API、转储文件、JConsole 和 XML 处理的风险。接着介绍了 SDK 提供的安全组件和工具（如 keytool, iKeyman）。最后强调了升级 SDK 时备份安全配置文件的重要性，并提供了相关 Oracle 安全文档的链接。

### 经典金句/数据
> “缺省情况下，未启用 Java安全性，它允许不受限制地运行 applet或不可信代码...为了保护 Java，需要启用 Security Manager...” (p.94)

## 第9章：故障诊断和支持
### 核心论点
- 本章主要提供一套系统化的方法论和工具集，用于诊断和解决 IBM SDK 在各平台上的运行时问题。
- 核心观点：故障诊断应遵循“收集信息->确定瓶颈->使用专用工具”的流程，不同平台（AIX, Linux, Windows, z/OS）有特定的诊断命令和转储分析工具。

### 关键概念/事件
- **问题确定第一步**：检查近期变更、其他软件干扰、重现性、平台差异等。
- **平台特定诊断**：
    - AIX: svmon, topas, dbx 插件, core dump 配置。
    - Linux: strace, ltrace, gdb, /proc 文件系统。
    - Windows: Dr. Watson, 任务管理器转储, 注册表设置。
    - z/OS: IPCS, CEEDUMP, SLIP traps。
- **通用工具**：IBM Monitoring and Diagnostic Tools (Health Center, GCMV, Memory Analyzer)。
- **常见问题**：内存泄漏（Java/本机堆）、死锁、挂起、性能瓶颈。

### 逻辑推演/叙事脉络
本章篇幅极长，首先介绍了提交问题报告的流程和已知问题。接着按平台（AIX, Linux, Windows, z/OS）分别详细阐述了环境设置、常用调试命令、崩溃/挂起/内存泄漏的诊断方法。随后介绍了 NLS（全球化）问题的诊断。最后重点介绍了 IBM 提供的图形化诊断工具集（Health Center, GCMV 等）以及 HPROF 概要分析器的使用。

### 经典金句/数据
> “发生故障时，要获取的最重要的诊断数据是系统转储。缺省情况下，大部分 JVM设置都适用，但要确保在 AIX上生成系统转储，必须检查多项操作系统设置。” (p.106)

## 第10章：利用数据压缩设备
### 核心论点
- 本章主要介绍如何利用硬件加速设备提高数据压缩和解压缩的性能。
- 核心观点：在支持的硬件（Power Systems, IBM Z）和 OS 上，通过配置环境变量或使用 zEDC，可以将 java.util.zip 操作卸载到硬件加速器，从而降低 CPU 消耗。

### 关键概念/事件
- **硬件压缩加速**：适用于 AIX 和 Linux，需 GenWQE 驱动和 PCIe 加速卡。通过 `ZLIB_DEFLATE_IMPL=1` 启用。
- **zEnterprise Data Compression (zEDC)**：适用于 z/OS，需 zEC12/zBC12 硬件和 zEDC 功能部件。通过 `_HZC_COMPRESSION_METHOD` 控制。

### 逻辑推演/叙事脉络
本章首先介绍了 AIX/Linux 上的硬件压缩加速，列出了软硬件需求，说明了如何通过环境变量启用并验证（通过跟踪日志）。接着介绍了 z/OS 上的 zEDC 解决方案，同样列出了需求、配置步骤（SAF 权限、环境变量）及验证方法。

### 经典金句/数据
> “如果应用程序使用 java.util.zip类提供 Java压缩服务，那么硬件压缩可以减少 CPU消耗并缩短处理时间。” (p.189)

## 第11章：利用图形处理单元（仅限 Linux和 Windows）
### 核心论点
- 本章主要介绍如何将 Java 应用程序的部分计算任务卸载到 GPU 以提升性能。
- 核心观点：通过 CUDA4J API、com.ibm.gpu API 或 JIT 编译器自动卸载，可以利用 NVIDIA GPU 的并行处理能力加速排序和并行循环操作。

### 关键概念/事件
- **系统需求**：需 NVIDIA CUDA Toolkit 7.5+ 和支持 CUDA 的 GPU。
- **编程接口**：
    - CUDA4J：低级控制，直接调用 GPU 内核。
    - com.ibm.gpu：高级 API，主要用于数组排序。
- **JIT 加速**：通过 `-Xjit:enableGPU` 启用，自动将 `IntStream.parallel().forEach` 等并行流操作卸载到 GPU。
- **启用方式**：通过系统属性 `-Dcom.ibm.gpu.enable` 或 JIT 选项控制。

### 逻辑推演/叙事脉络
本章首先解释了 GPU 并行处理的优势及适用场景。接着列出了详细的软硬件需求。随后介绍了两种编程模型：CUDA4J（低级）和 com.ibm.gpu（高级排序）。重点讲解了 JIT 编译器如何自动识别并卸载并行流任务。最后提供了启用 GPU 处理的步骤、系统属性说明及故障诊断方法。

### 经典金句/数据
> “您可以启用即时(Just-In-Time, JIT)编译器将特定处理任务卸载到通用图形处理单元(GPU)。JIT根据性能试探确定何时卸载这些任务。” (p.198)

## 第12章：利用 RDMA
### 核心论点
- 本章主要介绍如何利用远程直接存储器存取（RDMA）技术提高 Java 网络通信性能。
- 核心观点：通过 JSOR（Java Sockets over RDMA）或 jVerbs 库，Java 应用可以绕过内核协议栈，利用 InfiniBand/RoCE 网络实现低延迟、高带宽通信。

### 关键概念/事件
- **JSOR**：透明替换 TCP 套接字，无需修改代码，只需配置文件和系统属性。支持 NET 和 NIO。
