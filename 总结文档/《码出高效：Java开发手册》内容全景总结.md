## 概述
本书源于阿里巴巴内部广泛使用的《阿里巴巴Java开发手册》，由阿里高级技术专家杨冠宝（孤尽）等人编写。旨在通过规范代码风格、深入底层原理、解析并发与集合源码，帮助开发者写出高质量、可维护、高效的代码。核心理念是“码”出高效，即通过规范提升沟通效率与研发效能。

## 第1章：计算机基础 (来自 Part 1 & Part 2)

本章从底层硬件和网络协议出发，为上层编程打下基石。

### 1.1 走进0与1的世界
*   **二进制与位运算**：计算机底层由0和1组成。介绍了位移运算（`<<`, `>>`, `>>>`），左移相当于乘2，右移相当于除2（注意奇数右移精度丢失）。无符号右移 `>>>` 高位补0。
*   **逻辑运算**：区分了按位与/或（`&`, `|`）与逻辑与/或（`&&`, `||`）。后者具有短路特性，前者没有。异或（`^`）用于哈希离散。

### 1.2 浮点数
*   **IEEE 754标准**：浮点数由符号位、阶码（移码表示）、尾数组成。
*   **精度问题**：浮点数无法精确表示所有小数（如 `1.0 - 0.9 != 0.1`），因为二进制无法无限表示某些十进制小数。
*   **最佳实践**：
    *   金融场景严禁使用 `float/double`，应使用 `BigDecimal` 或整型（分/美分）。
    *   禁止使用 `==` 比较浮点数，应使用误差范围比较。
    *   数据库中使用 `DECIMAL` 类型而非 `FLOAT/DOUBLE。

### 1.3 字符集与乱码
*   **编码演变**：ASCII -> GBK/GB2312 -> Unicode -> UTF-8。
*   **UTF-8**：可变长度编码，兼容ASCII，适合网络传输。
*   **乱码根源**：编码与解码使用的字符集不一致。建议全链路（DB、Server、Client）统一使用 UTF-8。
*   **换行符差异**：Windows (`\r\n`), Linux/Mac (`\n`)。

### 1.4 CPU与内存
*   **CPU结构**：控制器（指令译码、控制单元）+ 运算器（ALU）。
*   **缓存体系**：L1/L2/L3 Cache 解决 CPU 与内存速度差异。利用局部性原理（时间/空间）提升性能。
*   **内存管理**：Java 通过 JVM 自动管理内存（GC），避免手动指针操作带来的风险（如 C/C++ 中的野指针）。

### 1.5 TCP/IP 网络协议
*   **分层模型**：链路层、网络层（IP）、传输层（TCP/UDP）、应用层（HTTP等）。
*   **TCP 三次握手**：建立连接，防止历史连接初始化混乱。
    *   Client: SYN
    *   Server: SYN + ACK
    *   Client: ACK
*   **TCP 四次挥手**：断开连接，确保数据发送完毕。
    *   主动关闭方进入 `TIME_WAIT` 状态，等待 2MSL，防止旧报文干扰新连接。
    *   被动关闭方可能处于 `CLOSE_WAIT`，若大量堆积说明应用层未正确关闭连接（资源泄漏）。
*   **连接池**：高频场景下复用连接，减少握手开销。需合理配置最小/最大连接数及超时时间，避免雪崩。

### 1.6 信息安全
*   **CIA 三要素**：保密性 (Confidentiality)、完整性 (Integrity)、可用性 (Availability)。
*   **SQL 注入**：严禁字符串拼接 SQL，必须使用预编译（PreparedStatement）或框架提供的绑定机制（如 MyBatis 的 `#{}`）。
*   **XSS (跨站脚本)**：对用户输入进行过滤或转义，防止恶意脚本执行。
*   **CSRF (跨站请求伪造)**：通过 Token 验证或同源策略防护。
*   **HTTPS**：结合对称加密（传输数据）与非对称加密（交换密钥），并引入 CA 证书解决信任问题。

### 1.7 编程语言发展
*   从机器语言到汇编，再到高级语言（面向对象/过程），最终趋向自然语言编程。
*   Java 的优势：跨平台（JVM）、面向对象、丰富的类库、强大的生态。

## 第2章：面向对象 (来自 Part 3, Part 4, Part 5)

本章深入 Java 面向对象的核心概念与最佳实践。

### 2.1 OOP 理念
*   **四大特性**：抽象、封装、继承、多态。
    *   **抽象**：提取共性，建模能力。
    *   **封装**：隐藏细节，暴露接口，降低耦合。
    *   **继承**：代码复用，遵循里氏代换原则（LSP）。慎用继承，优先组合。
    *   **多态**：运行时动态绑定，基于覆写（Override）。

### 2.2 初识 Java
*   JDK/JRE/JVM 的关系。
*   Java 版本演进：JDK 5 (泛型/注解), JDK 8 (Lambda/Stream), JDK 11/17 (LTS)。

### 2.3 类
*   **定义规范**：类名大驼峰，成员变量小驼峰。
*   **接口 vs 抽象类**：
    *   接口：契约设计，多实现，默认 public abstract。
    *   抽象类：模板设计，单继承，可有具体实现。
    *   优先定义接口，再提供抽象类实现骨架。
*   **内部类**：
    *   静态内部类：不依赖外部实例，常用（如 Builder 模式）。
    *   成员内部类：依赖外部实例。
    *   局部/匿名内部类：方法内或表达式中。
*   **访问权限**：`private` < `(default)` < `protected` < `public`。严控权限，最小化暴露。
*   **this 与 super**：`this` 指当前对象，`super` 指父类引用。构造方法中必须首行调用。
*   **类关系**：继承 (is-a)、实现 (can-do)、组合/聚合 (has-a)、依赖 (uses-a)。

### 2.4 方法
*   **方法签名**：方法名 + 参数列表。**不包含**返回值和访问修饰符。
*   **参数传递**：Java 只有**值传递**。
    *   基本类型：拷贝值。
    *   引用类型：拷贝引用地址（可修改对象内容，但不可改变引用指向）。
*   **可变参数**：`Type... args`，本质是数组。必须位于参数列表最后，避免重载歧义。
*   **参数校验**：对外接口、低频高耗时方法必须校验；内部高频调用可省略以提升性能。
*   **构造方法**：
    *   无参构造默认存在，若定义了有参构造，需显式定义无参构造。
    *   构造方法中不应包含复杂业务逻辑。
    *   执行顺序：父类静态块 -> 子类静态块 -> 父类构造块/构造方法 -> 子类构造块/构造方法。
*   **Getter/Setter**：
    *   遵循封装原则。
    *   布尔类型字段命名避免 `is` 开头（如 `isDeleted`），防止序列化框架解析错误，建议用 `deleted`。
    *   不要在 Getter/Setter 中添加复杂业务逻辑。
*   **覆写 (Override)**：
    *   口诀：“一大两小两同”。
        *   一大：访问权限 >= 父类。
        *   两小：返回值类型、抛出异常类型 <= 父类（协变）。
        *   两同：方法名、参数列表相同。
    *   必须加 `@Override` 注解。
*   **重载 (Overload)**：
    *   编译期静态绑定。
    *   匹配优先级：精确匹配 > 自动装箱/拆箱 > 宽类型转换 > 可变参数。

### 2.5 泛型
*   **本质**：类型参数化，编译期类型检查，运行时类型擦除（Type Erasure）。
*   **优势**：类型安全、代码复用、消除强制转换。
*   **通配符**：
    *   `? extends T`：上界，只读不写（Producer）。
    *   `? super T`：下界，只写不读（Consumer）。
    *   PECS 原则：Producer Extends, Consumer Super。

### 2.6 数据类型
*   **基本类型 vs 包装类型**：
    *   基本类型：栈存储，效率高，默认值非 null。
    *   包装类型：堆存储，支持 null，泛型必需。
*   **缓存机制**：
    *   `Integer`, `Long`, `Short`, `Byte`, `Character` 在特定区间（通常 -128~127）缓存对象。
    *   **陷阱**：超出缓存范围使用 `==` 比较会返回 false。**推荐始终使用 `.equals()` 比较包装类值。**
    *   `Long` 缓存范围可通过 `-XX:AutoBoxCacheMax` 调整。
*   **String**：
    *   不可变性，常量池缓存。
    *   `StringBuilder`（非线程安全，高效） vs `StringBuffer`（线程安全）。
    *   循环拼接字符串严禁使用 `+`，应使用 `StringBuilder.append()`。

### 2.7 序列化
*   **目的**：对象持久化或网络传输。
*   **方式**：
    *   Java 原生序列化：实现 `Serializable` 接口，需定义 `serialVersionUID`。性能一般，不支持跨语言。
    *   Hessian/Protobuf：高效，跨语言，二进制流小。
    *   JSON：可读性好，广泛用于 Web API。
*   **安全风险**：反序列化漏洞。避免反序列化不可信数据，敏感字段加 `transient`。

## 第3章：代码风格 (来自 Part 5)

代码风格不影响运行，但影响协作与维护。核心原则：**一致性**。

### 3.1 命名规约
*   **通用**：
    *   类名：大驼峰 (PascalCase)，名词。
    *   方法/变量：小驼峰 (camelCase)，动词/名词。
    *   常量：全大写，下划线分隔 (UPPER_CASE)。
    *   包名：全小写，单数，域名倒置。
*   **望文知义**：
    *   严禁拼音、中英文混合、无意义缩写。
    *   避免魔法值（Magic Number/String），必须定义为常量或枚举。
*   **特殊约定**：
    *   抽象类：`Abstract` 或 `Base` 开头。
    *   异常类：`Exception` 结尾。
    *   测试类：`Test` 结尾。
    *   枚举：`Enum` 后缀，成员全大写。

### 3.2 代码展示风格
*   **缩进**：4个空格，禁止 Tab。
*   **空格**：
    *   运算符两侧、逗号后、关键字与括号间加空格。
    *   左大括号前加空格，后换行。
*   **换行**：
    *   单行不超过 120 字符。
    *   运算符、点号、参数逗号后换行，第二行缩进 4 空格。
*   **方法行数**：单个方法不超过 80 行。过长需拆分，提取私有方法。

### 3.3 控制语句
*   **大括号**：即使只有一行代码，`if/else/for/while` 也必须加大括号。
*   **复杂逻辑**：将复杂条件表达式提取为有意义的布尔变量。
*   **嵌套**：避免超过 3 层嵌套。使用卫语句（Guard Clauses）、策略模式、状态模式优化。
*   **取反**：尽量使用正向逻辑，避免 `!condition`，除非语义更清晰。

### 3.4 代码注释
*   **三要素**：
    *   Nothing is strange：关键逻辑必有注释。
    *   Less is more：代码自解释，注释画龙点睛，避免废话。
    *   Keep with the code：代码修改，注释同步更新。
*   **格式**：
    *   类、方法、公有成员使用 Javadoc (`/** ... */`)。
    *   内部逻辑使用单行注释 (`//`)，置于代码上方，而非行尾。
    *   枚举、常量必须注释含义。

## 第4章：走进 JVM (来自 Part 5)

### 4.1 字节码
*   **Class 文件结构**：魔数 (`0xCAFEBABE`)、版本号、常量池、访问标志、字段表、方法表、属性表。
*   **指令集**：加载存储、运算、类型转换、对象创建、栈管理。
*   **执行模式**：解释执行 + JIT 编译（热点代码编译为机器码）。

### 4.2 类加载过程
*   **生命周期**：加载 -> 验证 -> 准备 -> 解析 -> 初始化 -> 使用 -> 卸载。
*   **双亲委派模型**：Bootstrap -> Extension -> Application。保证核心类库安全，避免重复加载。

### 4.3 内存布局
*   **对象头 (Object Header)**：12字节（64位开启压缩指针）。
    *   Mark Word：哈希码、GC 分代年龄、锁状态。
    *   Class Metadata Pointer：指向类元数据。
*   **实例数据**：成员变量。
*   **对齐填充**：对象大小必须是 8 字节的倍数。
*   **引用类型**：引用变量本身占 4 字节（压缩指针），指向堆中对象。

### 4.4 对象实例化
*   检查类是否加载 -> 分配内存（指针碰撞/空闲列表） -> 初始化零值 -> 设置对象头 -> 执行 `<init>` 方法。

### 4.5 垃圾回收 (GC)
*   **判断对象存活**：引用计数法（已淘汰）、可达性分析（GC Roots）。
*   **GC 算法**：标记-清除、标记-复制（新生代）、标记-整理（老年代）。
*   **收集器**：Serial, Parallel, CMS, G1, ZGC。

## 第6章：数据结构与集合 (来自 Part 6, Part 8, Part 9, Part 10)

本章是本书的重点之一，深入分析了Java集合框架的底层实现，特别是HashMap和ConcurrentHashMap。

### 6.1 数据结构基础

- **定义**：逻辑意义上的数据组织方式（线性、树、图、哈希）及其处理算法。

- **复杂度**：重点关注时间复杂度，从 O(1)*O*(1) 到 O(2n)*O*(2*n*)。

- 集合框架图

  ：

  - `Collection` 体系：`List` (ArrayList, LinkedList), `Set` (HashSet, TreeSet), `Queue`。
  - `Map` 体系：`HashMap`, `TreeMap`, `ConcurrentHashMap`, `Hashtable`。

### 6.2 常用集合详解

- List

  ：

  - `ArrayList`：基于动态数组，支持随机访问，扩容因子1.5倍。**建议初始化指定容量**。
  - `LinkedList`：基于双向链表，插入删除快，随机访问慢。

- Set

  ：

  - `HashSet`：基于HashMap实现，元素无序且唯一。
  - `TreeSet`：基于TreeMap实现，元素有序。

- Map

  ：

  - `HashMap`：基于哈希表，允许null键值，线程不安全。
  - `TreeMap`：基于红黑树，Key有序。
  - `ConcurrentHashMap`：线程安全的哈希表。

### 6.3 集合初始化与最佳实践

- 指定初始容量

  ：避免频繁扩容带来的性能损耗。

  - `ArrayList` 默认10，扩容公式 `oldCapacity + (oldCapacity >> 1)`。
  - `HashMap` 默认16，负载因子0.75，扩容为2倍。

- 数组与集合转换

  ：

  - `Arrays.asList()` 返回的是内部类，不支持增删操作（UnsupportedOperationException），仅支持修改。
  - `list.toArray()` 建议传入指定类型的数组，且容量足够，避免反射创建新数组的性能开销。

### 6.4 泛型与集合

- **类型擦除**：泛型仅在编译期有效，运行时擦除为Object或上限类型。

- 通配符

  ：

  - `<? extends T>` (PECS原则中的Producer)：上界，只读不写（除了null）。
  - `<? super T>` (PECS原则中的Consumer)：下界，只写不读（读取为Object）。
  - **PECS原则**：Producer Extends, Consumer Super。

### 6.5 元素比较

- Comparable vs Comparator

  ：

  - `Comparable`：自然排序，实现 `compareTo` 方法。
  - `Comparator`：定制排序，实现 `compare` 方法，更灵活。

- equals 与 hashCode

  ：

  - 约定：如果 `equals` 相等，则 `hashCode` 必须相等。
  - HashMap中先判断hashCode，再判断equals。自定义对象作为Key必须重写这两个方法。

### 6.6 Fail-Fast 机制

- **定义**：在遍历集合时，如果结构被修改（modCount != expectedModCount），抛出 `ConcurrentModificationException`。
- **场景**：单线程遍历时删除元素需使用 `Iterator.remove()`。
- **Fail-Safe**：`CopyOnWriteArrayList` 等并发集合采用读写分离/快照机制，遍历时不抛异常，但可能读到旧数据。

### 6.7 Map类集合深度解析

- TreeMap

  ：

  - 基于**红黑树**实现。
  - 红黑树特性：节点红/黑、根黑、叶子黑、无连续红节点、路径黑节点数相同。
  - 操作：插入/删除后通过旋转和着色保持平衡，最坏 O(log⁡n)*O*(log*n*)。

- HashMap (JDK 7 vs 8)

  ：

  - **JDK 7**：数组+链表。**致命缺陷**：多线程扩容时可能形成**死链**（Dead Loop），导致CPU 100%。原因是头插法导致链表逆序，并发迁移时指针指向错误。

  - JDK 8

    ：数组+链表+红黑树。

    - 当链表长度 > 8 且数组长度 >= 64 时，链表转为红黑树。
    - 当红黑树节点 < 6 时，退化为链表。
    - 扩容采用尾插法，避免死链。

- ConcurrentHashMap (JDK 8)

  ：

  - **摒弃分段锁**：采用 `Node` + `CAS` + `synchronized`。
  - **锁粒度**：仅锁定链表/红黑树的头节点，并发度更高。
  - **扩容优化**：支持多线程协助扩容，使用 `ForwardingNode` 标记正在迁移的桶。
  - **size计算**：使用 `baseCount` + `CounterCell` 数组，避免全局锁，类似 LongAdder 原理。

## 第7章：并发与多线程 (来自 Part 7, Part 10)

本章深入探讨Java并发编程的核心机制，从线程安全到锁原理，再到线程池。

### 7.1 线程安全与基础

- **并发 vs 并行**：并发是交替执行，并行是同时执行。

- **线程状态**：NEW, RUNNABLE, BLOCKED, WAITING, TIMED_WAITING, TERMINATED。

- 线程安全维度

  ：

  1. 数据单线程可见（ThreadLocal）。
  2. 只读对象（Immutable）。
  3. 线程安全类（Vector, Hashtable - 已过时，推荐JUC包）。
  4. 同步与锁机制。

### 7.2 锁机制

- **AQS (AbstractQueuedSynchronizer)**：JUC包的基础，通过state变量和CLH队列实现同步。

- Synchronized

  ：

  - JVM层面实现，基于Monitor对象。
  - **锁升级**：偏向锁 -> 轻量级锁（CAS自旋） -> 重量级锁（OS Mutex）。
  - 偏向锁：消除无竞争下的同步开销。

- ReentrantLock

  ：

  - API层面实现，基于AQS。
  - 支持公平/非公平锁，可中断，支持Condition。

- **ReadWriteLock / StampedLock**：读写分离，提升读多写少场景性能。

### 7.3 线程同步

- Volatile

  ：

  - 保证**可见性**（禁止指令重排，内存屏障）和**有序性**。
  - **不保证原子性**（如 i++ 操作仍需加锁或使用Atomic类）。
  - 适用场景：状态标志位、单例双重检查锁定（DCL）。

- 信号量同步工具

  ：

  - `CountDownLatch`：等待多个线程完成任务（一次性）。
  - `CyclicBarrier`：多个线程互相等待到达屏障点（可循环）。
  - `Semaphore`：控制并发访问的资源数量（限流）。

### 7.4 线程池 (ThreadPoolExecutor)

- 核心参数

  ：

  - `corePoolSize`：核心线程数。
  - `maximumPoolSize`：最大线程数。
  - `keepAliveTime`：空闲线程存活时间。
  - `workQueue`：任务队列（ArrayBlockingQueue, LinkedBlockingQueue, SynchronousQueue等）。
  - `threadFactory`：线程工厂（用于命名线程，便于排查问题）。
  - `handler`：拒绝策略（Abort, CallerRuns, Discard, DiscardOldest）。

- 执行流程

  ：

  1. 核心线程满？-> 入队。
  2. 队列满？-> 创建非核心线程。
  3. 最大线程满？-> 执行拒绝策略。

- 最佳实践

  ：

  - **禁止使用 `Executors` 静态方法创建线程池**（Fixed/Cached/NewSingle等），因为默认队列无界或线程数无限，易导致OOM。
  - 手动创建 `ThreadPoolExecutor`，根据业务类型（IO密集型/CPU密集型）配置参数。
  - 隔离不同业务的线程池，避免相互影响。

### 7.5 ThreadLocal

- **原理**：每个线程拥有独立的 `ThreadLocalMap`，Key是ThreadLocal本身（弱引用），Value是存储的对象。
- **内存泄漏风险**：Key是弱引用，GC后可被回收，但Value是强引用。若线程长期运行（如线程池），Value无法回收。
- **解决**：使用完后必须调用 `remove()` 方法清理。

## 第7章：并发与多线程 (续)

本章重点深入了线程池的源码实现、ThreadLocal的原理与副作用，以及并发编程的最佳实践。

### 7.4 线程池 (ThreadPoolExecutor)

#### 7.4.1 线程池的好处与创建

- 核心优势

  ：

  - **降低资源消耗**：复用线程，避免频繁创建/销毁线程带来的开销。
  - **提高响应速度**：任务到达时，线程已存在，无需等待创建。
  - **提高线程可管理性**：统一分配、调优和监控。

- 构造参数详解

  ：

  - `corePoolSize`：核心线程数。
  - `maximumPoolSize`：最大线程数。
  - `keepAliveTime`：非核心线程空闲存活时间。
  - `workQueue`：任务队列（如 `LinkedBlockingQueue`, `ArrayBlockingQueue`）。
  - `threadFactory`：线程工厂，**必须自定义命名**，便于问题排查（如死锁、CPU飙高时定位业务来源）。
  - `handler`：拒绝策略。

- 禁止使用 `Executors` 静态方法创建线程池

  ：

  - `newFixedThreadPool` 和 `newSingleThreadExecutor`：允许请求队列长度为 `Integer.MAX_VALUE`，可能堆积大量请求，导致 OOM。
  - `newCachedThreadPool`：允许创建线程数量为 `Integer.MAX_VALUE`，可能创建大量线程，导致 OOM。
  - **推荐方式**：直接使用 `ThreadPoolExecutor`构造函数，明确指定参数。

#### 7.4.2 线程池源码详解

- **状态表示**：使用 `int` 的高3位表示运行状态（RUNNING, SHUTDOWN, STOP, TIDYING, TERMINATED），低29位表示工作线程数量。

- 执行流程 (`execute`)

  ：

  1. 如果当前线程数 < `corePoolSize`，创建新线程执行任务。
  2. 如果当前线程数 >= `corePoolSize`，将任务加入 `workQueue`。
  3. 如果队列满，且当前线程数 < `maximumPoolSize`，创建非核心线程执行任务。
  4. 如果队列满，且当前线程数 >= `maximumPoolSize`，执行拒绝策略。

- **Worker 机制**：线程池通过 `Worker` 类包裹线程，`Worker` 实现了 `Runnable` 和 `AQS`（独占锁），用于控制线程的中断和生命周期。

### 7.5 ThreadLocal

#### 7.5.1 引用类型

- **强引用 (Strong Reference)**：默认引用，GC Roots 可达则不回收。
- **软引用 (Soft Reference)**：内存不足时回收，适合缓存。
- **弱引用 (Weak Reference)**：GC 发生时立即回收。`ThreadLocalMap` 的 Key 使用弱引用，防止内存泄漏（但 Value 仍是强引用，需手动 remove）。
- **虚引用 (Phantom Reference)**：对象被回收时收到通知，用于跟踪对象生命周期。

#### 7.5.2 ThreadLocal 价值与原理

- **核心价值**：实现线程隔离，每个线程拥有独立的变量副本，避免共享变量的线程安全问题。

- 应用场景

  ：

  - 数据库连接管理。
  - Session 管理。
  - 分布式链路追踪（TraceId 透传）。
  - SimpleDateFormat 线程安全封装。

- 底层结构

  ：

  - 每个 `Thread` 对象内部有一个 `ThreadLocalMap`。
  - `ThreadLocalMap` 是一个自定义的 HashMap，Key 是 `ThreadLocal` 实例（弱引用），Value 是存储的值。

- **InheritableThreadLocal**：支持父子线程间的数据传递（子线程创建时复制父线程的 InheritableThreadLocal 变量）。

#### 7.5.3 ThreadLocal 副作用

- 内存泄漏

  ：

  - **原因**：`ThreadLocalMap` 的 Key 是弱引用，Value 是强引用。如果 `ThreadLocal` 实例被回收，Key 变为 null，但 Value 仍然存在于 Map 中，且线程可能长期运行（如线程池），导致 Value 无法回收。
  - **解决**：使用完 `ThreadLocal` 后，必须调用 `remove()` 方法清理 Entry。

- 脏数据

  ：

  - **原因**：线程池复用线程，如果上一个请求设置了 `ThreadLocal` 值而未清理，下一个请求可能读取到旧值。
  - **解决**：在 `finally` 块中调用 `remove()`。

## 第8章：单元测试

单元测试是保证代码质量、提升重构信心、降低维护成本的重要手段。

### 8.1 单元测试的基本原则 (AIR + BCDE)

- AIR 原则

  ：

  - **Automatic (自动化)**：测试用例必须自动执行，不能有人工干预。
  - **Independent (独立性)**：用例之间互不依赖，执行顺序无关。
  - **Repeatable (可重复)**：在任何环境（本地、CI/CD）下都能稳定运行，不受外部因素（网络、时间、数据）影响。

- BCDE 原则

  ：

  - **Border (边界值)**：测试循环边界、特殊取值、空值等。
  - **Correct (正确输入)**：验证正常路径的预期结果。
  - **Design (设计文档)**：结合设计文档编写测试。
  - **Error (错误输入)**：验证异常路径、非法输入的处理。

### 8.2 单元测试覆盖率

- **粗粒度**：类覆盖、方法覆盖（意义不大，容易造假）。

- 细粒度

  ：

  - **行覆盖 (Line Coverage)**：语句是否被执行。
  - **分支覆盖 (Branch Coverage)**：判定真假分支是否都覆盖。
  - **条件判定覆盖 (Condition Decision Coverage)**：每个条件的真假及判定的真假都覆盖。
  - **条件组合覆盖 (Multiple Condition Coverage)**：所有条件的组合情况都覆盖（工作量巨大）。
  - **路径覆盖 (Path Coverage)**：所有可能的执行路径都覆盖。

- **建议**：追求高质量的分支覆盖和条件判定覆盖，而非盲目追求100%行覆盖。

### 8.3 单元测试编写

- **框架选择**：推荐使用 **JUnit 5** (Jupiter) + **AssertJ** (流式断言) + **Mockito** (Mock对象)。

- 命名规范

  ：

  - 测试类：`被测类名Test`。
  - 测试方法：`should_预期结果_When_场景` 或 `test_方法名_场景`。
  - 示例：`shouldReturnUser_WhenUserIdIsValid`。

- 断言 (Assertions)

  ：

  - 使用 `Assertions.assertThat()` (AssertJ) 提供流式API，可读性更强。
  - 避免使用 `System.out.println` 验证结果。
  - 断言消息应清晰描述预期与实际。

- Mock 技术

  ：

  - 隔离外部依赖（DB, RPC, Redis）。
  - 模拟异常场景、超时场景。

- **数据驱动测试**：使用 `@ParameterizedTest` 和 `@CsvSource` 减少重复代码，覆盖多种输入组合。

## 第9章：代码规约

代码规约不仅是风格统一，更是团队协作、系统稳定和个人成长的基石。

### 9.1 代码规约的意义

- **提升沟通效率**：统一的标准消除“鸡同鸭讲”，降低代码审查和理解成本。

- **提升代码质量**：规避常见陷阱（如 NPE、并发问题、SQL注入），防患于未然。

- **培养工匠精神**：追求极致、卓越的代码情怀。

- 破除误区

  ：

  - 规约不是消灭创造力，而是规范基础，让创造力集中在业务逻辑和架构设计上。
  - 代码不仅是给编译器看的，更是给维护者（包括未来的自己）看的。
  - 没有一成不变的代码，规约需随技术演进更新。

### 9.2 如何推动落地

- **立法透明**：全员参与讨论，理解规则背后的原因（知其然，知其所以然）。

- 执法坚定

  ：

  - **工具化**：使用 IDE 插件（如 Alibaba Java Coding Guidelines）、SonarQube、CI/CD 扫描，自动化检查。
  - **人工审查**：对于无法自动化的规则（如索引设计、业务逻辑合理性），通过 Code Review 落实。
  - **奖惩机制**：将规约遵守情况纳入考核，树立标杆。

- **组织支持**：管理层重视，建立长效的代码文化，提供培训和支持。

### 9.3 手册纵览与成长

- **手册结构**：编程规约、异常日志、单元测试、安全规约、数据库规约、工程结构、设计规约。

- 约束等级

  ：

  - **强制**：必须遵守，否则可能导致故障或严重性能问题。
  - **推荐**：强烈建议遵守，有助于提升代码质量和团队协作。
  - **参考**：可根据实际情况灵活处理。

- 个人成长建议

  ：

  - **扎实基础**：深入理解计算机基础、JVM、并发、数据结构。
  - **学以致用**：将理论知识应用到实际项目中，解决具体问题。
  - **持续反思**：定期复盘，总结教训，优化代码。
  - **开放心态**：勇于接受批评，向优秀者学习，分享知识。
  - **技术情怀**：保持对技术的热爱，追求卓越，享受编程的乐趣。

2. **底层决定上层**：深入理解计算机基础（二进制、内存、网络）和 JVM 原理，才能写出高性能、稳定的代码。
3. **并发需谨慎**：多线程编程复杂且易错，应优先使用 JUC 包提供的高级组件（如 `ConcurrentHashMap`, `ThreadPoolExecutor`），避免手动加锁。
4. **集合选对型**：根据场景选择合适的集合（`ArrayList` vs `LinkedList`, `HashMap` vs `TreeMap` vs `ConcurrentHashMap`），注意初始容量和线程安全。
5. **异常要处理**：区分受检/非受检异常，合理捕获和抛出，记录完整日志，便于排查问题。
6. **测试保质量**：单元测试是代码质量的最后一道防线，应遵循 AIR 原则，追求高覆盖率和高有效性。
7. **成长无止境**：程序员应从“码农”向“工程师”、“架构师”转变，不仅关注代码实现，更关注系统设计、业务价值和持续学习。
