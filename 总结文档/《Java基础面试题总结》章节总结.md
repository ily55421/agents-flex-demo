## Java基础篇

### 1. 核心论点
-   **本章主要试图回答或解决什么问题？** 系统梳理Java语言核心机制、集合框架、并发编程及JVM底层原理中的高频面试考点，帮助开发者建立扎实的基础知识体系。
-   **作者在本章最核心的一句话观点是什么？** Java基础不仅是语法的使用，更是对内存模型、数据结构设计哲学（如HashMap扩容机制）及并发安全本质的深刻理解。

### 2. 关键概念/事件
-   **值传递与引用传递：** Java本质上只有值传递；基本类型传递值的副本，引用类型传递对象地址的副本，而非对象本身。
-   **String不可变性设计：** String被final修饰且内部char数组私有，保证了线程安全、哈希码缓存及常量池复用，是Java安全与性能优化的基石。
-   **HashMap底层演进：** JDK1.7采用数组+链表，存在多线程死循环风险；JDK1.8引入红黑树优化哈希冲突查询效率，并将长度设计为2的幂次方以利用位运算替代取模。
-   **动态绑定与多态：** 除private/static/final方法外，Java通过运行时动态绑定实现多态，这是设计模式与框架解耦的核心机制。
-   **四种引用类型：** 强、软、弱、幻象引用定义了对象在GC时的不同可达性状态，直接影响内存敏感场景下的对象生命周期管理。

### 3. 逻辑推演/叙事脉络
本章采用“概念辨析→源码级原理→实战陷阱”的递进逻辑展开。首先从语言特性（面向对象、平台无关性）入手，确立Java的设计哲学；随后深入核心API（String、Object、Collection），通过对比equals/hashCode契约、ArrayList/LinkedList底层差异等，揭示API设计背后的权衡；接着进入并发与JVM深水区，解析HashMap死循环成因、ConcurrentHashMap分段锁/CAS机制及引用类型对GC的影响；最后回归到编译与运行机制，阐明静态绑定与动态绑定的区别，完成从代码编写到运行时行为的完整认知闭环。

### 4. 经典金句/数据
> “如果两个对象的 equals 相等，那么 hashCode 必须相同；如果两个对象 equals 不相等，那么 hashCode 也有可能相同。”

-   **byte取值范围：** -128 ~ 127（补码表示，-0归为-128）。
-   **Integer缓存池：** 默认缓存 -128 ~ 127，可通过 `-XX:AutoBoxCacheMax` 调整上限。
-   **HashMap扩容阈值：** 链表长度 > 8 时转红黑树（JDK1.8+）。
-   **UTF-8编码：** 变长编码，使用1-4字节表示Unicode字符，向下兼容ASCII。
