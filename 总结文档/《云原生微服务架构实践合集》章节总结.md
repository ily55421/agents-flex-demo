## 第1部分：掌门教育云原生落地实践

### 1. 核心论点
- **问题**：传统微服务架构在向云原生转型过程中，如何解决注册中心高可用、多注册中心同步容灾、以及灰度发布与全链路监控的落地难题？
- **观点**：通过构建基于 Spring Cloud Alibaba、Nacos、Sentinel 的 Solar 云原生框架，并结合 Kubernetes 容器化部署，实现服务治理的标准化、自动化与高可用性，特别是通过 Nacos-Eureka Sync 解决异构注册中心迁移痛点。

### 2. 关键概念/事件
- **Nacos Server 高可用部署**：采用 8C16G 三台集群部署，支持近 660 个服务瞬间从 Eureka 同步至 Nacos，CPU 仅增长 3%，验证了其高性能与低资源消耗。
- **Nacos-Eureka Sync 双向同步**：实现 Nacos 与 Eureka 之间的高可用双向同步和容灾。通过一致性 Hash 分片路由同步任务，支持节点宕机故障转移与自动恢复。
- **Solar 云原生微服务框架**：基于 Spring Cloud Alibaba 整合，内置多环境域名（DEV/FAT/UAT/PROD），支持跨注册中心调用的蓝绿灰度发布，并通过 Java Agent 解决异步调用上下文丢失问题。
- **Solar Sentinel SDK 增强**：深度集成 Apollo 配置中心，将限流熔断埋点输出至 SkyWalking，支持灰度蓝绿发布指标的熔断扩展及网关流控。
- **Kubernetes 容器化实践**：采用阿里云 Terway CNI 网络方案，实现 Pod IP 与 Node IP 处于同一平面，简化网络模型。

### 3. 逻辑推演/叙事脉络
本章首先介绍 Nacos Server 的落地实践，通过压测数据证明其性能优势；接着重点阐述从 Eureka 迁移至 Nacos 过程中的核心组件“Nacos-Eureka Sync”的设计与灾难演练，证明其高可用性；随后详细介绍自研的 Solar 微服务框架如何封装 Nacos 和 Sentinel，实现业务无感知的多环境隔离、灰度发布及全链路监控；最后简述了基于 Kubernetes 的容器化网络方案。整体遵循“基础设施落地 -> 迁移工具保障 -> 应用框架封装 -> 底层容器支撑”的技术栈分层逻辑。

### 4. 经典金句/数据
> “将近 660 个服务（非实例数）瞬间从 Eureka Server 同步到 Nacos Server，CPU 增长 3%... 内存增长到 72%，归因为云原生微服务框架里内置较多的元数据。”

> “极限灾难演练，9 台挂掉 8 台，剩 1 台也能抗住，故障转移，同步正常。”

## 第2部分：爱奇艺在 Dubbo 生态下的微服务架构实践

### 1. 核心论点
- **问题**：在大规模微服务场景下，如何优化 Dubbo 的性能、安全性及可观测性，并实现多可用区（AZ）的高可用部署？
- **观点**：通过自研 Dubbo SDK 增强认证、负载均衡与监控能力，结合 Nacos 作为注册中心替代 ZooKeeper 以提升性能，并利用 Sentinel 实现细粒度的流量治理，构建高可用、可观测的微服务架构。

### 2. 关键概念/事件
- **Dubbo SDK 增强**：
    - **安全认证**：基于 hmac-sha1 实现服务间认证，支持 HTTPS 传输。
    - **就近访问负载均衡**：正常情况下优先同 AZ 访问，故障时跨 AZ 访问，降低延迟并提高容灾能力。
- **注册中心选型对比（Nacos vs ZooKeeper）**：数据显示，使用 Nacos 后 QPS 从 7.2k/s 提升至 19.8k/s，RT 从 22.2ms 降至 6.1ms，ZK RT 从 41ms 降至 8ms，显著提升了系统性能。
- **Nacos 高可用架构**：采用多可用区（AZ-1, AZ-2, AZ-3）部署，每个 AZ 内部署 Nacos 集群并通过 L7 LB 暴露，后端共享 MySQL 主从集群存储数据。
- **Sentinel 流量治理**：
    - **热点参数限流**：针对特定参数（如用户 ID）进行 QPS 限制，区分热点与非热点流量。
    - **熔断降级**：基于响应时间（RT）或异常比例进行服务降级。
    - **监控集成**：通过 Micrometer API 将指标暴露给 Prometheus，并在 Grafana 展示。

### 3. 逻辑推演/叙事脉络
本章首先回顾 Apache Dubbo 的发展历程及爱奇艺的贡献；接着深入讲解自研 Dubbo SDK 的核心功能，包括安全认证和基于 AZ 的智能负载均衡；随后通过性能对比数据论证从 ZooKeeper 迁移至 Nacos 的必要性与收益，并展示 Nacos 的多 AZ 高可用架构；最后介绍如何集成 Sentinel 实现精细化的流量控制与监控，形成完整的微服务治理闭环。

### 4. 经典金句/数据
> “QPS: 7.2k/s -> 19.8k/s; RT: 22.2ms -> 6.1ms (Nacos 相比 ZK 的性能提升数据)”

> “正常情况优先就近访问，故障情况进行跨 AZ 访问。”

## 第3部分：携程微服务框架实践及思考

### 1. 核心论点
- **问题**：面对 HTTP 与 TCP 协议的局限性、网关兼容性差、移动端支持不足等问题，如何演进微服务框架以支持云原生、Service Mesh 及多语言互通？
- **观点**：从私有协议 CDubbo 演进至标准 Dubbo 2.7+，通过统一 Filter、配置与序列化机制，解决异步服务、线程模型优化及多协议兼容问题，最终向 Service Mesh 架构过渡，实现标准化与解耦。

### 2. 关键概念/事件
- **框架演进历程**：ESB -> SOA Net -> SOA Java -> CDubbo (Protobuf Stream) -> Dubbo 2.7.3 -> Service Mesh。
- **Dubbo 升级动机与收益**：
    - **动机**：支持异步服务、分离注册/元数据/配置中心、解决 HTTP/TCP 连接重置问题。
    - **收益**：线程数量降低 60%，编译时暴露不兼容问题，运行时无异常，测试覆盖率高达 93%。
- **关键问题解决**：
    - **异步服务 Trace**：解决异步调用链路跟踪断裂问题。
    - **线程池共享**：优化线程模型，减少资源消耗。
    - **网关兼容性**：解决网关依赖解包性能差、绑定序列化器的问题，推动协议标准化。
- **未来方向**：
    - **标准化**：采用标准传输协议，支持 POJO 与 ProtoBuf 对象。
    - **互通性**：兼容 gRPC，实现多语言互通。
    - **Mesh 化**：将治理能力下沉至 Sidecar，实现进程解耦。

### 3. 逻辑推演/叙事脉络
本章首先分析现有架构（HTTP/TCP）的痛点，如连接重置、网关不友好等；接着回顾携程微服务框架的演进历史，重点阐述从 CDubbo 升级至开源 Dubbo 2.7 的决策依据、实施过程及显著成果（性能提升、故障率降低）；随后指出当前 Dubbo 在网关、移动端及多语言支持上的局限；最后提出向 Service Mesh 演进的路径，强调标准化、协议互通及治理能力下沉的重要性。

### 4. 经典金句/数据
> “线程数量降低 60%... 迄今为止 0 故障。”

> “标准化、进程解耦、下沉... 主流语言 SDK 不可少，标准的传输协议，扩展性，标准 API。”

## 第4部分：下一代高性能云原生消息队列-Apache RocketMQ

### 1. 核心论点
- **问题**：在云原生时代，消息队列如何满足高 SLA、弹性伸缩、低成本及标准化的需求？RocketMQ 如何通过架构演进保持核心竞争力？
- **观点**：RocketMQ 通过存算分离、DLedger 强一致复制模型、Connector 生态扩展以及对 OpenMessaging 标准的支持，演进为云原生通信基础设施，提供高可用、高性能且易于集成的消息服务。

### 2. 关键概念/事件
- **云原生消息队列定义**：具备高 SLA、弹性化（自动扩缩容）、多样性（丰富生态）、易用性（开箱即用）和低成本特征的通信基础设施。
- **RocketMQ 核心特性**：
    - **事务消息**：通过半消息、本地事务执行、回查机制保证分布式事务最终一致性。
    - **消息轨迹**：独立存储轨迹数据，支持发送/订阅全链路追踪，便于问题排查。
    - **存储模型**：CommitLog 顺序写 + ConsumerQueue 索引，利用 PageCache 与零拷贝技术提升性能。
- **高可用架构演进**：
    - **Master-Slave**：传统主从架构，支持同步/异步复制。
    - **DLedger 模式**：基于 Raft 协议的强一致复制模型，解决主从切换数据丢失问题，支持并行复制优化性能。
    - **Jepsen 验证**：通过 Jepsen 测试验证 DLedger 在分区、节点崩溃等故障下的线性一致性。
- **生态扩展**：
    - **Spring 整合**：提供 RocketMQTemplate 与注解驱动开发。
    - **Connector**：构建数据流转引擎，支持 MySQL、Mongo、Redis、Kafka 等源/目的端的数据同步。
    - **Knative 支持**：作为 Eventing Channel，融入 Serverless 生态。

### 3. 逻辑推演/叙事脉络
本章首先定义云原生消息队列的标准与演进方向；接着详细解析 RocketMQ 的核心竞争力，包括事务消息、消息轨迹、存储模型及高可用架构（重点介绍 DLedger 的原理与性能优化）；随后展示 RocketMQ 丰富的社区生态，如 Spring 整合、Connector 数据流转平台及对 Knative 的支持；最后展望 RocketMQ 完全 CP 模式化及全面支持 OpenMessaging 标准的未来规划。
