## 第1章：基础概念
### 核心论点
- **解决的问题**：什么是 Docker 及其核心组成部分？
- **核心观点**：Docker 是轻量级容器产品，能将代码和依赖环境打包在一起，实现“一次构建，到处运行”，不依赖于宿主机软件环境。

### 关键概念/事件
- **TCC (TianChi Computing)**：天池竞赛计算平台的简称，用于 Docker 提交模型评估。
- **镜像 (Image)**：代码和环境打包后的产物，类似于只读模板。
- **Registry (仓库)**：存储镜像的云端服务（类似网盘/Git），支持版本管理和分享，如阿里云容器镜像服务。
- **容器 (Container)**：运行起来的镜像实例，实质是进程；代码运行结束，进程结束，容器随之消失。

### 逻辑推演/叙事脉络
本章首先定义了 TCC 平台背景，随后引入 Docker 的核心价值（环境隔离与便携性）。接着详细拆解了 Docker 的三要素：镜像（静态包）、Registry（存储与管理）、容器（动态运行实例），建立了用户对 Docker 基本架构的认知。

### 经典金句/数据
> “docker作为虚拟机领域成熟的轻量化容器产品，可以轻松的将代码和所依赖的整个环境（可以理解为包含整个操作系统）都打包在一起，不依赖于软件环境。”

## 第2章：环境篇
### 核心论点
- **解决的问题**：如何在不同操作系统上安装 Docker 并掌握基础操作命令？
- **核心观点**：掌握安装、拉取、运行、查看、提交、构建及清理等基础命令是使用 Docker 的前提；建议养成使用 Dockerfile 构建镜像的习惯，避免依赖 `commit`。

### 关键概念/事件
- **安装方式**：
    - **Linux**：脚本一键安装；若需 GPU 支持，需额外安装 `nvidia-container-toolkit`。
    - **Windows**：下载 Docker Desktop 或使用 winget 安装。
    - **macOS**：使用 Homebrew Cask 或手动下载安装 Docker Desktop。
- **基础命令体系**：
    - `docker pull`：拉取镜像。
    - `docker run`：运行容器（常用参数 `-it` 交互式, `--rm` 退出即删, `-v` 挂载卷, `--gpu` 调用显卡）。
    - `docker ps` / `docker images`：查看运行容器和本地镜像。
    - `docker exec`：进入运行中的容器调试。
    - `docker commit`：保存容器修改为镜像（不推荐作为常规构建手段，仅用于保留现场）。
    - `docker build`：基于 Dockerfile 构建镜像（推荐方式）。
    - `docker tag/push/rmi/rm`：打标、推送、删除镜像/容器。
- **Dockerfile 规范**：指定基础镜像 (`FROM`)、安装依赖 (`RUN`)、添加文件 (`ADD`)、设置工作目录 (`WORKDIR`)、定义启动命令 (`CMD`)。
- **最佳实践**：使用国内源加速、必备包预装、版本标签管理、避免臃肿镜像。

### 逻辑推演/叙事脉络
本章按“安装 -> 基础命令 -> 进阶操作 -> 最佳实践”的逻辑展开。首先分平台指导安装，特别强调了 Linux 下 GPU 支持的配置。随后系统介绍了常用命令，对比了 `commit` 与 `Dockerfile` 的优劣，强烈推荐使用 Dockerfile 进行标准化构建。最后提供了调试技巧、镜像优化建议及海外选手的网络加速方案。

### 经典金句/数据
> “建议 commit 仅作为保留现场的手段，然后通过修改 dockerfile 构建镜像。”
> “养成使用 Dockerfile 的习惯，不要依赖于 commit。”

## 第3章：实践篇
### 核心论点
- **解决的问题**：如何从零开始创建一个镜像并提交到阿里云容器镜像仓库？
- **核心观点**：通过注册阿里云账号、创建命名空间与仓库、本地登录、编写代码与 Dockerfile、构建并推送镜像，完成完整的闭环实践。

### 关键概念/事件
- **仓库创建流程**：注册阿里云容器镜像服务 -> 创建唯一命名空间 -> 创建本地仓库 -> 获取公网地址。
- **本地登录**：使用 `docker login` 配合用户名密码登录 registry。
- **案例实战（GPU版练习赛）**：
    - **代码结构**：`main.py` (逻辑代码), `run.sh` (入口脚本), `Dockerfile` (构建描述)。
    - **Dockerfile 示例**：基于 PyTorch 官方镜像，安装 numpy，添加代码，设置工作目录，指定 `run.sh` 为启动命令。
    - **构建与推送**：`docker build -t <registry>/<namespace>/<repo>:<tag> .` 然后 `docker push`。

### 逻辑推演/叙事脉络
本章以天池 GPU 练习赛为例，手把手演示全流程。首先指导用户在阿里云控制台创建仓库并获取凭证；接着展示了一个典型的 AI 任务代码结构（Python 脚本 + Shell 入口 + Dockerfile）；最后演示了如何在命令行执行构建和推送操作，并简要提及了在天池页面提交镜像后的状态查看。

### 经典金句/数据
> “镜像命名根据自己申请的仓库 registry 来，可以省去 tag 步骤直接上传，保持本地镜像清洁。”

## 第4章：天池竞赛规范
### 核心论点
- **解决的问题**：在天池大赛中提交 Docker 镜像有哪些特定的规则、限制和注意事项？
- **核心观点**：严格遵守数据集挂载路径、无网络环境、超时限制及入口文件规范；最终成绩以端到端完整代码运行为准，严禁作弊或使用非官方外部数据。

### 关键概念/事件
- **数据挂载规范**：
    - `/tcdata`：只读，存放训练集+测试集。
    - `/external_data`：只读，存放官方允许的预训练权重等外部数据。
    - `/myspace`：读写，持久化存储空间（仅用于调试中间结果，最终提交不可依赖此处的中间文件）。
- **运行入口**：必须以工作目录下的 `run.sh` 为唯一入口，进程结束即视为程序结束。
- **网络限制**：线上环境**无网络**，镜像内禁止任何网络请求操作。
- **超时机制**：
    - **正常超时**：超过规定时间，成绩无效但可查看日志。
    - **严重超时**：超过规定时间+30~60min，强制 Kill 进程。
    - **流评测超时**：单次 Infer 响应时间受限。
- **代码审核**：取排行榜最优成绩对应的镜像进行审核，必须包含完整代码，否则淘汰。
- **其他规范**：共享内存默认为内存一半；自定义镜像需安装 `curl` 且不能用 `ENTRYPOINT`。

### 逻辑推演/叙事脉络
本章详细列出了天池竞赛的“红线”与“规范”。从数据读取路径、外部数据使用、持久化存储的限制，到程序入口、网络禁令、超时判定标准，逐一进行了说明。特别强调了日常调试（可联网、可存中间结果）与最终提交（端到端、无网、完整代码）的区别，警示选手避免因违规被取消名次。

### 经典金句/数据
> “大赛一律无网络链接，切记镜像内不要有网络操作否则会导致线上运行时由于无网络触达而导致程序卡住。”
> “最终排行榜最优成绩对应提交需是端到端完整代码运行得出，不能使用存储空间的中间结果。”

## 第5章：docker&大赛
### 核心论点
- **解决的问题**：如何利用 Docker 技巧提高大赛效率、调试问题及应对常见异常？
- **核心观点**：本地模拟线上环境调试是关键；理解提交状态、日志分析及超时逻辑有助于快速排查问题；掌握可视化、后台运行等高级技巧可提升开发体验。

### 关键概念/事件
- **本地调试技巧**：
    - 使用 `-v` 挂载本地数据模拟 `/tcdata`。
    - 使用 `-m` 限制内存，模拟线上资源限制。
    - 注意本地与线上驱动/CUDA 版本差异。
- **状态与日志分析**：
    - **Waiting/Init**：机器库存动态调整，通常不超过 30min。
    - **Creating/ImageBackoff**：镜像拉取失败，检查链接、账号密码。
    - **日志为空/网络错误**：可能遇到坏节点，重新提交即可，不扣次数。
- **提交次数逻辑**：仅当状态进入 `running` 时才扣除提交次数。
- **高级技巧**：
    - **可视化**：挂载 `/tmp/.X11-unix` 共享宿主机屏幕，或使用 `ai-hub` 发送图片至微信。
    - **后台运行**：使用 `-d` 参数。
    - **容器通信**：使用 `--link`。
    - **权限问题**：工作目录通常可读写的，或通过 `chmod 777` 解决。
- **海外选手优化**：利用阿里云 ACR 自动构建功能，避免大镜像跨国上传慢的问题。

### 逻辑推演/叙事脉络
本章侧重于“实战经验”与“Troubleshooting”。首先对比本地与线上环境的差异，给出本地模拟建议。接着深入解析竞赛平台的各种状态含义及日志查看方法，帮助选手定位卡顿或失败原因。随后介绍了一些提升效率的高级 Docker 用法（可视化、后台、通信）。最后针对海外用户和网络异常等特殊情况给出了具体解决方案。
