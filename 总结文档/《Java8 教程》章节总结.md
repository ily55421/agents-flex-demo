## 第1章：Java8 - 介绍
### 核心论点
- 本章旨在概述 Java 8 发布背景及其最重要的新特性。
- 核心观点是 Java 8 引入了 Lambda 表达式、默认方法、Stream API 和新的日期时间 API，这些特性显著改变了 Java 编程的方式。

### 关键概念/事件
- **Lambda 表达式**：一种匿名函数，允许将功能作为方法参数传递，简化代码编写。
- **默认方法（Default Methods）**：允许在接口中提供方法的默认实现，保持向后兼容性。
- **Stream API**：提供了一种高效处理集合数据的机制，支持过滤、转换等聚合操作。
- **新的日期时间 API（JSR-310）**：引入了 `LocalDate`、`LocalTime`、`LocalDateTime` 等类，替代过时的 `Date` 类。

### 逻辑推演/叙事脉络
作者首先指出 Java 8 于 2014 年初发布，重点讨论了 Lambda 表达式。随后简要介绍了其他重要功能：默认方法用于增强接口而不破坏兼容性；Stream API 用于简化集合处理；新的日期时间 API 解决了旧日期类的缺陷。最后通过简短的代码示例展示了 Stream 的基本用法和新日期类的实例化。

### 经典金句/数据
> “Java8 在 2014 年初发布，在 Java8 中大家讨论最多的特性是 lambda 表达式。”

## 第2章：Java8 - lambda表达式
### 核心论点
- 本章详细解释 Lambda 表达式的定义、语法及使用规则。
- 核心观点是 Lambda 表达式是匿名函数，其语法简洁，可根据上下文推断参数类型，适用于函数式接口。

### 关键概念/事件
- **Lambda 语法**：`(parameters) -> expression` 或 `(parameters) -> { statements; }`。
- **参数推断**：可以显式声明参数类型，也可以由编译器从上下文推断。
- **单参数简写**：当只有一个参数且类型可推断时，括号可以省略。
- **函数体规则**：单行语句可省略大括号和 return 关键字；多行语句需使用大括号。

### 逻辑推演/叙事脉络
本章首先定义了 Lambda 表达式为没有名称的匿名函数。接着详细列举了编写 Lambda 表达式的五条规则：参数数量、类型推断、括号使用、单参数简写以及函数体的语句限制。通过 `(x, y) -> x + y` 等典型示例，说明了其在不同上下文中的多态性（如整数相加或字符串拼接）。

### 经典金句/数据
> “lambda 表达式（或者函数）只是一个匿名函数，即一个没有名称也没有标识符的函数。它们都被写在你需要使用的地方，通常作为其他函数的参数。”

## 第4章：Java8 - 默认方法
### 核心论点
- 本章深入探讨接口中默认方法的定义与作用。
- 核心观点是默认方法允许在不破坏现有实现类二进制兼容性的前提下，向接口添加新功能。

### 逻辑推演/叙事脉络

### 经典金句/数据

## 第5章：Java8 - 函数式接口
### 核心论点
- 本章定义函数式接口及其注解 `@FunctionalInterface` 的作用。
- 核心观点是函数式接口只能有一个抽象方法，但可以有多个默认方法或重写 Object 类的方法。

### 关键概念/事件
- **SAM 接口**：Single Abstract Method Interface，即单一抽象方法接口。
- **@FunctionalInterface 注解**：编译期检查，确保接口符合函数式接口规范。
- **Object 方法例外**：重写 `toString`、`equals` 等 Object 类方法不计入抽象方法数量。

### 逻辑推演/叙事脉络
作者首先定义了函数式接口为只包含一个抽象方法的接口。介绍了 `@FunctionalInterface` 注解的作用，即强制编译器检查接口是否符合规范。随后指出，即使不加注解，只要满足条件也是有效的函数式接口。最后特别说明，重写 Object 类的方法不会破坏函数式接口的定义，并通过代码示例验证了这一规则。

### 经典金句/数据
> “Functional Interface 也被称为单一抽象方法的接口（SAM接口）。就像它的名字一样，它只能有一个抽象方法。”

## 第6章：Java8 - Optional
### 核心论点
- 本章介绍 `Optional` 类如何解决空指针异常问题。
- 核心观点是 `Optional` 是一个容器对象，可能包含也可能不包含非空值，旨在设计更清晰的 API 而非简单替换 null。

### 关键概念/事件
- **Null 的问题**：返回 null 容易导致调用者忽略检查，引发 `NullPointerException`。
- **Optional 创建**：`Optional.empty()`、`Optional.of()`（非空）、`Optional.ofNullable()`（可为空）。
- **值处理**：`ifPresent()`、`orElse()`、`orElseThrow()`、`filter()`。
- **使用限制**：不建议用于领域模型、DTO、方法参数或构造函数参数，因不可序列化。

### 逻辑推演/叙事脉络
本章首先探讨了 Null 引用的历史及其带来的“十亿美元错误”。接着分析了返回 null 的弊端，引出 `Optional` 作为解决方案。详细介绍了创建 Optional 对象的三种方式，以及如何通过 `ifPresent`、`orElse` 等方法安全地获取值或提供默认值。还讲解了 `filter` 方法的用法。最后明确了 `Optional` 的内部实现原理、适用场景（主要用于返回值）和不适用场景（如 DTO），强调其目的是提升 API 的可读性和安全性。

### 经典金句/数据
> “Optional 存在的目的不是为了替代我们代码中简单的 null 引用，而是帮助我们设计更清晰明了的 API... 如果你想让你的程序通过编译，你就不得不去考虑值为 null 的情况。”

## 第8章：Java8 - 日期时间API的改变
### 核心论点
- 本章介绍 Java 8 新的日期和时间 API（JSR-310）。
- 核心观点是新 API 提供了不可变、线程安全且易于理解的日期时间类，替代了旧的 `Date` 和 `Calendar`。

### 关键概念/事件
- **本地日期时间类**：`LocalDate`（日期）、`LocalTime`（时间）、`LocalDateTime`（日期时间），不含时区。
- **带时区类**：`OffsetDate`、`OffsetTime`、`OffsetDateTime`，结合 `ZoneId` 使用时区。
- **瞬时时间**：`Instant`，表示时间戳，精度为纳秒。
- **时间段**：`Duration`（基于时间，如秒、分）、`Period`（基于日期，如天、月、年）。

### 逻辑推演/叙事脉络
作者指出旧的 `Date` 类已过时。介绍了新的三大本地类及其不带时区的特性。随后介绍了处理时区的偏移类和 `ZoneId`。接着讲解了 `Instant` 用于表示时间戳，以及 `Duration` 和 `Period` 分别用于处理机器时间间隔和人类日期间隔。通过代码示例展示了这些类的初始化和基本运算。

### 经典金句/数据

## 第9章：Java8 - Stream示例
### 核心论点
- 本章全面介绍 Stream API 的概念、构建方式及核心操作。
- 核心观点是 Stream 是对集合数据的抽象，支持串行和并行处理，通过流水线操作实现声明式数据处理。

### 关键概念/事件
- **Stream vs Collection**：Stream 不存储数据，按需计算，支持懒加载和并行；Collection 存储所有数据。
- **构建 Stream**：`Stream.of()`、`collection.stream()`、`Stream.generate()`、`String.chars()` 等。
- **中间操作**：`filter()`、`map()`、`sorted()`，返回 Stream，支持链式调用。
- **终端操作**：`forEach()`、`collect()`、`match()`、`count()`、`reduce()`，触发执行并返回结果。
- **短路操作**：`anyMatch()`、`findFirst()`，满足条件即停止处理。
- **并行 Stream**：使用 `parallelStream()` 轻松启用并行处理。

### 逻辑推演/叙事脉络
本章首先区分了 Stream 和 Collection 的本质差异，强调 Stream 的概念性和惰性。接着列举了多种构建 Stream 的方法。随后详细讲解了中间操作（过滤、映射、排序）和终端操作（遍历、收集、匹配、计数、归约），并通过 `memberNames` 列表的示例串联这些操作。最后介绍了短路操作以提高效率，以及通过 `parallelStream()` 实现并行处理的简便性，强调了内部迭代的优势。

### 经典金句/数据
> “Streams 可以被定义为元素集合从源支持聚合操作... 流是概念上固定的数据结构，其中的元素需要根据需要计算。”

## 第20章：Java8 - 内部迭代 VS 外部迭代
### 核心论点
- 本章对比传统的外部迭代与 Java 8 引入的内部迭代。
- 核心观点是内部迭代将控制权交给库，允许优化（如并行、懒加载），使代码更聚焦于业务逻辑而非遍历机制。

### 关键概念/事件
- **外部迭代**：使用 `Iterator` 或 `for-each`，用户控制遍历过程，顺序执行，难以优化。
- **内部迭代**：使用 `forEach` 或 Stream，库控制遍历，用户只提供操作逻辑，支持并行和短路。
- **关注点分离**：内部迭代分离了“做什么”和“怎么做”。

### 逻辑推演/叙事脉络
作者首先展示了使用 `for-each` 和 `Iterator` 进行外部迭代的传统代码，指出其顺序性和性能优化的局限性。随后展示了使用 `forEach` 的内部迭代代码，强调其简洁性。最后论证了内部迭代的优势：库可以决定最佳执行策略（如并行、乱序），用户只需关注数据处理逻辑，从而提升代码可读性和潜在性能。

### 经典金句/数据
> “外部迭代将‘干什么’和‘怎么做’混杂在一起，内部迭代则通过库来控制‘怎么做’，而将‘干什么’留给用户去实现。”
