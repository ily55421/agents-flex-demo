## 第1章：混合工程
### 核心论点
本章主要解决已有大型 Native 工程如何无缝接入 Flutter 并保证开发效率的问题。核心观点是通过“远程依赖抽取”和“混合栈框架”实现 Native 与 Flutter 的解耦，使两者能并行开发与构建。

### 关键概念/事件
- **混合工程研发结构**：Flutter 作为模块集成到 Native 工程中，通过 Pod（iOS）或 AAR（Android）依赖。
- **Native 启动调试**：介绍了在不使用 flutter_tools 全流程构建的情况下，如何通过 Observatory 远程连接实现 Dart 代码的调试与热重载。
- **依赖抽取方案**：将 Flutter 的引擎、业务代码、插件编译产物打包成远程 SDK（AAR/Pod），供 Native 工程直接依赖，解除对 Flutter 环境的强依赖。
- **flutter-boot 脚手架**：闲鱼开源的工程化工具，用于快速搭建混合工程，自动处理工程配置与混合栈集成。
- **FlutterBoost 混合栈**：第二代混合技术方案，采用共享引擎模式，解决页面栈管理与 Native/Flutter 页面嵌套问题。

### 逻辑推演/叙事脉络
本章首先分析了混合工程的背景与痛点（构建慢、环境配置复杂），然后提出“Standalone 模式”与“Flutter 模式”的概念。接着详细阐述了如何通过脚本自动化抽取 Flutter 依赖并发布到远程仓库，实现持续集成。随后介绍了 flutter-boot 如何简化这一流程。最后，针对页面导航问题，对比了 Google 官方方案与闲鱼的 FlutterBoost 方案，论证了共享引擎模式的优越性。

## 第2章：能力增强
### 核心论点
本章探讨如何通过原生能力扩展 Flutter 的功能边界，特别是解决多媒体渲染性能与富文本排版难题。核心观点是利用 Flutter 的 Platform Channel 机制与底层图形接口（Skia/OpenGLES）进行深度定制。

### 关键概念/事件
- **Platform Channel**：Flutter 与 Native 通信的桥梁，支持 MethodChannel（方法调用）与 EventChannel（事件流）。
- **外接纹理（External Texture）**：一种高性能的图像传输机制，通过共享 GPU Texture ID 避免内存拷贝，解决视频/相机预览的性能瓶颈。
- **相册组件**：基于 MVC 架构自研的高性能相册，利用 GPU 纹理缓存降低内存占用，解决大图加载与列表滑动卡顿问题。
- **富文本渲染**：通过 `ui.TextPainter` 与 `PlaceholderSpan` 实现复杂的图文混排，解决原生 RichText 组件能力不足的问题。

### 逻辑推演/叙事脉络
本章从基础的 Plugin 开发流程入手，讲解了电量获取等简单案例。随后深入到性能敏感场景，分析了 Flutter 默认渲染管线的局限性，提出了基于外接纹理的“同层渲染”方案。接着通过相册组件的案例，展示了如何利用 OpenGL 进行图片处理优化。最后，针对电商详情页的复杂排版需求，详细拆解了富文本组件的设计与实现代码。

### 经典金句/数据
> “Flutter 在与 Native 隔离的同时，也在 Flutter Engine 和 Native 之间竖立了‘一座大山’。” (p.55)
> “通过这种方式……数据都在 GPU 中传递，对于图片场景尤其适用。” (p.60)

## 第3章：业务架构设计
### 核心论点
本章重点解决大型 Flutter 应用的状态管理与代码组织问题。核心观点是通过 **Fish Redux** 框架，实现“集中式状态管理”与“组件化分治”的统一，同时利用 AOP（面向切面编程）解决框架侵入性问题。

### 关键概念/事件
- **Fish Redux**：闲鱼开源的组装式应用框架，基于 Redux 模式，核心要素包括 Component（组件）、Reducer（状态修改）、Effect（副作用/异步）与 View（UI）。
- **组件化分治**：将页面拆分为独立的 Component，每个 Component 拥有独立的 State 与逻辑，通过 Connectors 进行数据绑定与通信。
- **AspectD**：闲鱼开发的 Dart AOP 框架，基于编译期修改（Dill Transform），用于实现无侵入的代码注入（如埋点、自动化测试）。
- **动态模板渲染**：将 Dart 代码编译为 JSON 协议，在端侧解析渲染，实现 Flutter 的动态化能力。

### 逻辑推演/叙事脉络
本章首先回顾了闲鱼在状态管理上的演进（从原生 Redux 到 Fish Redux 的诞生），解释了为何需要将 UI 与逻辑分离。接着详细解析了 Fish Redux 的架构原理，包括数据流、组件通信与刷新机制。随后，针对开发效率与自动化测试痛点，引入了 AspectD 框架，讲解了其基于 Dill 文件修改的实现原理。最后，探讨了动态化方案，从 DSL 解析到高性能渲染引擎的优化（如 Layout 计算优化）。

### 经典金句/数据
> “Fish Redux 应运而生。在后续的应用中，闲鱼又发现业务组装以后的代码性能问题……” (p.73)
> “AspectD 的原理基于 Dill 变换。有了 Dill 操作，开发者可以自由地对 Dart 编译产物进行操作……” (p.105)

## 第4章：数据统计与性能
### 核心论点
本章旨在建立一套完整的 Flutter 性能监控与评估体系。核心观点是不能照搬 Native 的监控指标，而应深入 Flutter 渲染管线（UI & GPU TaskRunner），定制化采集 FPS、加载耗时与异常率。

### 关键概念/事件
- **埋点时机控制**：通过监听页面栈（NavigatorObserver）与组件可见性（OverlayEntry），精准捕获页面进入、离开与曝光事件。
- **FPS 监控原理**：利用 `WidgetsBinding` 监听 `handleBeginFrame` 与 `handleDrawFrame` 间隔，计算 UI 线程帧率。
- **高可用 SDK**：设计了分层架构（API -> Recorder -> Processor -> Uploader），实现数据采集与上报的解耦。
- **跨端性能对比**：通过与 React Native 的对比测试，展示了 Flutter 在低端机上的内存优势与帧率稳定性。

### 逻辑推演/叙事脉络
本章首先定义了用户行为埋点的标准（如页面进入/离开、曝光逻辑），解决了 Flutter 页面栈与 Native 不同步的问题。接着深入性能监控，分别阐述了流畅度（FPS）、加载耗时（首屏与可交互）以及异常率的采集算法。随后介绍了闲鱼高可用 SDK 的整体架构设计，强调了数据处理的管道化与可拓展性。最后，通过实测数据对比 Flutter 与 React Native 的性能差异，验证了 Flutter 的性能优势。

### 经典金句/数据
> “Native 的 FPS 检测方法并不适用于 Flutter。” (p.125)
> “在 Release 模式下，AOT 编译时长明显缩短很多，整体页面加载时长还是要优于 Weex。” (p.130)
> “Flutter 在低端机型上的起始内存和 React Native 几乎一致……带来更流畅的体验。” (p.143)

## 第5章：企业级应用实战
### 核心论点
本章总结了闲鱼在大规模应用 Flutter 过程中的架构演进与创新。核心观点是通过“混合工程 + 云端一体化”构建企业级研发体系，解决研发效率与业务复杂度之间的矛盾。

### 关键概念/事件
- **架构演进**：从单 Engine 共享到 FlutterBoost 多容器管理，再到 Fish Redux 的业务组件化。
- **研发智能化**：利用数据化与自动化（CI/CD）打通代码提交到打包测试的链路，减少人工干预。
- **云端一体化（Flutter + FaaS）**：使用 Dart 语言统一端侧与云侧技术栈，实现 Hot Reload 移植与业务闭环。

### 逻辑推演/叙事脉络
本章首先分析了 Flutter 带来的优势（跨端一致性、高性能）及面临的挑战（混合开发、内存压力）。接着回顾了闲鱼的架构演进史：如何解决页面栈混乱、如何优化图片视频内存。然后重点介绍了“研发智能化”实践，通过自动化工具链提升效率。最后，提出了“Flutter 与 FaaS 云端一体化架构”的愿景，论证了 Dart 作为服务端语言的可行性及其带来的研发模式变革。
