# 《面试题(Java建设者出品)》章节总结

## 目录说明

文档以“面试题”的形式组织，内容涵盖了Java、HTTP、MySQL、操作系统等多个技术领域的高频面试知识点。文档结构清晰，按技术栈分为“Java基础篇”、“HTTP篇”、“MySQL篇”、“操作系统篇”四大核心模块。每个模块下列举了一系列常见面试题，并对部分题目进行了详细的解答和原理分析。本总结严格按照文档提供的“篇章-题目-解答”结构进行梳理，将每个技术模块视为一个章节，对其下的核心面试题及答案要点进行结构化提炼。

## Java基础篇

### 核心论点

本章（模块）旨在解决Java开发工程师在面试中遇到的关于Java语言核心特性、集合、I/O、多线程、JVM等方面的问题。作者的核心观点是：深入理解Java的基本设计、内存模型、常用API及并发机制，是应对技术面试和进行高效开发的基础。

### 关键概念/事件

- 

  **Java的特性**：包括简单性、面向对象、平台无关性、解释性、多线程性、分布式、健壮性、高性能、安全性、动态性。

- 

  **值传递与引用传递**：在调用函数时，值传递是复制实际参数的值，形式参数的修改不影响实际参数；引用传递是传递对象的地址，形式参数的修改会影响实际参数。在Java中，所有参数传递本质上都是值传递，传递的是对象引用的拷贝。

- 

  **== 与 equals**：`==`对于基本类型比较值，对于引用类型比较内存地址是否相同；`equals`是Object类的方法，用于比较两个对象的内容是否相等，可以被重写。

- 

  **String不可变性**：String类被设计为final，其内部表示字符的char数组也是final的，一经创建，其值就不能被修改。任何看似修改的操作都会返回一个新的String对象。这种设计主要基于安全性、线程安全和作为HashMap键的哈希值缓存等考量。

- 

  **HashMap底层原理**：JDK1.8之前采用数组+链表，1.8之后引入了红黑树优化长链表的查询效率。其长度设计为2的幂次方是为了更高效地通过 `(n-1) & hash`计算数组下标，减少哈希碰撞。多线程下操作可能导致死循环，线程安全版本有`ConcurrentHashMap`、`Collections.synchronizedMap(new HashMap())`和 `Hashtable`。

### 逻辑推演/叙事脉络

本章首先从Java语言的整体特点切入，然后深入到最基本的变量传递机制和对象比较机制。接着，以`String`和`HashMap`这两个最核心的类为例，详细剖析了它们的设计原理、内存行为、线程安全问题及性能考量。在此基础上，扩展到集合框架（`ArrayList`、`LinkedList`、`Vector`、`HashSet`）、泛型、反射、I/O、多线程（`ConcurrentHashMap`）、异常处理、设计模式等多个核心领域。论证过程通常采用“问题 -> 定义/区别 -> 源码/原理分析 -> 应用场景/注意事项”的逻辑链条，并结合代码片段和内存图示进行说明。

### 经典金句/数据

> 要想真正理解的话，可以参考这篇文章: https://www.zhihu.com/question/31203609。简单理解的话就是：值传递是指在调用函数时将实际参数复制一份到函数中，这样的话如果函数对其传递过来的形式参数进行修改，将不会影响到实际参数；引用传递是指在调用函数时将对象的地址直接传递到函数中，如果在对形式参数进行修改，将影响到实际参数的值。

> String代表的是 Java中的字符串，String类比较特殊，它整个类都是被 final修饰的，也就是说，String不能被任何类继承，任何修改String字符串的方法都是创建了一个新的字符串。

> 如果在Java运行期间对同一个对象调用 hashCode 方法后，无论调用多少次，都应该返回相同的hashCode，但是在不同的 Java 程序中，执行 hashCode 方法返回的值可能不一致。... 如果两个对象 equals 不相等，那么 hashCode 也有可能相同，所以需要重写 hashCode 方法。

## HTTP篇

### 核心论点

本章（模块）旨在解答关于HTTP/HTTPS协议、TCP/UDP传输层、以及Web应用基础原理的面试问题。作者的核心观点是：理解HTTP协议的无状态、请求/响应模型，以及其与TCP、TLS/SSL协议的结合（即HTTPS），是构建和理解现代Web应用架构的关键。

### 关键概念/事件

- 

  **HTTP与HTTPS区别**：HTTPS = HTTP + TLS/SSL，在HTTP基础上增加了加密、身份认证和完整性保护。HTTP默认端口80，HTTPS默认端口443。HTTP是明文传输，HTTPS是密文传输。

- 

  **GET与POST区别**：

  - 

    GET请求参数在URL中，有长度限制，可被缓存、书签收藏，幂等，用于获取资源。

  - 

    POST请求参数在请求体中，无长度限制，不可被缓存，不幂等，用于提交数据。

- 

  **TCP三次握手与四次挥手**：三次握手（SYN, SYN-ACK, ACK）用于建立可靠连接；四次挥手（FIN-ACK, FIN-ACK）用于安全终止连接。确保了数据传输的可靠性和有序性。

- 

  **HTTP 1.0/1.1/2.0**：

  - 

    HTTP/1.0：短连接，无状态。

  - 

    HTTP/1.1：默认长连接（Keep-Alive），支持管道化，新增缓存控制头（如E-tag）。

  - 

    HTTP/2.0：二进制分帧，多路复用，头部压缩，服务端推送。

- 

  **URL输入到页面展示**：过程包括DNS解析、建立TCP连接、发送HTTP请求、服务器处理请求并返回响应、浏览器解析渲染页面、连接结束。

### 逻辑推演/叙事脉络

本章从HTTP协议的基本定义和其在网络分层模型中的位置讲起，首先辨析了HTTP与HTTPS的核心差异，引出安全性的重要。接着，深入到HTTP的方法（GET/POST）和其无状态特性及解决方案（Cookie/Session）。然后，向下延伸到传输层，对比TCP（可靠、面向连接）和UDP（不可靠、无连接），并详解了TCP建立和断开连接的“握手”与“挥手”过程。之后，纵向梳理了HTTP协议从1.0到2.0的演进与优化。最后，通过“从输入URL到页面展示发生了什么”这一问题，将DNS、TCP、HTTP、浏览器渲染等多个知识点串联起来，形成一个完整的Web请求生命周期全景图。

### 经典金句/数据

> 无状态协议(Stateless Protocol)就是指浏览器对于事务的处理没有记忆能力。... HTTP就是一种无状态的协议，他对用户的操作没有记忆能力。... 这其实不是 HTTP 做的事情，起作用的是一个叫做小甜饼(Cookie)的机制。它能够让浏览器具有记忆能力。

> 如果用现实生活来举例的话就是：小明-客户端 小红-服务端。小明给小红打电话，接通了后，小明说喂，能听到吗，这就相当于是连接建立。小红给小明回应，能听到，你能听到我说的话吗，这就相当于是请求响应。小明听到小红的回应后，好的，这相当于是连接确认。在这之后小明和小红就可以通话/交换信息了。

> TLS旨在为 Internet 提供通信安全的加密协议。TLS握手是启动和使用 TLS加密的通信会话的过程。... 在 TLS握手期间，Internet中的通信双方会彼此交换信息，验证密码套件，交换会话密钥。

## MySQL篇

### 核心论点

本章（模块）聚焦于数据库，特别是MySQL相关的核心面试题，涵盖存储引擎、事务、索引、SQL优化、查询执行过程等。作者的核心观点是：熟练掌握MySQL的InnoDB存储引擎特性、事务ACID与隔离级别、索引数据结构及优化策略，是保证数据一致性、完整性和系统高性能的基石。

### 关键概念/事件

- 

  **事务ACID**：

  - 

    原子性（Atomicity）：事务内的操作要么全成功，要么全失败。

  - 

    一致性（Consistency）：事务执行前后，数据库从一个一致性状态变到另一个一致性状态。

  - 

    隔离性（Isolation）：并发事务间相互隔离，防止脏读、不可重复读、幻读。

  - 

    持久性（Durability）：事务提交后，对数据的修改是永久性的。

- 

  **存储引擎MyISAM vs InnoDB**：

  - 

    MyISAM：不支持事务、外键，表级锁，支持全文索引，查询性能高。

  - 

    InnoDB：支持事务、外键，行级锁，支持聚簇索引，崩溃恢复能力强，MySQL 5.5后默认引擎。

- 

  **SQL执行顺序**：`FROM`-> `ON`-> `JOIN`-> `WHERE`-> `GROUP BY`-> `HAVING`-> `SELECT`-> `DISTINCT`-> `ORDER BY`-> `LIMIT`。理解此顺序对编写正确高效的SQL和优化至关重要。

- 

  **索引类型**：主要有B-Tree索引（最常用）、哈希索引（Memory引擎）、全文索引（MyISAM/InnoDB）、R-Tree索引（空间数据）。

- 

  **SQL优化经验**：避免`SELECT *`、为搜索字段建索引、避免在WHERE子句中对字段进行NULL判断或使用函数、选择合适的数据类型、使用EXPLAIN分析查询、考虑分库分表等。

### 逻辑推演/叙事脉络

本章首先对比了关系型与非关系型数据库的差异，为讨论MySQL设定背景。然后，核心围绕InnoDB存储引擎展开，详细阐述了其保证数据可靠性的四大事务特性（ACID）及不同隔离级别如何解决并发问题。接着，深入MySQL的内部架构，剖析一条SQL语句从连接到返回结果所经历的“连接器 -> 查询缓存 -> 分析器 -> 优化器 -> 执行器”完整流程，并解释了SQL语句的真正执行顺序。之后，讨论了临时表、不同索引的原理与适用场景。最后，总结了常见的SQL性能优化实践经验，从索引使用、查询写法到表结构设计等方面给出了具体建议。

### 经典金句/数据

> 一致性（Consistency）:一致性指的是一个事务在执行前后其状态一致。比如A和B加起来的钱一共是1000元，那么不管A和B之间如何转账，转多少次，事务结束后两个用户的钱加起来还得是1000，这就是事务的一致性。

> 读未提交:读未提交指的是一个事务在提交之前，它所做的修改就能够被其他事务所看到。读已提交:读已提交指的是一个事务在提交之后，它所做的变更才能够让其他事务看到。可重复读:可重复读指的是一个事务在执行的过程中，看到的数据是和启动时看到的数据是一致的。未提交的变更对其他事务不可见。串行化:顾名思义是对于同一行记录，写会加写锁，读会加读锁。当出现读写锁冲突的时候，后访问的事务必须等前一个事务执行完成，才能继续执行。

> 使用 EXPLAIN 命令优化你的 SELECT 查询，对于复杂、效率低的 sql 语句，我们通常是使用 explain sql 来分析这条 sql 语句，这样方便我们分析，进行优化。

## 操作系统篇

### 核心论点

本章（模块）涉及操作系统（OS）的基础概念、核心功能及关键算法，旨在解答计算机科学基础的面试问题。作者的核心观点是：操作系统作为硬件与软件之间的桥梁，其核心使命是管理资源（CPU、内存、I/O）、抽象接口、并提供进程/线程调度、内存管理、文件系统等基础服务，是理解计算机系统工作原理的必备知识。

### 关键概念/事件

- 

  **进程与线程**：进程是资源分配的基本单位，拥有独立的地址空间；线程是CPU调度的基本单位，共享进程的资源。线程更轻量，切换开销小，利于提高并发性。

- 

  **进程状态与调度**：进程主要状态包括运行、就绪、阻塞。常见调度算法有先来先服务（FCFS）、最短作业优先（SJF）、时间片轮转（RR）、多级反馈队列等，旨在平衡响应时间和吞吐量。

- 

  **死锁**：指两个或以上的进程在执行过程中，因争夺资源而造成的一种互相等待的现象。产生死锁必须同时满足四个条件：互斥、请求与保持、不剥夺、循环等待。

- 

  **虚拟内存**：一种内存管理技术，它使得应用程序认为它拥有连续可用的内存，而实际上，它通常是被分隔成多个物理内存碎片，还有部分暂时存储在外部磁盘存储器上，在需要时进行数据交换。

- 

  **页面置换算法**：当发生缺页中断且物理内存已满时，需选择一页换出。常见算法有：最佳置换（OPT，理论）、先进先出（FIFO）、最近最久未使用（LRU）、时钟（Clock）算法等。

### 逻辑推演/叙事脉络

本章开篇定义了操作系统及其主要目的。接着，介绍了几种经典的操作系统结构（单体、分层、微内核、客户-服务器）。然后，重点展开讨论操作系统的两大核心管理功能：进程管理和内存管理。在进程管理部分，详细区分了进程与线程，阐述了进程状态模型、进程间通信（IPC）方式，以及导致死锁的条件和避免策略。在内存管理部分，解释了虚拟内存的概念及其实现基础——分页机制，并重点介绍了多种页面置换算法及其优劣比较。此外，还简要介绍了磁盘管理（RAID）、I/O控制（DMA）等概念。全章以“资源管理”和“提供抽象服务”为主线，串联起各个知识点。

### 经典金句/数据

> 进程就是正在执行程序的实例，比如说Web程序就是一个进程，shell也是一个进程，文章编辑器typora也是一个进程。... 线程其实就是进程中的单条流向，因为线程具有进程中的某些属性，所以线程又被称为轻量级的进程。

> 死锁的出现需要同时满足下面四个条件：互斥（Mutual Exclusion）... 保持并等待（Hold and Wait）... 无抢占（No Preemption）... 循环等待（Circular Wait）...

> 虚拟内存是一种内存分配方案，是一项可以用来辅助内存分配的机制。我们知道，应用程序是按页装载进内存中的。但并不是所有的页都会装载到内存中，计算机中的硬件和软件会将数据从 RAM 临时传输到磁盘中来弥补内存的不足。
