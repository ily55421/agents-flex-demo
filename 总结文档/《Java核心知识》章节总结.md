## 第1章：Java 语言概述与开发环境

### 核心论点
本章旨在解决“Java 是什么”以及“如何运行 Java 程序”的问题。核心观点是：Java 是一门面向对象、跨平台的编程语言，其“Write once, run anywhere”的特性依赖于 JVM（Java 虚拟机）作为中间层屏蔽底层操作系统差异。

### 关键概念/事件
-   **JDK/JRE/JVM 关系**：JDK 包含 JRE 和开发工具；JRE 包含 JVM 和核心类库；JVM 是字节码解释执行与跨平台的核心载体。
-   **跨平台原理**：Java 源码编译为字节码（.class），由不同平台的 JVM 解释或 JIT 编译执行，而非直接编译为机器码。
-   **面向对象 vs 面向过程**：Java 摒弃了 C++ 中指针、多继承等复杂特性，强调封装、继承、多态，以对象为核心组织代码。
-   **自动内存管理**：通过垃圾回收机制（GC）自动管理内存，避免手动分配释放带来的内存泄漏与悬空指针问题。

### 逻辑推演/叙事脉络
作者首先介绍 Java 的诞生背景与三大平台版本（SE/EE/ME），确立其企业级开发地位。随后深入解析 JDK 与 JRE 的组成，阐明开发环境与运行环境的区别。接着通过对比 C/C++，引出 Java 的安全性与简易性设计哲学。最后以“Hello World”为例，串联起编写、编译、运行的全流程，并解释 JVM 在其中的桥梁作用。

### 经典金句/数据
> “Write once, run anywhere.”
> “Java 是纯面向对象语言，不支持全局变量与指针运算。”

## 第2章：Java 基础语法与数据类型

### 核心论点
本章解决“Java 程序的基本构成单元”问题。核心观点是：Java 是强类型语言，严格区分基本数据类型与引用类型，所有逻辑控制均建立在明确的类型系统与结构化语句之上。

### 关键概念/事件
-   **八大基本类型**：byte/short/int/long/float/double/char/boolean，各自占用固定字节数，存储于栈中，非对象。
-   **引用类型与 null**：类、接口、数组均为引用类型，变量存储的是堆中对象的地址；null 是引用类型的默认值，表示“不指向任何对象”。
-   **流程控制**：if-else、switch（支持 String/Enum）、for/while/do-while、break/continue/return，构成程序的执行骨架。
-   **运算符优先级**：算术、关系、逻辑、位运算、赋值运算符的优先级与结合性决定表达式求值顺序。

### 逻辑推演/叙事脉络
从变量声明与初始化入手，详解基本类型与包装类的区别。随后介绍字符串（String）的不可变性与常量池机制。接着系统梳理条件判断与循环结构，特别强调 switch 的穿透性与 for-each 的语法糖本质。最后通过 break/continue 说明循环控制的精细粒度，并指出 goto 为保留字但不可用。

### 经典金句/数据
> “int a = 10; // 基本类型，栈上分配”
> “String s = new String("abc"); // 引用类型，堆上分配对象”

## 第3章：面向对象编程（OOP）核心

### 核心论点
本章回答“如何用对象思维构建软件系统”。核心观点是：OOP 通过封装隐藏实现细节、通过继承复用代码、通过多态实现灵活扩展，三者协同支撑复杂系统的可维护性与可扩展性。

### 关键概念/事件
-   **类与对象**：类是模板（抽象），对象是实例（具体）；构造器负责初始化，this 指代当前实例。
-   **封装**：通过 private/public/protected/default 控制访问权限，暴露行为而非数据，保障内部状态安全。
-   **继承与 super**：子类 extends 父类复用属性与方法；super 调用父类构造器或成员；Java 单继承限制避免菱形问题。
-   **多态与重写**：父类引用指向子类对象，运行时动态绑定方法；@Override 确保正确重写；重载（Overload）是编译期多态。

### 逻辑推演/叙事脉络
从现实世界建模引入类与对象概念，演示属性与方法定义。接着讲解构造器链与 this/super 的使用场景。深入剖析四大访问修饰符的作用域，强调最小权限原则。通过动物/水果等案例演示继承层次与方法重写，引出多态的动态绑定机制。最后对比组合与继承，建议优先使用组合以降低耦合。

### 经典金句/数据
> “封装是保护屏障，继承是复用手段，多态是扩展灵魂。”
> “父类引用指向子类对象时，只能调用父类声明的方法，实际执行子类重写版本。”

## 第4章：抽象类、接口与高级特性

### 核心论点
本章解决“如何设计规范与契约”及“如何处理特殊语言特性”。核心观点是：抽象类提供部分实现的模板，接口定义纯粹的行为契约；static/final/enum/annotation 等特性补充了 OOP 的表达力，使语言更严谨、更具元数据能力。

### 关键概念/事件
-   **抽象类 vs 接口**：abstract class 可有构造器与非抽象方法，体现“is-a”；interface 仅定义行为规范（Java8+ 可有 default/static），体现“can-do”。
-   **static 关键字**：修饰成员属于类而非实例；静态代码块用于类加载初始化；不能访问非静态成员。
-   **final 关键字**：修饰类不可继承，修饰方法不可重写，修饰变量不可重新赋值（引用不可变≠对象不可变）。
-   **枚举（Enum）**：类型安全的常量集合，本质是 final 类，支持构造器、方法与字段，可实现接口。
-   **注解（Annotation）**：元数据标记，@Retention 决定生命周期（SOURCE/CLASS/RUNTIME），@Target 限定使用位置。

### 逻辑推演/叙事脉络
先对比抽象类与接口的适用场景，强调接口在解耦中的核心价值。接着逐一解析 static/final 的语义约束与内存模型影响。引入枚举替代魔法数字，展示其单例与策略模式应用。最后讲解注解的定义与反射读取，为框架开发奠定基础。穿插内部类（成员/静态/局部/匿名）的作用域与外部类访问规则。

### 经典金句/数据
> “接口是行为的契约，抽象类是代码的模板。”
> “枚举本质上是继承了 java.lang.Enum 的 final 类。”

## 第5章：异常处理机制

### 核心论点
本章回答“如何优雅地处理程序错误”。核心观点是：异常机制将正常业务逻辑与错误处理分离，通过 Checked/Unchecked 分类强制开发者关注可恢复错误，同时保留运行时异常的灵活性。

### 关键概念/事件
-   **Throwable 体系**：Error（JVM 级严重错误，如 OOM）不可捕获；Exception 分为 Checked（编译期检查）与 RuntimeException（运行时异常）。
-   **try-catch-finally**：try 包裹风险代码，catch 按子类到父类顺序捕获，finally 保证资源清理（即使 return 也会执行）。
-   **throws vs throw**：throws 声明方法可能抛出的异常（契约），throw 主动抛出异常实例（动作）。
-   **自定义异常**：继承 Exception 或 RuntimeException，携带业务错误码与信息，增强语义表达。

### 逻辑推演/叙事脉络
从程序崩溃的现实问题引入异常必要性。绘制 Throwable 继承树，区分 Error 与 Exception 的处理策略。详解 try-catch-finally 执行顺序，特别强调 finally 中 return 的风险。对比 Checked 与 Unchecked 的设计哲学，讨论何时该捕获、何时该抛出。最后给出异常处理最佳实践：避免吞掉异常、不要用异常控制流程、日志记录要完整。

### 经典金句/数据
> “Checked Exception 强迫你面对问题，RuntimeException 信任你的代码质量。”
> “finally 块总会在 try/catch 之后、方法返回之前执行。”

## 第6章：集合框架与泛型

### 核心论点
本章解决“如何高效存储与操作数据”及“如何保证类型安全”。核心观点是：Collection 框架提供统一的数据结构抽象（List/Set/Queue/Map），泛型在编译期擦除类型信息以实现代码复用与类型检查，二者共同构成 Java 数据处理基石。

### 关键概念/事件
-   **List/ArrayList/LinkedList**：有序可重复；ArrayList 基于动态数组，随机访问快；LinkedList 基于双向链表，插入删除快。
-   **Set/HashSet/TreeSet**：无序不可重复；HashSet 依赖 hashCode/equals；TreeSet 基于红黑树，支持排序。
-   **Map/HashMap/TreeMap**：键值对映射；HashMap 允许 null key/value，非线程安全；ConcurrentHashMap 为并发优选。
-   **泛型（Generics）**：类型参数化，编译期检查；类型擦除导致运行时无法获取泛型信息；通配符 ? extends / ? super 界定上下界。
-   **fail-fast 机制**：迭代过程中检测到结构性修改即抛 ConcurrentModificationException，防止不确定行为。

### 逻辑推演/叙事脉络
从数组局限性引出集合框架必要性。分层讲解 Collection 接口体系，对比各实现类的性能特征与适用场景。深入 HashMap 底层（哈希冲突、扩容、红黑树转换）。转入泛型，解释为何需要泛型、类型擦除的后果及 PECS 原则。最后介绍 Collections 工具类与 Arrays 工具类的常用操作。

### 经典金句/数据
> “ArrayList 适合读多写少，LinkedList 适合写多读少。”
> “泛型是编译期的语法糖，运行时被擦除为 Object。”

## 第7章：IO 流与文件操作

### 核心论点
本章回答“如何进行数据持久化与传输”。核心观点是：IO 流以“装饰器模式”构建灵活的输入输出管道，区分字节流/字符流、节点流/处理流，File 类仅提供元数据操作而不涉及内容读写。

### 关键概念/事件
-   **字节流 vs 字符流**：InputStream/OutputStream 处理二进制数据；Reader/Writer 处理文本数据，内置编码转换。
-   **节点流 vs 处理流**：FileInputStream 等直接连接数据源；BufferedInputStream 等包装节点流以提升性能或增加功能。
-   **序列化**：ObjectInputStream/ObjectOutputStream 实现对象持久化；serialVersionUID 保证版本兼容。
-   **File 类**：表示文件或目录路径，提供创建、删除、查询元数据等方法，但不直接读写内容。

### 逻辑推演/叙事脉络
从数据流动的物理模型引入流的概念。分类讲解四大抽象基类及其典型子类，强调缓冲流的重要性。演示文件复制、文本读写、对象序列化的标准代码范式。介绍 File 类的路径处理与文件系统交互。最后提及 NIO（New IO）作为传统 IO 的补充，适用于高并发场景。

### 经典金句/数据
> “一切皆流，装饰器模式让 IO 组合无限可能。”
> “关闭流应放在 finally 块或使用 try-with-resources。”

## 第8章：反射机制

### 核心论点
本章解决“如何在运行时动态操作类与对象”。核心观点是：反射打破了 Java 的静态类型约束，允许程序在运行时检视类结构、创建实例、调用私有成员，是框架（Spring/MyBatis）实现的基石，但牺牲了性能与安全性。

### 关键概念/事件
-   **Class 对象**：每个类加载后生成唯一 Class 实例，是反射入口；可通过 .class、getClass()、Class.forName() 获取。
-   **Field/Method/Constructor**：分别代表字段、方法、构造器；getDeclared* 获取本类所有成员（含私有），get* 仅获取 public 及继承成员。
-   **动态代理**：Proxy + InvocationHandler 实现接口代理；CGLIB 通过字节码生成子类代理；AOP 的核心实现方式。
-   **性能与安全**：反射调用比直接调用慢数十倍；setAccessible(true) 绕过安全检查，需谨慎使用。

### 逻辑推演/叙事脉络
从“框架如何知道你的类结构”引出反射需求。演示获取 Class 对象的三种方式。逐步展示如何通过反射创建对象、读写私有字段、调用私有方法。讲解注解与反射的结合，实现自定义配置驱动。最后讨论反射的性能代价与安全边界，强调仅在框架层使用，业务代码应避免。

### 经典金句/数据
> “反射让 Java 拥有了动态语言的灵活性，但也打开了潘多拉魔盒。”
> “getDeclaredFields() 获取本类所有字段，getFields() 仅获取 public 字段。”

## 附录：常见陷阱与最佳实践

### 核心论点
本章汇总 Java 开发中的高频误区。核心观点是：理解语言底层机制（如 null 语义、字符串池、集合契约）是避免隐蔽 Bug 的前提，防御性编程与规范意识比技巧更重要。

### 关键概念/事件
-   **null 的安全处理**：null 不是对象，instanceof 返回 false；字符串拼接 null 转为 "null"；比较时用 Objects.equals()。
-   **字符串陷阱**：== 比较引用，equals 比较内容；intern() 入池需谨慎；StringBuilder 优于 + 拼接。
-   **集合契约**：HashMap 的 key 必须重写 hashCode/equals；遍历时禁止直接 remove，应用 Iterator。
-   **并发隐患**：SimpleDateFormat 非线程安全；HashMap 多线程死循环（JDK7）；优先使用 concurrent 包工具类。

### 逻辑推演/叙事脉络
以真实 Bug 案例切入，还原问题现场。分析根因（如 null 的类型系统定位、String 的不可变性设计）。给出修复方案与预防措施。总结为可执行的检查清单，帮助开发者建立防御性编码习惯。

### 经典金句/数据
> “null 是十亿美元的错误，请用 Optional 或空对象模式替代。”
> “永远不要在 foreach 循环中对集合进行增删操作。”
