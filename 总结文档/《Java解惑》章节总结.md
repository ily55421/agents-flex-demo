## 全书核心主题

本书通过95个 Java 编程谜题，揭示语言中容易被忽视的细节和陷阱。每个谜题先给出看似简单的代码，然后分析其实际行为与预期的差异，解释背后的语言规范、类型系统、异常处理、线程、序列化等机制。核心目的是帮助开发者深入理解 Java，避免常见错误。

## 第1章：表达式谜题

### 谜题1：奇数性

#### 核心论点

判断奇偶的方法 `i % 2 == 1` 对负数奇数值失败，因为 `%` 结果符号与被除数相同。

#### 关键概念

- 取余操作符 `%` 的定义：`(a / b) * b + (a % b) == a`
- 负数取余结果为负数
- 修正：`i % 2 != 0` 或 `(i & 1) != 0`

#### 逻辑推演

问题 → 常见写法在负奇数时返回 false → 分析取余符号规则 → 给出正确写法。

### 谜题2：找零时刻

#### 核心论点

浮点数 `2.00 - 1.10` 打印 `0.8999999999999999`，因为二进制浮点数无法精确表示十进制小数。

#### 关键概念

- 二进制浮点数精度问题
- 货币计算应使用 `int`、`long` 或 `BigDecimal`
- `BigDecimal` 必须用 `String` 构造器

#### 流程图

```mermaid
graph LR
    A[double 2.00 - 1.10] --> B[实际计算值近似]
    B --> C[打印 0.899...]
    D[使用 int 表示分] --> E[正确结果 90 cents]
    F[使用 BigDecimal(String)] --> G[正确结果 0.90]
```

### 谜题3：长整除

#### 核心论点

`long MICROS_PER_DAY = 24*60*60*1000*1000` 溢出，因为所有因子是 `int`，结果在 `int` 溢出后才提升为 `long`。

#### 关键概念

- 整数运算中，结果类型由操作数类型决定
- 溢出在提升前发生
- 修正：使用 `24L` 等长整型字面常量

#### 逻辑推演

常量计算 → 全部 int 运算 → 溢出 → 错误值 → 提升为 long → 除法得到 5。

### 谜题4：初级问题

#### 核心论点

`System.out.println(12345+54321)` 实际输出 `17777`，因为 `54321` 中的 `1` 是小写字母 `l`，即 `5432L`，类型为 `long`。

#### 关键概念

- long 字面常量应使用大写 `L`，避免与小写 `l` 混淆
- 混合类型运算会导致类型提升

### 谜题5：十六进制的趣事

#### 核心论点

`0x100000000L + 0xcafebabe` 输出 `cafebabe`，因为 `0xcafebabe` 是 `int` 负数，被符号扩展为 `0xffffffffcafebabeL`，相加后高位抵消。

#### 关键概念

- 十六进制字面常量可以是负数（最高位为1）
- 混合类型运算中的符号扩展
- 修正：使用 `0xcafebabeL`

### 谜题6：多重转型

#### 核心论点

`(int)(char)(byte)-1` 输出 `65535`，原因是从 `byte` 到 `char` 时发生了符号扩展，再从 `char` 到 `int` 零扩展。

#### 关键概念

- 拓宽转换：有符号类型进行符号扩展，`char` 进行零扩展
- 转型顺序导致结果变化

### 谜题7：互换内容

#### 核心论点

`x ^= y ^= x ^= y` 在 Java 中不能正确交换，因为左操作数先取值，导致最终 `x=0`。

#### 关键概念

- Java 操作数求值顺序从左到右
- 避免在单个表达式中多次赋值同一变量

### 谜题8：Dos Equis

#### 核心论点

`true ? x : 0` 输出 `'X'`，`false ? i : x` 输出 `88`，因为条件表达式类型规则：当第二、三操作数一个是 `char`、另一个是 `int` 常量且可表示时，类型为 `char`；否则进行二进制数字提升。

#### 关键概念

- 条件表达式类型确定规则
- 重载方法选择基于表达式类型

### 谜题9：半斤

#### 核心论点

`short x = 0; int i = 123456; x += i` 合法，但 `x = x + i` 非法。复合赋值包含隐式转型。

#### 关键概念

- 复合赋值自动执行窄化转换，可能丢失精度
- 应避免对 `byte`、`short`、`char` 使用复合赋值

### 谜题10：八两

#### 核心论点

`Object x = "Buy"; String i = "Effective Java!"; x = x + i` 合法，`x += i` 非法。因为 `+=` 要求左操作数为 `String` 才能进行字符串连接。

#### 关键概念

- 简单赋值允许任意赋值兼容类型
- 复合赋值对左侧类型有更严格限制

## 第2章：字符谜题

### 谜题11：最后的笑声

#### 核心论点

`System.out.print("H"+"a")` 输出 `Ha`，`System.out.print('H'+'a')` 输出 `169`，因为 `+` 在 char 上做加法而非字符串连接。

#### 关键概念

- `+` 操作符：至少一个操作数为 `String` 时做连接，否则做加法
- char 是 16 位无符号整数

### 谜题12：ABC

#### 核心论点

`System.out.println(letters + " easy as " + numbers)` 输出类似 `ABC easy as [C@16f0472`，因为数组的 `toString()` 返回类型名+哈希码。

#### 关键概念

- 数组直接字符串连接会调用 `Object.toString()`
- 应使用 `String.valueOf(numbers)` 转换

### 谜题13：畜牧场

#### 核心论点

`"Animals are equal: " + pig == dog` 输出 `false`，因为 `+` 优先级高于 `==`，实际比较的是布尔值。

#### 关键概念

- 运算符优先级：`+` 高于 `==`
- 字符串常量内存限定（intern）不应依赖
- 对象比较应使用 `equals` 而非 `==`

### 谜题14：转义字符的溃败

#### 核心论点

`System.out.println("a\u0022.length() + \u0022b".length())` 编译出错，因为 `\u0022` 是双引号，在注释中被提前转义，改变了字符串字面量结构。

#### 关键概念

- Unicode 转义在词法分析之前处理
- 字符串中应使用转义序列 `\"` 而非 Unicode 转义

### 谜题15：令人晕头转向的Hello

#### 核心论点

注释中的 `\units` 被解析为非法 Unicode 转义 `\u`，导致编译错误。

#### 关键概念

- Unicode 转义必须以 `\u` 开头后跟四个十六进制数字
- 即使出现在注释中也会被处理

## 第3章：循环谜题

### 谜题24：尽情享受每一个字节

#### 核心论点

循环 `for (byte b = Byte.MIN_VALUE; b < Byte.MAX_VALUE; b++)` 中 `if (b == 0x90)` 从未成立，因为 `0x90` 是 `int` 144，超出 `byte` 范围，比较时 `b` 被符号扩展为负数。

#### 关键概念

- 混合类型比较触发拓宽转换
- 常量 `0x90` 为正数，但 `(byte)0x90` 为负数
- 避免混合类型比较，使用显式转型或掩码

## 第4章：异常谜题

### 谜题36：优柔寡断

#### 核心论点

`try { return true; } finally { return false; }` 返回 `false`，因为 `finally` 中的 `return` 覆盖了 `try` 中的 `return`。

#### 关键概念

- `finally` 语句块意外结束会丢弃 `try` 中的返回
- 不要在 `finally` 中使用 `return`、`break`、`continue` 或 `throw`

## 第5章：类谜题

### 谜题46：令人混淆的构造器案例

#### 核心论点

`new Confusing(null)` 调用 `Confusing(double[])` 而非 `Confusing(Object)`，因为重载解析选择最精确的构造器。

#### 关键概念

- 重载解析：先找可应用方法，再选最精确
- `null` 可匹配多个类型，选择更具体的子类
- 避免重载或确保参数类型不兼容
